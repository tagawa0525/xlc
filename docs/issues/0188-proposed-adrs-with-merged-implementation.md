# 実装をマージした proposed の ADR

## 問題

docs/adr/README.md の「運用」は、実装をマージするブランチで proposed の ADR を実装に合わせて直し、同じ変更で
`status: accepted` にし、`date` をその日にすると決めている。main には、`Refs:` にその ADR を挙げた feat か fix のコミットがあるのに
proposed のままの ADR が 6 件ある（2026-10-29、main f99afa6b8 で
`git log --format='%h %as %s' --grep="Refs:.*ADR-NNNN" main | grep -E ' (feat|fix)\('` を数えた。日付は author date）。決定の全部が実装されたかは確かめていない:

| ADR      | 最初の実装のコミット（`Refs:` に挙げたもの）                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADR-0144 | 9daf2faa0（2026-10-14）                                                                                                                          |
| ADR-0151 | 1052c1158（2026-10-13。ADR-0152 の tally の送付の修正）。AWS のツールを足したのは同じ日の 419ebc315。実行の形は ADR-0155（accepted）が決めている |
| ADR-0152 | 3343ca05c（2026-10-12）                                                                                                                          |

| ADR-0206 | 94fd70855（2026-10-27）                                                                                                                          |

ADR-0202 は、方法を物質と χ に広げた分を 2026-10-29 に「## 補足」に足した（proposed なので本文を直せる）。accepted に
すると、以後の広げ方は新しい ADR（`amends`）になる。2026-10-29 の委任の依頼文は ADR-0202 を accepted と書いていた
（親の誤り。担当が確かめた）。

関係する ADR: なし

## 完了の条件

表の ADR ごとに、決定の全部が実装されたかを確かめ、実装されたものを accepted にする（「確認」と「帰結」を実装に
合わせる）か、残りを「帰結」に書いて issue に結ぶ。実装をマージするブランチで status を見落とさない仕組み（/git-merge
の段か検査）が要るかを決める。
