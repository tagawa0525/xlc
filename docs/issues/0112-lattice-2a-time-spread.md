# VERA 2A の格子計算の時間が、排他のジョブの中でも 1 回ごとに大きくばらつく

## 問題

ADR-0157 の測定で、同じ実行ファイル（b873a967 の lattice、整列の設定なし）に同じ入力
（examples/build-alignment/assembly-2A.toml）を与えて、r995 の Slurm の排他のジョブで実行した 2A の集合体の時間が、
1 回ごとに大きくばらついた。

| ジョブ（日付）    | 整列の設定なし（秒）                           | `-align-loops=64`（秒）                        |
| ----------------- | ---------------------------------------------- | ---------------------------------------------- |
| 287（2026-10-13） | 123.60、124.20                                 | 122.77、124.09                                 |
| 292（2026-10-13） | 127.58、129.72、129.83、142.48                 | 139.84、131.26、123.67、143.00                 |
| 305（2026-10-14） | 121.90、122.28                                 | 122.16、129.59                                 |
| 307（2026-10-14） | 138.78、130.80、146.33、168.31、161.77、151.81 | 129.09、134.79、129.26、151.15、166.83、146.01 |
| 284（2026-10-13） | 121.5、129.6                                   | 145.6、158.9                                   |

（287、292、284 は手元のスクリプトとビルド（同じソースと設定、同じ入力）、305 と 307 はコミット c029a27c の
スクリプト。284 の 2 回の `-align-loops=64` はほかのどの回よりも遅い側だが、ほかのジョブでは再現しなかった）

出力（少数群定数とピン出力の msgpack、標準出力）は、どの回もバイト単位で一致した。同じジョブの中でも、307 では 129 秒から 168 秒
（30%）まで変わる。M0 の xs も、302（2026-10-14）では同じ実行ファイルの 2 回が 54.2 秒と 59.2 秒で、277（2026-10-13）の
2 回の差（0.4 秒以下）より大きかった。

原因の候補（確かめていない）: 排他のジョブの外で、手元で走る計算（ジョブ 285 では、別のエージェントが手元で 1B の
格子計算を実行していたことが分かっている）、CPU の温度やクロック、メモリの配置。

ADR-0144 の時間の判定は、分岐点と変更後を同じ排他のジョブで比べる。このばらつきがあると、lattice の 2A で 10〜20% の
差は見分けられない。

関係する ADR: ADR-0157

## 完了の条件

- ばらつきの原因を確かめる（ジョブの時刻の CPU の負荷、クロック、温度を記録して比べるなど）
- 原因を除くか、ADR-0144 の判定で 2A の時間をどう比べるか（回数、交互に実行する、ばらつきの幅との比べ方）を決める

## 経緯
