# MOC のスイープで組の作業の配列を 0 にする時間

## 問題

- 非等方散乱のスイープは、方位角が変わるたびに `Sweeper::directional` が組の通る領域 × 2 × 3 × 群の線源と減衰の和の 2 つの配列を
  `resize(size, 0.0)` で 0 にし、スイープの始めに `Tally::clear` が `[組の中の領域][モーメント][群]` の減衰の和を 0 にしていた。2A では
  組あたり数十 MB で L2 に収まらず、どちらもメモリとの別の往復になる。`memset` は、2A の一般化随伴の源ごとのスイープの区間でも
  前向きの固有値計算の MOC の区間でもサイクルの 26% で、呼び出し元は `directional` と `Tally::clear` がほぼ半分ずつ（下の「測定」の
  perf。`perf script` の戻り先の行）
- 直し（コミット b4bffdbd0、レビューで直した形は 0d839a956）: 線源は真空でない領域の欄をすべて書き直し、真空の領域の欄はスイープが
  読まないので 0 にしない。減衰の和は `fold` が読んだ欄をキャッシュにあるうちに 0 に戻してプールに返す。線源と減衰の和のプールを
  分け（前向きと随伴の積は線源だけを使う）、減衰の和のプールに返すのは `fold` だけなので、その配列はいつも 0。プールの配列は縮めず、
  伸ばした分だけを 0 で埋める。モーメントごとの減衰の和は、そのスイープの最初の `fold` が領域ごとに足す直前に 0 にする。どの和も
  足す順は変わらない
- 等方散乱の経路（自己遮蔽の Dancoff と塊の固定源のスイープ）には `directional` が無く、`Tally::clear` の 0 埋めだけが残る。2A の
  1 状態の Dancoff（2.3 秒）と塊（2.4 秒）の区間で `memset` はサイクルの 4.3% と 4.4%（Slurm 802）で、状態あたり 2 回ずつでも
  約 0.4 秒（状態の約 110 秒の 0.4%）なので直していない。等方散乱では減衰の和をスイープの中で直に足すので、非等方散乱の `fold` の
  ように最初に足す場所が無い。読む場所の `sum_tallies` で 0 に戻す形は、代表の領域ごとに並列に集める中で、対称操作で動かない領域の
  欄を像の数だけ読む（読み終わりが欄ごとに決まらない）ので、別の走査が要る

## 完了の条件

同じことを確かめて直す。
