# MOC のスイープで組の作業の配列を 0 にする時間

## 問題

- 2A の一般化随伴の源ごとのスイープで、`memset` がスイープの内側のクロージャに近いサイクルを使う（値は #0279 の「段 3 の後の加速」の
  B のカウンタの項の表）。`directional` は非等方散乱（モーメントが 2 つ以上）のときだけ呼ぶので、その分は非等方散乱のスイープ
  （2A の固有値計算と一般化随伴）にだけかかる。ESSM と等方散乱のスイープの割合は測っていない
- 呼び出し元（`perf script` の戻り先の行。0.3 秒の区間の標本 91 個）: 44 個が `Sweeper::sweep` の中の `directional` の呼び出し
  （方位角が変わるたびに、組の通る領域 × 2 × 3 × 群の線源と減衰の和の 2 つの配列を `resize(size, 0.0)` で 0 にする）、47 個がスイープの
  クロージャの中のスライスの `fill`（`Tally::clear` の `[組の中の領域][モーメント][群]` の減衰の和と、真空境界から入るトラックの
  `psi.fill(0.0)` が候補で、どれかは分けていない）
- 大きさ: 2A の組の通る領域の和は 125,253（DEBUG のログの `regions held by the tallies of the track groups`）で、`directional` の
  1 領域の線源と減衰の和は 2 × 3 × 69 × 8 B = 3.3 KB ずつ。`directional` の配列は組ごとに使い回し（`Sweeper::pool`）、1 回に 0 にするのは
  その組の領域の分で、同時に 32 の組を掃く。`Tally::clear` は毎スイープすべての組の分を 0 にする。`memset` のメモリからの埋めは
  1 スイープ 5.2 百万（64 B で 333 MB）。組の数、組ごとの領域の数と方位角の変わる回数は数えていないので、0 にした値がキャッシュに
  残るかは確かめていない
- 案（どれも和の順を変えないので、結果はビットで同じ見込み）: 線源の配列は真空でない領域ですぐ上書きするので、真空の領域の分だけ
  0 にする。減衰の和は、`fold` が読んで足し込むときに 0 を書き戻す（読み終えた値をキャッシュにあるうちに 0 にし、別の走査を
  無くす）。見込みは、源ごとのスイープの `memset` の分（区間のサイクルの 2 割ほど）の大半で、#0279 の本番の見込みの一般化随伴の
  時間と、固有値計算の輸送にかかる

関係する ADR: なし

## 完了の条件

2A の固有値計算と一般化随伴の 1 スイープの時間を、`--timed` のジョブで直す前後に測り、k、一般化随伴の解、テーブルの md5 がビットで
同じことを確かめて直す。
