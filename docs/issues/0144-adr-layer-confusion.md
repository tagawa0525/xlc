# ADR が今の姿として読まれ、決定の範囲を越えて効く

## 問題

ADR は 176 件（0001〜0179、2026-10-21 の main 21ee9bdf）、合わせて 13,164 行ある。今の設計を知るには ADR の連鎖
（`requires` と `supersedes`）を読んで、どの部分がまだ効いているかを自分で組み立てることになる。そのため、決定の証拠として
書いた ADR が今の姿として読まれ、確かめた範囲を越えて効く。2026-10-21 に見つかった例:

- ADR-0173 の案 N1 は、温度が 1 つのピンセルで決めたのに、決定の文が一般の形（「すべての燃焼の領域の温度」）で書かれている。
  ADR-0179 が範囲を狭めた（温度が複数のときは止める）が、ADR-0173 は accepted のままで、それだけを読むと狭めに気づかない。
  範囲を正しく表しているのは、エラーとテスト `depleted_materials_share_one_temperature` だけである
- ADR-0048 は superseded（superseded-by: ADR-0177）だが、ADR-0177 は LSSF = 0 の無限希釈を「ADR-0048 の決定のうち残る部分」と
  書いている。生きている決定が superseded の ADR の中に残る
- crates/lattice/src/depletion.rs の `//!` は ADR-0173 だけを指し、ADR-0179（燃料でない吸収体も燃焼させる、温度は 1 つ）を
  反映していない
- 比較や測定を伴わない初めの方針の ADR がある（例: ADR-0022）。accepted の 134 件のうち 60 件は、
  7〜40 桁の16進（測った値の出どころのコミット）を 1 つも含まない（大まかな指標）

一方で、書き換えない記録が働いた例もある。nixfiles の ADR-0013 は、捨てた案と理由が残っていたので同じ提案を止められた。
ADR-0177 の PURR との比較の表は、今の結果だけを書く verification.md（ADR-0117）には置けない。

関係する ADR: なし（上の ADR は例で、この issue をフロントマターに挙げていない）

## 完了の条件

決定の証拠と今の姿をどこに、どの形で書くかの方針をユーザーが決め、ADR に書く。決まるまでは今の運用を変えない。

2026-10-21 の調査で比べた候補（どれも合意していない）:

1. ADR を続け、書く条件を絞る
2. 今の設計だけを書く文書（docs/design/<部位>.md）に移す
3. モジュール文書（`//!`）に書き、ADR をやめる
4. ADR と設計文書の両方を持つ
5. ADR は証拠（比べた案、捨てた理由、測った値、調べた範囲）に限り、今の姿は `//!`、CLAUDE.md、plans/architecture.md に、
   範囲はコードの止めとテストに任せる

方針と別に、上の 3 件のずれ（ADR-0048 の残る部分、ADR-0173 の範囲、depletion.rs の `//!`）を直す。この issue は、方針の ADR と 3 件の修正がそろったら閉じる。
