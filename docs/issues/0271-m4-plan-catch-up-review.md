# M4 の計画の追いつきのレビューで直さなかった指摘

## 問題

docs/plans/m4-depletion.md の「進め方」と「CPU と記憶の見積もり（xlc）」を 2026-11-07 の main に追いつかせたブランチ（docs/m4-plan-catch-up）の
ローカルのレビュー（1〜3 周目）で、直さずに残した指摘:

- 「次の順序」の段落は ADR-0238 の「帰結」のライブラリの作り直しだけを挙げ、同じ帰結の p2 の格子計算の燃焼の 7 ステージ（2A-density、2A-rods、
  2F、2M、2N、2O、2P）が changed で、読む作業が来たときに再実行すること（時間は同じ帰結）を挙げていない。6 の本番のテーブルがそれらの
  履歴を読むなら、その前に再実行が要る
- 同じ段落は、ADR-0238 の「帰結」が挙げる例（m0、m1、m3-nuclides、mox、reflector、core、vera、vera/endfb70、depletion）を「vera、depletion など」と
  書き、CPU 時間の和は 3 つだけ。言い換えずに帰結の項を指す形にするか
- 「CPU と記憶の見積もり（xlc）」の「炉心の燃焼」の 30 ステップの約 23 分は、examples/depletion/verification.md の「固有値計算の複数のスレッド
  （小さな炉心と全炉心）」の見積もり（固有値計算の回数 × 1 回の平均）で、固有値計算の外の時間と熱水力の分を含まない。計画にその範囲を添えるか
- 「進め方」8 は Problem 6 の入力を済みとするが、ADR-0238 の「帰結」で VERA のライブラリは今の形式で読めず、examples/vera/p6 を再実行するには
  ライブラリの作り直しが要る。8 の項からその帰結を指すか
- 「次の順序」の段落は、9 を 9 の項の「前に要るもの」（7 の残りと 8）がそろってから始めるとし、同じ段落で 8 の残り（#0228 の「残り」の
  ギャップのコンダクタンス、実効温度、流量の再配分）は順を決めていないと書く。7 の残りも解く時間の issue を含むので、9 を始める条件が
  決まらない。9 の項の「前に要るもの」のどこまでが 9 を塞ぐかを決める（2 周目）
- 「次の順序」の「次の 3 つは済んだ」の 3 つは、最初だけ「…解けるまで」で終わり、ほかは「…こと」で並びがそろわない。続く「BOC の B-10 …引ける」の
  文が 4 つ目の済んだ項目に読める。最初の項の「8 のほかの残りは作業中」は、8 の項と同じ段落の後の文と重なる（3 周目）
- 「CPU と記憶の見積もり（xlc）」の約 23 分は、熱水力ありの 320.9 s の直後に置かれ、熱水力の分を含まないことが読み取れない（上の見積もりの範囲の項と同じ。3 周目）
- #0228 の「残り」も Problem 6 の記録の節の題を「Problem 6 の 3D の HFP の集合体」と書き、記録の見出し（「…（熱水力のフィードバック）」）と違う
