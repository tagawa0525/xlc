# UFG の S(α,β) の移行の表の大きさと散乱源の手間

## 問題

ADR-0205 の S(α,β) の移行の表と散乱源は、正確さを先に作り、大きさと手間を詰めていない（ブランチ feat/ufg-sab-kernel のレビューの指摘）。

- 表の大きさ: 表は入射 317 点 × 移行 2389 点の長方形で、移行は全行で出射 0 eV に当たる −B(4) から始まる。入射が 10 eV より低い行の
  出射 0 eV 以下（値 0）を含み、lattice が使うのは出射が UFG の下限（4 eV）以上の移行だけ。H-1 の核種のステージの出力は 0.64 MB から
  21 MB になった（examples/depletion/dvc.lock、843e2223）。表の温度の間の温度（565 K など）の lookup は、表の全体を内挿する
- 表のコピー: lattice の `solve_cell` は、セルを解くたびに表（約 6 MB）を `Thermal` にコピーする（`Data` が温度の表を持っているので、借用で足りる）
- 散乱源の手間: `SabSource::add` は出射の格子点ごとに直列で、小区間ごとに `cumulative_at` を 2 回呼ぶ（同じ入射の行を 2 回探す）。
  ADR-0205 の測定（examples/depletion/verification.md「H in H2O の S(α,β) の UFG の散乱核（ADR-0205）」、b7541488）のログの経過時間
  （`--timed` でないジョブなので目安）は、S(α,β) のある散乱核が同じ扱いの自由ガスより長い（2A-40 の `fine_flux` で 504 s と 294 s、
  1C の 5 MWd/kg の `swap_absorption` で 303 s と 173 s）
- 掃き直しの始め: `Thermal::new` は S(α,β) の上方散乱の届く格子点を、自由ガスの上限と S(α,β) の上限の大きい方に移行の最大を
  足して決めるので、自由ガスの上限が S(α,β) の上限より上（`upper = 400` の 565 K で 19.5 eV と 10 eV）だと、掃き直す格子点が
  0.57 eV ほど余分になる（S(α,β) の上限 + 移行の最大で足りる）

関係する ADR: ADR-0205

## 完了の条件

表を、出射が UFG の下限以上の移行だけ（または行ごとに最初の 0 でない移行から）にして大きさを測り、表のコピーをやめ、散乱源の小区間の
評価を減らして（入射の行を 1 度だけ探す、D の区間と同じ並列にする）、`--timed` のジョブで時間を測る。結果がビットで変わるなら、
ADR-0205 の測定との差を記録する。
