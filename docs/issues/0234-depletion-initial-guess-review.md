# 燃焼の固有値計算の初期値（ADR-0231）のレビューで直さなかった指摘

## 問題

ブランチ perf/0156-warm-start-nem のローカルのレビュー（/code-review high）で、再現を書けず直さなかった指摘（/git-merge の「直す指摘の基準」の
non-blocking）。

関係する ADR: ADR-0231

1. 収束の判定（`Remaining::update`）は直前の 2 回の変化の比で残りを見積もるので、前の解から始めると、速いモードの比で見積もって遅いモードの
   誤差を残したまま止まりうる、という指摘。確かめた範囲では再現しない: `nem` の試し（2 群、高さ 400 cm の柱の 20 ノードと、4 × 4 の 1/4 の高さ
   360 cm の 16 層の炉心。上半分か外側の吸収と全体の吸収を変えた問題の、許容 1e-14 と 1e-13 の参照解に対する誤差）で、前の解から始めた解の中性子束の
   相対誤差は 9.7e-8〜9.9e-8 で、平らな初期値の解（9.7e-8〜9.9e-8）と同じ大きさ（テストのコードは残していない、2026-11-06）。小さな炉心の燃焼の出力の割合の
   相対差（examples/depletion/verification.md の「固有値計算の初期値（小さな炉心）」の Xe を時間で追う探索で 4.1e-6）は燃焼点 0 で 2.3e-7、ステップを
   重ねて 52 日で 1.8e-6 に育つ（平衡 Xe は 0.5e-7〜2.8e-7 で育たない）。比較の JSON の点ごとの差から、伝わって育つことが候補で、確かめていない
2. 点と中点の最初の固有値計算を平らな初期値にするのは、`deplete` の中の共有の `RefCell` を、点と中点の解の前ごとに手で空にする（`fresh`）形で、
   点を解く経路を足すときに呼び忘れると、黙って前の点の解から始まる。初期値を点と中点の解の中に持たせる（`solve_operating` が持って渡す）形にすると
   構造で守れる
3. ADR-0231 の「確認」の小さな炉心の項は k とホウ素の差だけを書き、燃焼度と出力の割合の相対差（記録の表の値。中性子束の許容の 2 倍を超える）を
   書いていない
4. 記録の小さな炉心の比較の時間（固有値計算の時間と全体の時間、その比）は手元の同時の 4 本の目安で、`--timed` のジョブの値ではない（記録の
   「計算」に目安と書いた。CLAUDE.md の「計算」は `--timed` を付けないジョブの時間を記録に書かないとする）。反復の回数は時間によらない
5. どの `Solved` も初期値（`Guess`）を持ち、燃焼は直前の解の `Guess` を複製して持つ。燃焼でない解の `Guess` は使わない。複製せずに移せる
6. 初期値の検査はノードの数と群の数だけで、ノードの並びが違って数が同じ問題の初期値は止めない（今は点と中点の解の中だけで引き継ぎ、同じ状態の
   並び）
7. 燃焼のテスト `eigenvalue_solves_from_the_previous_solution_keep_the_flat_start_results` は点ごとの固有値計算の回数が平らな初期値と同じことを
   確かめる。探索や平衡 Xe の打ち切りの境にある値が丸めの桁で動くと、正しい結果でも回数が 1 回違いうる

8. 全炉心の試行の燃焼の履歴 `examples/depletion/p9-timing/trial-0231/core-p9.msgpack`（md5 792c2a19）は、`trial-0231/compare-guess.json` が md5 で引くが
   `dvc add` していない（小さな炉心の `branches/compare-core-small-*.json` が引く履歴と同じ扱い）。worktree を消すと戻らない
9. 全炉心の初期値の比較（`trial-0231/compare-guess.json`）は、記録に表とコマンドが無く、ADR-0231 の「確認」に値をコピーしただけ（小さな炉心の節は
   `core_guess_runs` と `core_guess_differences` で表を描く）
10. `trial-0231/core-p9.toml` の注の相対パス（`../../vera/p5/hzp/core-hzp.toml`、`../p2/lattice-2A.toml`）は、移す前の置き場のままで、無いファイルを指す
11. `examples/verification_tables.py` の p9 の表の出どころを替えた変更（dce2efd0）を、それを確かめるテスト（9c313b3b）より先にコミットした（TDD の順）
12. 試行の入力 `trial-0231/core-p9.toml` は `p9_timing_inputs.py` の書く `core-p9.toml` のコピーで、`--check` はコピーとの一致を確かめない
13. Slurm 702 の中点の平衡 Xe の 2 回目の解き直しは、外側の反復 1 回あたり 43 ms（ほかの 24 回は 29〜31 ms）で、212.3 s かかった。原因は確かめていない
14. コミット ebdc31a7 の本文は、試行が使う p5 のテーブルのライブラリを 55be71c9 と書くが、使ったステージ（軸方向の平板と反射体）の p5 の dvc.lock は
   0dfa3aca（記録、ADR-0231、#0235 は 0dfa3aca）

前提が誤っていて issue にしない指摘: 燃焼の点の探索を状態の探索とビットで比べるテスト（`searched_points_match_the_state_search_at_the_same_uniform_burnup`）を
`initial-guess = "flat"` にしたのは許容を緩めたのではなく、状態の探索（平らな初期値）と同じ計算をビットで比べるテストの意図を保つため。既定の経路と平らな
初期値の一致は、新しいテストが許容の中で確かめる。
