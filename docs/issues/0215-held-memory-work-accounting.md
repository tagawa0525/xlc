# 減速計算の作業の配列の数え方の残り（#0212 のレビュー）

## 問題

issue #0212 の直し（ADR-0213 の「## 変更」、2026-11-03）は、1 回の減速計算の量から、`solve_cell` が手で挙げた格子点に比例する配列の確保を
除いて持つ区間の上限にする。fix/0212-lattice-depletion-memory の 1 周目の /code-review（2026-11-03、HEAD ac7fa356e）が挙げた次の点は、
落ちるテストか再現する手順が無いので直していない（間引かない格子の 2A の 1 ステップは MaxRSS 69.2 GiB で流れた。Slurm 652）。

- 数えていない配列: `Thermal` の今のスイープの累積の積率（`prefix`。リングごとに格子点（start から）あたり 48 B）、`finish` で前の
  スイープに移した積率と `flux.to_vec()` の中性子束の写し。自由ガスの範囲の広い入力では、数えた列と同じ桁になりうる（測っていない）
- 倍に伸びる確保: `Prefix.values` は空から伸び、`finish` のたびに伸ばし直す。自由ガスの σs の列は `collect::<Result<Vec<_>, _>>()` で
  伸びる。`lethargy_grid` の返す配列も足した点で伸びうる
- 数えすぎ: 自由ガスの枝の `energies` は `Thermal::new` の後に捨てるが数える。核種の格子の和、間引いた格子、`lethargy_grid` の
  `u` と `energies` は格子点を作った後は使わないが、関数の終わりまで残して数える（先に捨てれば、メモリも差し引きも減る）
- 形: 配列を足すたびに `solve_cell` の `work +=` に足す必要があり、漏れやすい。配列を持つ型（`Sweep`、`Thermal`、`Prefix`）が
  自分の確保を返す形にすると、数える場所と確保する場所が揃う。数え漏れを止める試験（小さな入力で held と work の和、または
  計数するアロケータ）が無い
- ログ: `UFG slowing down` の `work` は、`Scattering::Static` と `sweeps = 1`（差し引かない経路）でも出るので、コメントの「持つ区間の
  上限から除いた」が成り立たない
- 数えない段: `release` の後の移行の計数（`segment_groups`、`collapse`）と飛程の表は、どの量にも入らない。間引かない格子で測っていない

3 周目の後の記録のための周（2026-11-03、HEAD 412d076ab。指摘は直さない）が、#0212 と ADR-0213 の記録に次を挙げた。ADR-0213 の決定と
理由の事実（最初の項）は、マージの後には「## 変更」でしか直せないので、マージの前に判断が要る。

- ADR-0213 の決定と理由の、数える作業の配列の一覧に、自由ガスの枝の `energies` のコピー（コードは数える）が無い
- #0212 の「原因」と ADR-0213 の「## 変更」の OOM の比べ方: 使用可能メモリ（80.1 GiB）は自己遮蔽の始めの常駐の分 B を除いた値なので、
  持たないときの MaxRSS 26.8 GiB（B を含む）を残りの 17.6 GiB と比べるのは B を 2 度数える。B + 80.1 GiB と 89.3 GiB、または MemTotal
  92.0 GiB と止めたときの RSS で比べる。B は記録に無い
- 量の式の書き方: #0212 の「8 割から 2 GiB を除いた分」は 0.8 × A − 2 と読める（コードは（A − 2 GiB）× 0.8）。ADR-0213 の「## 変更」の
  「80.1 GiB の 2 割と 2 GiB で 17.6 GiB」は 2 割 × 78.1 + 2 の値
- ADR-0213 の帰結と input.rs の `ufg-hold-memory` の説明の「作業の配列と持つ区間を合わせて量まで」は、作業の配列が量を超えたとき
  （持つ区間は 0 まで下がるが作業の配列は抑えない）と、`Scattering::Static` と `sweeps = 1` の経路では成り立たない
- 持たないときの 12.4 GiB（Slurm 457、16 スレッド）から 26.8 GiB（Slurm 646、32 スレッド）への増え方は、ADR-0213 では説明できず、
  ADR-0214 の同時に解く数の倍と列の倍の確保が候補で、確かめていない（#0212 は書いていない）
- #0212 の手元のピンのライブラリの注で、653 の試行も examples/depletion/p2/depletion.msgpack（e84310af）を使うのに、2A の試行を
  d86514f8 とまとめて書いた
- ADR-0213 の帰結の「全体の量 59 GB ほど」「6 GB ほど」は `free -g` の GiB の値。Slurm 457 の日付（JST）と dvc.lock のログの時刻（UTC）の
  書き分け。652 の入力を ADR-0213 は examples/depletion/lattice-2A.toml と書くが、流したのは trials/0212/2A-fixed2.toml（ac7fa356e）
- 試行の入力は 6d50c467b で外したので、#0215 の完了の条件の入力は ac7fa356e から戻す（残すなら examples/depletion/ に `git mv`）

関係する ADR: ADR-0213
