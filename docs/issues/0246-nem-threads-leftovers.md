# core の色の順の並列の残り（粗メッシュの並列の効き、組み立て、スレッドの規則の共有）

## 問題

ADR-0234 で固有値計算を市松の 2 色の順で並列に解いた後に、次が残る。

- 粗メッシュの固有値問題の並列の効き: 全炉心の BOC の固有値計算 1 回（`trials/0156/boc-rb-<数>.toml`。c68d6320 の `trials/p9-timing/boc-1100.toml` に
  `threads` を足した手元の試行の入力。コミットしていない）の粗メッシュの問題の時間は、1 スレッドで 7.89 s、16 スレッドで 1.49 s（粗メッシュの反復 17,894 回で 1 回
  83 µs。Slurm 710、区分 trial、63bdc95a0 と同じコード、2026-11-06。時間は目安）で、8 スレッドの 1.36 s から縮まない。1 回の反復は色ごとの解きと規格化の
  3 回の並列の呼び出しで、仕事を配る時間が候補（確かめていない）
- 粗メッシュの問題の組み立て（span `homogenize`）は 1 スレッドで 0.80 s、16 スレッドで 0.46 s（同じ試行）。外側の反復ごとに `Coarse::colored` が色の並べ替え、同じ色の
  隣の検査、全部の入力の並べ直しをやり直し、ノードごとの小さな `Vec` を作って平らな配列に詰め直す（ADR-0234 のレビューの 1 周目と 2 周目の指摘）。色の並びは
  `nem::Core` が固定で持つので、色の順に直接組み立てる形が候補
- `nem::Core::write_color` は 1 色を書くのに全ノードを 10 本の配列の zip で回り、もう一方の色を飛ばす（レビューの指摘。速さへの効きは測っていない）
- `xlc_cmfd::Coarse::colored` と `Coarse::new` は、隣の番号や中性子束の長さがセルの数と合わない入力でエラーでなく panic する（レビューの指摘。core の組み立ては
  合う入力だけを作る）
- スレッドの数の規則（`RAYON_NUM_THREADS` の読み取りと、物理コアの数を許された論理 CPU の数で抑えた既定）が、lattice の `use_allowed_cpus`、xs の
  `parallel::cores`、core の `use_threads` に分かれている（レビューの指摘）。共通のクレートに移すと xs と lattice の実行ファイルのバイトが変わる（ADR-0232 の案 S2
  と同じ）。物理コアの数は機械の全体の数なので、排他でない `-c` のジョブでは SMT の兄弟を含む数になる（xs と同じ。CLAUDE.md の「計算」）
- 比べるツールの `parse` は、`compare_core_guess.py` と `compare_core_acceleration.py` でも空のパスを見つけない（`Path('')` は `.`。`compare_core_threads.py` は直した）

関係する ADR: ADR-0234

## 完了の条件

粗メッシュの問題の並列の効きと組み立ての時間の内訳を全炉心の BOC で測り、直せるものを直す（#0242 の粗メッシュの解き方の比較と合わせて決める）。スレッドの数の規則を
共有するかは、xs か lattice の実行ファイルが次に変わる作業で決める。

- 2026-11-06: ADR-0234 の実装とレビューの 1、2 周目で残した
