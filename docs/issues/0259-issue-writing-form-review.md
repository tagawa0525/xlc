# issue の書き方（ADR-0235）のレビューで残した点

## 問題

ADR-0235 の決定と、それをコピーした docs/issues/README.md のテンプレートと「運用」に残る点:

- ADR-0235 のフロントマターの `issues` に、背景で挙げた #0248、#0254、#0258 が無い。足すと、その 3 件の「関係する ADR:」も
  直すことになり、既存の issue は直さないとした帰結と合わない
- 「経緯」に hash を書かない（決定の 2）ことと、値を書くなら出典・コミット・日付をそろえる（決定の 4）ことの間で、値を書く
  1 か所をどの節に置くかが決まっていない（「経緯」の行に置くと 2 と食い違う）
- README の「運用」は ADR-0235 の決定の 4 項をそのままコピーしており、ADR-0235 の決定を「## 変更」で変えたときに片方だけが直りうる
- 「問題」の最後の点を消したとき（全部が直ったとき）に閉じるのか、「完了の条件」で決めるのかが書かれていない
- この形で記録の周の後の例外の周が減るか（ADR-0235 の帰結）を、次に issue を残すブランチのマージの本文の周の数で見る

関係する ADR: ADR-0235

## 完了の条件

上の点ごとに、README か ADR-0235 の凍結しない節を直すか、直さない理由を書き、周の数を 1 本以上のマージで見てから閉じる。
