# issue の書き方（ADR-0235）のレビューで残した点

## 問題

ADR-0235 の決定と、それをコピーした docs/issues/README.md のテンプレートと「運用」に残る点:

- ADR-0235 のフロントマターの `issues` に、背景で挙げた #0248、#0254、#0258 が無い。足すと、その 3 件の「関係する ADR:」も
  直すことになり、既存の issue は直さないとした帰結と合わない
- 「経緯」に hash を書かない（決定の 2）ことと、値を書くなら出典・コミット・日付をそろえる（決定の 4）こと、検証の記録の数値を
  名前で指すときもコミットを添える（ADR-0235 の決定と理由が指す ADR-0117 の「記録の辿り方」）ことの間で、コミットを添える値と
  名前の指し先をどの節に置くかが決まっていない（「経緯」の行に置くと 2 と食い違う）
- 決定の 4 の「名前（文書と節）で指す」の文だけでは、検証の記録の数値にコミットと日付を添えることが読めない（決定の 4 の下の
  段落にだけある。README の「運用」も決定の 4 項と、記録の数値の項に分けて書く）
- 捨てた形に測った値を残す（決定の 3）とき、その値がほかの文書にあれば決定の 4 とどちらを当てるかが書かれていない
- ADR-0117 の「## 変更」の項は前の文を「…」で省いて引き、省いた部分の主語（ADR と issue）が、直した文で ADR だけになったことが
  項の引用からは読めない
- README の「運用」は ADR-0235 の決定の 4 項をそのままコピーしており、ADR-0235 の決定を「## 変更」で変えたときに片方だけが直りうる
- 「問題」の最後の点を消したとき（全部が直ったとき）に閉じるのか、「完了の条件」で決めるのかが書かれていない
- ADR-0117 の決定と理由の項は、見出しが「ADR と issue（ADR-0115 から引き継ぐ）」のまま、issue の部分は ADR-0235 を指すだけになり、
  本文は「ADR は」が 2 度続く
- ADR-0235 の `requires` の ADR-0122 は、決定と理由が添えるコミットの意味を指すだけで、前提と言えるかが決まっていない
- 下の完了の条件の「ADR-0235 の凍結しない節」では、決定の 2〜4 の文を直せない（決定を変えるには docs/adr/README.md の「運用」の
  「## 変更」が要る）
- この形で記録の周の後の例外の周が減るか（ADR-0235 の帰結）を、次に issue を残すブランチのマージの本文の周の数で見る

関係する ADR: ADR-0235

## 完了の条件

上の点ごとに、README か ADR-0235 の凍結しない節を直すか、直さない理由を書き、周の数を 1 本以上のマージで見てから閉じる。
