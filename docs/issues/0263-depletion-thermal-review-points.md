# 燃焼の熱水力のブランチのレビューで直さなかった点

## 問題

燃焼のステップの熱水力（#0228、ADR-0229 の「燃焼のステップ」。ブランチ feat/0228-depletion-thermal-hydraulics）の /code-review の 1〜3 周目で、
/git-merge の「直す指摘の基準」の blocking に当たらないとした指摘。どれも今のコードに残る。

- 減速材の密度の履歴の変数（ADR-0215）は、熱水力の燃焼ではノードの温度の IF97 の密度、熱水力のない燃焼ではテーブルの格子点の組を温度で
  内挿した密度（crates/core/src/state.rs の `moderator_density`）。格子点の間では、定数は格子点の組の線形の内挿で引くので、履歴の変数の
  密度と定数の密度が格子点の間の内挿の差（ADR-0229 の帰結の約 0.003 g/cc）だけ違う。どちらに合わせるかは、HFP の範囲の本番のテーブルで
  履歴の補正の効きを測ってから決める
- `CoreHistory::from_msgpack`（crates/core/src/depletion.rs）は、状態の `moderator` と `fuel` か `inlet` のどちらか一方を持つことと、点の
  `temperatures` の形（集合体 × 軸方向のノード × 2）と状態の `inlet` の有無の一致を確かめない。core が書く履歴はこの形を満たす
- `advance_history` は燃焼度 0 のまま解く点で瞬時の値 x を返すので、熱水力のない燃焼でも、燃焼度 0 のノードの履歴の変数は点を解いた状態の
  値になる（崩壊だけのステップで始まり、状態を変える燃焼で、記録する値が燃焼点 0 の状態の値から変わる）。燃焼度 0 の残りは 0 なので定数には
  効かない。ADR-0215 の帰結に今の規則として書いた。変えるなら ADR-0215 の変更
- 熱水力のない燃焼でも、履歴の変数のステップの値と進めた値を、固有値計算ごと（探索の評価と Xe の解き直しのすべて）に作り直す（効率）
- 燃焼点 0 の前の熱水力の履歴の変数の値（入口の温度の密度）は、燃焼点 0 の解の値で必ず置き換わるので、作る処理は要らない（`deplete` の
  `histories` の初めの値）
- examples/depletion/compare_core_thermal.py の `moderator_max`、`fuel_max` は、点の `temperatures` の空の行（ノードのない位置）を除かない
- crates/core/src/input/tests.rs の `depletion_takes_thermal_hydraulics_with_inlet_states` の doc コメントが「燃焼のケースの熱水力は未実装」の
  まま
- `deplete` の中で、クロージャ `node_densities`（ノードの温度 → IF97 の密度）と、restart の数密度の束縛 `node_densities` が同じ名前
- ADR-0229 の「出力」は状態の解の標準出力の項目を決め、燃焼の点と中点の熱水力のログ（出口の温度の最大など）は帰結にだけ書いてある
- ADR-0229 の「繰り返し（案 I1、B1）」はテーブルを「ケースの状態の…燃焼度」で引くと書き、燃焼のケースではノードの燃焼度で引く（ADR-0190）。
  燃焼のステップの繰り返しの初めの出力の「位置の出力の割合」は、ADR の中の「集合体の位置」と紛れうる（コードはノードごとの出力）
- ADR-0229 の「燃焼のステップ」の「探索と Xe の反復が解く関数が熱水力を含む 1 つの関数になる」は、繰り返しの許容の中で成り立つ（初めの
  出力が前の解で変わる）
- ADR-0229 の「燃焼のステップ」の「解の熱出力」は、停止の前の点を平衡 Xe で解くとき、終わったステップの状態の入口の温度で Xe を釣り合わせる
  解を先に解くことを書かない（決定は点を解く状態の入口の温度だけを書く）
- ADR-0229 の「## 変更」の、停止の前後の点を熱出力 0 で解く案を採らない理由（平衡 Xe の点の出力の水準との食い違い）は、平衡 Xe を作らない
  停止の後の点と Xe を時間で追うケースには当たらない
- ADR-0229 の「燃焼のステップ」の解の熱出力のうち、崩壊だけのステップの前後の点と、燃焼度 0 のまま解いた燃焼点 0 のほかの点の履歴の変数を
  確かめるテストが無い（「確認」の燃焼のステップのテストは出力のステップだけを見る）
- crates/core/src/depletion.rs のモジュールの説明（燃焼度 0 の値）、`advance_history` の中、`deplete` の履歴の変数の初めの値と燃焼点 0 の解の
  後のコメント、`point_power` の上のコメントと、crates/core/src/depletion/tests.rs の熱水力の履歴の変数のテストのコメントは、燃焼度 0 の値と
  前に出力のステップの無い点の割合を、ADR-0215 の帰結と ADR-0229 の決定より狭く「燃焼点 0」で書く
- `point_power`（crates/core/src/depletion.rs）は、出力のステップが 1 つも無いとき、黙って割合 1 を返す（`.unwrap_or(1.0)`）。TOML の入力の
  検査は出力のステップの無い燃焼を止めるが、`DepletionInput` を直に組み立てて `deplete` を呼ぶと届く
- `point_power` の上のコメントは、平衡 Xe の反応率の出力の水準の出典を「ADR-0218、ADR-0229」と書く（規則は ADR-0219 の決定の「出力のある解」）。
  crates/core/src/depletion/tests.rs の `thermal_depletion_points_heat_the_channels_at_their_operating_power` のコメントは、運転している出力の
  割合を ADR-0218 の案 P2 に帰す（案 P2 は点を解く状態を決め、割合は ADR-0229 の「燃焼のステップ」）
- crates/core/src/depletion.rs のモジュールの説明の「崩壊だけのステップは燃焼度が進まないので変えない」は、燃焼度 0 のノード（崩壊だけのステップの
  後の点で解いた値になる）には当たらない
- 例外の周（ADR-0229 の出典を直した後）の指摘:
  - ADR-0229 の「## 変更」の、停止の前の点を熱出力 0 で解く案を採らない理由は、崩壊だけのステップが別の状態を指す平衡 Xe のケース（Xe は別の解で
    釣り合わせる）と、Xe を時間で追うケースには当たらない。燃焼点 0 を停止の前の点と同じ扱いとする理由づけも、燃焼点 0 が出力のステップの初めの
    点であることと合わない
  - ADR-0229 の「解の熱出力」は、ADR-0219 の「出力のある解」が平衡 Xe のケースだけの規則であることを書かない（Xe を時間で追うケースは、どの点も
    この決定で決まる）。「前に出力のステップの無い点」と「停止の前後の点」の文は、前の文の繰り返し
  - この issue の、熱出力 0 の案の理由の項は前の文を引いたままで、停止の後の点の分は「## 変更」で直った。`point_power` のコメントの項の
    「規則は ADR-0219 の『出力のある解』」は、燃焼点 0 と停止の後の点を含まないので、コメントの出典は ADR-0229 の「燃焼のステップ」
  - この issue の「経緯」は同じ日に 4 項で、docs/issues/README.md の「日付ごとに 1〜2 行」を超える。ADR-0215 の帰結の熱水力の文の「（解の値）」は、
    同じ項の前の括弧の繰り返し
