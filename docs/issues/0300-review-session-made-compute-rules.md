# ユーザーの発言の記録が無いまま決まった計算と DVC の規則を見直す

## 問題

計算と DVC の規則のうち、次の 5 件は、中身を決めたのが過去のセッション（親か担当）で、その中身についてのユーザーの発言が
会話の記録に見当たらない。1 はコミットの本文と ADR-0184 の「## 変更」に、5 はスキルに、ユーザーの決定として書かれていて、
ユーザーが決めた規則と読まれうる（経緯は ADR-0258 の背景の「上流を飛ばす実行を数秒のステージに限る規則の経緯」）。

出どころは 2026-11-19 の調査（コミットと会話の記録の読み比べ）で、親のセッションが自分で確かめたのは 1 の経緯と 4 の
ユーザーの発言の 2 か所。ほかは担当の調査による（親は確かめていない）。

1. ADR-0184 の、`dvc repro -s` を数秒のステージに限る制限（3c11ece7f、2026-10-22）。/code-review が CLAUDE.md の文言と計画の
   手順の食い違いを指摘したのがきっかけで、前後の会話の記録にこの制限についてのユーザーの発言は無い。例外を足した
   50c2b69ef（2026-11-03）の本文の「ユーザーの判断」と、ADR-0184 の「## 変更」の同じ日の項の「ユーザーが決めた」は、親の 3 件の推奨への
   一括の承認で、「数秒」の限定は親の文に入っていた。
   状態: ADR-0258（proposed）が直す対象にしている（決定と理由の「実行」、「移行の順」の 2 と 3）
2. ADR-0257 の、`scripts/dvc-repro.py` の `--max-stages` と `--allow-reference`、生の `dvc repro` を止める hook（ADR を書いたコミットは
   4d55be897、2026-11-19）。規則を script と hook に移すことはユーザーの指示で、どの規則を移すかと中身はセッションが決めて事後に報告した。
   状態: `-s` を受けない部分だけ、ADR-0258（proposed）が直す対象にしている（「移行の順」の 2）。ほかは見直していない
3. ADR-0212 の (b)、`dvc commit` の付け直しは ADR が決めた移行だけ（dd06fe8ec、e4d7ff75d、293ecc3a1、2026-10-28）。ユーザーが
   承認したのは、条件を ADR で決める進め方までで、条件の中身は担当が決めた。状態: 見直していない
4. ADR-0130 の帰結の「数秒で終わるステージだけは再実行してよい」（a548a9098、2026-10-12）。重いステージを再実行しない部分は
   ユーザーの求めに沿う（同じコミットの本文）。「数秒」の線には、ユーザーの発言の出どころが見当たらない。記録にあるのは、
   再実行するかは時間により、2 時間程度なら待ってもよいという考え（ユーザー 2026-10-22）。
   状態: ADR-0258（proposed）が直す対象にしている（「移行の順」の 3）
5. スキル compute の「高速化の途中は、高速化の測定以外のジョブを流さない」（142ae27f1、2026-10-28 がセッションの memory から
   CLAUDE.md に移し、a63a6fb4a、2026-11-19 がスキルに移した）。もとは、特定の高速化が進んでいた場面での、絶対ではないと添えた
   意見（ユーザー 2026-10-24）。常設の規則にしたのはセッションで、スキルの項は（ユーザー 2026-10-24）を添えている。
   状態: 常設の決まりから外し、スキルの項を場面ごとの判断の目安に直した（2026-11-20）。ユーザーは、高速化の途中で本番の計算を
   流すより、終わらせてから流した方が時間の節約になるだろうという程度の提案で、禁止ではないと述べた（ユーザー 2026-11-20。
   別のセッションが尋ねた場面の発言で、このセッションはその要約で受け取った）

見直しの対象でないもの（ユーザーが求めたか、個別に承認した。担当の調査による）: ADR-0175、ADR-0223、ADR-0222、読めなくなった出力の再実行の
後回し（スキル compute）、ADR-0122 の試行の運用（原文は会話の記録の残る前）。

調べられなかった範囲: 2026-10-11 21:40 JST より前の会話、記録の無い 2 つのセッション、担当に直接出された指示。

関係する ADR: なし（上の ADR のフロントマターの `issues` には、まだこの issue を挙げていない）
