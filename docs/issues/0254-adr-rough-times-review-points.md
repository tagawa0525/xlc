# ADR の目安の時間の規則の残り

## 問題

CLAUDE.md の「計算」の節の「ADR の「検討した案」には、/slurm-run の「ログと時間」の節の TIME 行の規則が記録に使わないとする時間と、
作業中の版で出した時間を目安として書いてよく…」の文と、それに関わる文書に残る点:

規則の文の間

- docs/adr/README.md の「書き方」は「測った数値は、その時点の値として、出典のファイルと、数値を出したコミット（checkout すれば
  再現できるもの。ADR-0122）と日付を添える」とし、上の文は作業中の版で出した時間を許して日付を求めない。どちらを優先するかが
  書かれていない
- 同じ段落の「付けないジョブは main で、timed のジョブに止められうるので、その時間は記録に書かない」は、区分 `timed` で `--timed` を
  付けないジョブ（同じ段落の「`--timed` を付けなくてもパーティション timed」）を main と読ませる
- 同じ段落の「その時間は記録に書かない」（main のジョブと `-c` のジョブの 2 か所）と、グローバルの CLAUDE.md の「付けないジョブの
  時間は、止められなくても記録に使わない」は「記録」を狭めておらず、上の文が ADR の「検討した案」への例外であることが、その 2 か所
  から読めない
- 上の文は「検討した案」だけに掛かり、「決定と理由」が同じ時間を理由に使うとき（ADR-0234 の Slurm 709 と 710）の扱いが無い
- TIME 行に印を付ける前のログのジョブを、上の文の対象にどう当てるかが決まっていない（例: ADR-0204 の「検討した案」の Slurm 473 の
  「38 分の実績」。`sacct` でパーティション main、ログの TIME 行に印が無い）

今の ADR

- ADR-0234 のほかにも、accepted の ADR の「検討した案」が、TIME 行に `preemptible:` の印のあるジョブの時間を印なしに目安として
  引く: ADR-0228 の Slurm 672 の「59 分」
- 上の文を、それより前に確定した ADR（ADR-0234 など）の「## 補足」に当てるかが決まっていない（docs/adr/README.md の「運用」の
  「今ある ADR を新しい形に書き直すことはしない（…）。この運用は、今ある ADR も含めて、以後の変更から当てる」）

### 検討して捨てた形

印を付ける前のジョブを日付や時刻で分ける境目として試し、捨てたもの:

- 最初のパーティション `timed` のジョブ（Slurm 514、2026-10-24T00:13 に開始）: それより前に main のジョブが止められていた（下の 498）
- Slurm 498 の反例: パーティション main で 2026-10-23T21:48:07 に始まり、パーティション urgent の Slurm 499（21:48:28 に開始）に
  止められて `Suspended` が 00:01:01（`sacct`）
- パーティション urgent を入れた nixfiles のコミットの時刻（2026-10-23 20:54）: ブランチのコミットの時刻で、urgent が効いた時刻では
  ない（マージは 2026-10-23 21:39:27）
- `journalctl -u slurmctld` の 2026-10-23 21:40:37「preparing for 2 partitions」: `slurm-history.sh` の `PREEMPT_SINCE` のコメントの
  2026-10-23 21:40:32 の nixos-rebuild switch と同じ出来事を指し、既にある規則の境目を issue で立て直すことになる
- /slurm-run の「ログと時間」の節の「割り込みを反映する前」の段落と `PREEMPT_SINCE` を指す形: その段落は `slurm-history.sh` の表に
  入れるジョブを選ぶ規則で、ADR の時間に印が要るかを決める規則ではない

関係する ADR: なし

## 完了の条件

各点について、CLAUDE.md、docs/adr/README.md、各 ADR の凍結しない節を直すか、直さない理由を書いて閉じる。README の再現の
要件との優先と、印を付ける前のジョブの扱いは、規則の決定が要る。
