# ADR の目安の時間の規則のレビューで直さなかった指摘

## 問題

CLAUDE.md の「計算」の節に、ADR の「検討した案」には `--timed` でないジョブの時間と作業中の版で出した値を目安として書いてよい
とする 1 文を足したブランチ（docs/claude-md-adr-rough-times）の 1 周目のレビューで、/git-merge の「直す指摘の基準」の blocking に
当たらず直さなかった指摘:

1. docs/adr/README.md の「書き方」は、測った数値に「数値を出したコミット（checkout すれば再現できるもの。ADR-0122）と日付」を
   添えるとする。CLAUDE.md の足した文は、作業中の版の値と `commit=<hash>-dirty` を許し、checkout しても再現できない。
   2 つの規則のどちらを優先するかが書かれていない
2. 足した文は 2026-11-07 のユーザーの判断によるが、CLAUDE.md のほかの決定のような「（ユーザー <日付>）」の印と ADR が無い
3. ADR-0234 のほかにも、目安の時間を引く accepted の ADR に、割り込まれうる印の無いものがある: ADR-0204 の「検討した案」の
   Slurm 473 の「38 分の実績」と、ADR-0228 の「検討した案」の Slurm 672 の「59 分」（`sacct` でどちらもパーティション main）。
   指摘は ADR-0201 の Slurm 531 と 532、ADR-0215 の Slurm 625 も挙げたが、どちらの ADR もそのジョブを k∞ や pcm の値の出どころとして
   引き、時間は引いていない
4. ADR-0234 の「決定と理由」も Slurm 709 と 710 の時間を理由に使うが、足した文は「検討した案」だけに掛かる。#0253 も「決定と理由」に
   触れていない
5. `-c` のジョブは排他でなく CPU を共有する（`TIME:` 行の `shared (-c N)`）が、足した文は割り込まれうることだけを添えさせる
6. 足した文はコミットだけを求め、日付を求めない（docs/adr/README.md の「書き方」は日付も求める）
7. 足した文は「ジョブのコメントの `commit=`」と書くが、終わったジョブの `sacct` の `Comment` の列は空で、`commit=` は SubmitLine の
   `--comment` に残る（`~/.claude/scripts/slurm-run.sh` のコメント。元は nixfiles のリポジトリ）。読む場所を書いていない

2 周目のレビューで直さなかった指摘:

8. 同じ段落の「その時間は記録に書かない」（main のジョブと `-c` のジョブの 2 か所）と、グローバルの CLAUDE.md の「付けないジョブの
   時間は、止められなくても記録に使わない」は「記録」を狭めておらず、グローバルの CLAUDE.md は ADR を「設計の記録」に置く。足した
   文が例外として掛かることが、前の 2 か所から読めない
9. 足した文は「割り込まれうるジョブで時間を記録に使わないことを添える」と書く。/slurm-run の「ログと時間」の節は、`timed` で
   走らなかったジョブの TIME 行に「止められなかったときも `preemptible: 割り込まれうるので時間は記録に使わない（記録するなら排他の
   --timed）` が付く」とする。足した文の「割り込まれうるジョブ」が、この TIME 行の規則の対象（`--timed` でないジョブの全部）と
   そろうか、条件つきで一部に限ると読めるかが書かれていない
10. #0253 の完了の条件は、2026-11-06 に accepted になった ADR-0234 に 2026-11-07 の規則の印を足させるが、docs/adr/README.md の「運用」は
    「今ある ADR を新しい形に書き直すことはしない」とする。新しい規則を前の ADR に当てるかを先に決めていない
11. ADR-0234 は Slurm 709 の版を「作業中の版（コミットしていない）」とだけ書き、元のコミットとブランチを書いていない（指摘は、ジョブの
    記録にブランチ perf/0156-nem-threads と worktree のパスがあるとした。確かめていない）。#0253 は割り込まれうる印だけを足りないと
    している
12. このブランチの 9c0abbab3 は ADR-0234 の `issues` に #0253 を足し、c54ce936f が外した。マージの後の履歴に、最後の形と合わない
    コミットの本文（「両方向に結ぶ」）が残る

3 周目のレビューで直さなかった指摘:

13. 項 10 は docs/adr/README.md の「運用」の文を途中で切っている。続きは「この運用は、今ある ADR も含めて、以後の変更から当てる」で、
    「## 補足」は確定の後も直してよい節なので、README は ADR-0234 に印を足すことを禁じていない、という指摘
14. 項 12 のコミットの本文は、マージの後には直せない（直すならマージの前に 9c0abbab3 と c54ce936f をまとめる）
15. 項 11 の Slurm 709 のブランチと worktree は `sacct -j 709 --format=SubmitLine` で確かめられる。709 は `commit=` を付ける前に
    投げたので、ジョブの記録にコミットは無い、という指摘（確かめていない）

関係する ADR: なし

## 完了の条件

各項について、CLAUDE.md か docs/adr/README.md を直すか、直さない理由を書いて閉じる。1 はユーザーの判断（作業中の版の値を
目安として書いてよい）と README の再現の要件のどちらを規則にするかの決定が要る。
