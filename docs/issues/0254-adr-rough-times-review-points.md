# ADR の目安の時間の規則の残り

## 問題

ADR-0122 の決定と理由の例外の項（ADR の「検討した案」に案を比べる目安として書く時間は、出し直せるコミットでなくてよい。
docs/adr/README.md の「書き方」が指す）と、それに関わる文書に残る点:

規則の文の間

- CLAUDE.md の「計算」の節の「付けないジョブは main で、timed のジョブに止められうるので、その時間は記録に書かない」は、区分
  `timed` で `--timed` を付けないジョブ（同じ段落の「`--timed` を付けなくてもパーティション timed」）を main と読ませる
- CLAUDE.md の同じ段落の「その時間は記録に書かない」（main のジョブと `-c` のジョブの 2 か所）と、グローバルの CLAUDE.md の
  「付けないジョブの時間は、止められなくても記録に使わない」は「記録」を狭めておらず、ADR-0122 の例外が ADR の「検討した案」に
  掛かることが、その 2 か所から読めない
- 例外は「検討した案」だけに掛かり、「決定と理由」が同じ時間を理由に使うとき（ADR-0234 の Slurm 709 と 710）の扱いが無い
- 割り込みを入れる前に走ったジョブに、例外の「割り込まれうるジョブ」の条件をどう当てるかが決まっていない（例: ADR-0204 の
  「検討した案」の Slurm 473 の「38 分の実績」。`sacct` でパーティション main、2026-10-23T12:55 に終了、ログの TIME 行に印が無い）
- CLAUDE.md の「計算」の節の「記録の数値には、それを出したコミットと日付を添える（checkout すれば再現できるため）」に、ADR-0122 の
  例外が掛かることが書かれていない
- docs/adr/README.md の「書き方」の「コミットが簡単に分からなければ、ファイルと日付を書く」と、例外の項の「元のコミットを決め
  られなければ「確かめていない」」の、どちらを当てるかが書かれていない
- 例外の範囲（パーティション timed で走らなかったジョブ、手元の実行）に、パーティション timed で作業中の版を実行した時間が入らない。
  パーティション urgent のジョブは範囲に入るが、例外の項の出した条件のどれにも当たらない
- 例外の項を足した ADR-0122 の「## 変更」は、変えていない元の文を「前は」で引く（足しただけの変更を README の「運用」の形でどう
  書くかが決まっていない）
- ADR-0122 のフロントマターの `issues` に #0254 が無く、#0253 と #0254 の「関係する ADR」は「なし」で、ADR-0122 と issue の間をたどれない
- #0253 は「確定した ADR に当てるか」の決定を待つ（`blocked-by`）が、その決定の例が ADR-0234 そのもので、ADR-0204 と ADR-0228 には
  別の issue が無い
- ADR-0122 の案 D に「測り直し」が残る（今の日本語の辞書は通す）

今の ADR

- ADR-0234 のほかにも、accepted の ADR の「検討した案」が、パーティション main のジョブの時間を、目安であることと出した条件を
  添えずに引く: ADR-0228 の Slurm 672 の「59 分」（ログの TIME 行は `preemptible:`）
- 例外を、それより前に確定した ADR（ADR-0234 など）の「## 補足」に当てるかが決まっていない（docs/adr/README.md の「運用」の
  「今ある ADR を新しい形に書き直すことはしない（…）。この運用は、今ある ADR も含めて、以後の変更から当てる」）

### 検討して捨てた形

割り込みを入れる前のジョブを分ける境目として試し、捨てたもの:

- 最初のパーティション `timed` のジョブ（Slurm 514、2026-10-24T00:13 に開始）: それより前に main のジョブが止められていた
  （Slurm 498 は main で 2026-10-23T21:48:07 に始まり、パーティション urgent の Slurm 499（21:48:28 に開始）に止められて `Suspended` が
  00:01:01。`sacct`）
- パーティション urgent を入れた nixfiles のコミットの時刻（2026-10-23 20:54）: ブランチの上のコミットの時刻で、マージは
  2026-10-23 21:39:27 だった
- `journalctl -u slurmctld` の 2026-10-23 21:40:37「preparing for 2 partitions」: 反例は見つかっていない（498 はこの後に始まった）。
  同じ出来事（`~/.claude/scripts/slurm-history.sh` の `PREEMPT_SINCE` のコメントの、2026-10-23 21:40:32 の nixos-rebuild switch）の
  境目が既にそのスクリプトにあり、issue で別に立てないために捨てた

境目でない形:

- /slurm-run の「ログと時間」の節の「割り込みを反映する前」の段落と `PREEMPT_SINCE` を指す形: その段落は `slurm-history.sh` の表に
  入れるジョブを選ぶ規則で、ADR の時間に印が要るかを決める規則ではないので捨てた

例外の置き場と範囲として試して捨てた形:

- CLAUDE.md の「計算」の節に足し、範囲を `--timed` のフラグで決める文: 区分 `timed` のジョブは `--timed` を付けなくても
  パーティション timed で走って割り込まれないのに、割り込まれうるジョブとして添える対象に入った
- 同じ文で、範囲をパーティションで決めて /slurm-run の分け方をコピーする形: スキルの規則を言い換えてコピーしたので、`-c` の係り方、
  パーティション urgent、`partition=unknown` の扱いが原文とずれた
- 同じ文で、/slurm-run の TIME 行の規則と版の読み方を指す形: その版の読み方は、コミットしていない変更で走ったジョブの版を
  「確かめていない」とするので、例外が許す作業中の版の時間に元のコミットが残らなかった。CLAUDE.md は ADR の書き方を
  docs/adr/README.md に任せており、README の再現の要件とも食い違った

関係する ADR: なし

## 完了の条件

各点について、CLAUDE.md、docs/adr/README.md、各 ADR の凍結しない節を直すか、直さない理由を書いて閉じる。割り込みを入れる前の
ジョブの扱いと、確定した ADR に当てるかは、規則の決定が要る。
