# topic-start の cherry-pick の始め方の、レビューで残した点

## 問題

スキル topic-start の「別のブランチにしか無い issue を cherry-pick で取り込んで始める」手順（ブランチ
docs/topic-start-cherry-pick-issue）のレビュー（2 周）で、起きうるが再現を確かめていない点を残した。

- 取り込むコミットが issue 以外のファイルや、元のブランチにしか無い別の `#NNNN`・ADR の参照を含むとき、
  `docs-consistency` が止まる。参照の先を推移的にたどる指示と、コミットのファイル一覧を先に見る指示が無い
- 関係する ADR のコミットも取り込むと、このブランチの新しい ADR が 2 件になり、/git-merge の「止まる条件」の
  新しい ADR 2 件以上に当たりうる。また未レビューの proposed の ADR が、このブランチの経路で main に入る
- cherry-pick が元のコミットの `Claude-Session:` を引き継ぎ、グローバルの CLAUDE.md の担当の判定で、ブランチに
  2 つのセッションが現れる。`-x` による出どころの記録の要否
- `git log --diff-filter=A` が 0 件か複数件のとき（改名、削除と再追加）の扱い、グロブの引用
- 先にマージする側が、もう一方に取り込んだコピーがあると知る方法

関係する ADR: なし

## 完了の条件

実例（#0244 のような取り込み）で上の点が起きるかを確かめ、起きるものはスキルに書き、起きないものは閉じる。

## 経緯

- 2026-11-06: 取り込みの手順を足したブランチの /code-review の指摘のうち、再現を確かめていないものを残した
- 2026-11-08: レビューで直さなかった指摘を集めた issue は作らない決定（nixfiles の ADR-0066 の「## 変更」の 2026-11-08）に合わせて閉じた。再現のある項目は無い
