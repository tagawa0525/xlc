# issues

未解決の問題とやることを、1件1ファイルで管理する。計画（docs/plans/）には何をなぜ決めたかだけを書き、ここには
まだ決まっていないこと、分かっていないこと、これからすることを書く。決まったことは計画に移し、issue からは計画を
参照する。

## ファイル

`NNNN-short-name.md`（4桁の連番と、英語の短い名前の kebab-case）。番号は作った順に振り、使い回さない。

```markdown
---
status: open          # open | closed
labels: [lattice, shielding]
opened: 2026-10-08
closed:
---

# 題名

## 問題
何が起きているか、数値、再現の手順。

## 完了の条件
何が分かれば、何ができれば閉じるか。

## 経緯
- 2026-10-08: 起こした経緯や途中で分かったこと
```

## 運用

- 閉じるときは `status: closed` と `closed` の日付を書き、ファイルは消さずに残す。閉じる変更は、対応したブランチの
  中でコミットする
- ブランチ名とコミットの本文で番号を示す（例: ブランチ `fix/0004-frame-gap`、本文に `Refs: #0004`）
- 一覧のファイルは作らない（手で書く一覧は各ファイルとずれる）。開いている issue は
  `grep -l '^status: open$' docs/issues/[0-9]*.md` で探す
