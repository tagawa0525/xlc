# コードを変えた後に、軽い問題を今のコードで再実行して結果の変化に気付く検査が無い

## 問題

- xs、lattice、core のコードを変えたブランチが、今のコードで軽い問題（小さな格子計算と、その比較）を再実行して結果が
  変わったかを見る検査が無い。`cargo test` のうち本番のライブラリを読むテストは `#[ignore]` で、pre-commit の hook
  `verification-tables` は記録の表が比較の JSON と合うかだけを見る（確かめた内容と日付は ADR-0258 の検討した案の案 T5）
- rebase の後の付け直し（スキル dvc-relock の前半、`scripts/dvc-relock.py`）は、DVC のステージを含むブランチの rebase のときに
  しか働かず、軽いステージも自動では再実行しない（名前で指定したステージだけ。ADR-0258）
- 決まっていないこと: どの問題の組を流すか（燃料の種類と燃焼度を変えた組にするか）、いつ流すか（マージの前か、main で
  定期的にか）、上流（ライブラリ）は `dvc.lock` の出力をそのまま使うか、結果の変化をどう示すか（lock の outs の md5 の差か、
  比較の JSON の値の差か）、#0150 の小さな問題の組（新旧の実行ファイルの出力の一致を確かめる組）と同じ組にできるか

関係する ADR: ADR-0258
