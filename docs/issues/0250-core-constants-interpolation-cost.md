# core の燃焼の固有値計算の外の時間（少数群定数の内挿、ミクロ燃焼、平衡 Xe）

## 問題

core の燃焼は、固有値計算のたびに（臨界ホウ素の探索の評価と平衡 Xe の解き直しを含む）、`case::solve_with` の span `constants` の中で、テーブルの
使い方ごとに少数群定数を内挿し、ミクロ燃焼のノードには `case::node_constants` で補正を足す。この span の中は、テーブルの使い方を 1 スレッドで順に回す
（`layout.tables.iter()`）。

固有値計算を複数のスレッドで解いた（ADR-0234）後の全炉心の燃焼（examples/depletion/verification.md の「固有値計算の複数のスレッド（小さな炉心と全炉心）」の
「全炉心（Problem 9 の形）」、dd6bbbe02、Slurm 711 の timed、16 スレッド、2026-11-06）で、全体 106.2 s のうち固有値計算の外は 15.3 s で、そのうち
「少数群定数の内挿とミクロ燃焼の補正」（span `constants` の和）が 9.7 s（全体の 9.1 %）、ミクロ燃焼が 1.9 s、平衡 Xe が 1.6 s、その他が 2.1 s。span `constants` は
固有値計算と同じ 43 個で、1 個の time.busy は 188〜240 ms（`examples/depletion/p9-timing/trial-0234/core-p9.log`）。固有値計算 1 回の平均は 2.11 s（90.9 s / 43 回）
で、内挿と補正はその約 1 割になった（ADR-0234 の前の Slurm 707 では、固有値計算の外は 14.6 s で全体の 2.9 %）。

原因の候補と縮め方の候補（どれも確かめていない）:

- span `constants`: テーブルの使い方ごとの内挿と補正は互いに独立で、複数のスレッドで解ける。1 回の解の中の探索の評価と平衡 Xe の解き直しでは、
  燃焼度と履歴の変数が変わらず、ホウ素と組成だけが変わるので、内挿の軸の点と重みや、ホウ素に依らない部分を解の中で使い回せるか。span の中の
  内挿（`state::interpolate` など）と補正（`case::node_constants`）の内訳は測っていない。燃焼度の軸の 3 次の Hermite の内挿は線形の 2 倍の手間
  （ADR-0192 の帰結）で、その分も分けて測っていない
- ミクロ燃焼（ADR-0216 の帰結と「確認」の (d)）: ノードごとの燃焼の時間の内訳は測っていない
- 平衡 Xe: #0202 の「速さ」の項（Anderson の反復がすべての位置のすべての解く核種を並べる、`MicroChain::equilibrium` が燃焼行列の項をすべて作る、
  中点の最後の反復の反応率を修正子でもう一度求める）
- その他: ADR-0218 の帰結の、状態ごとの解く前の準備の時間と、#0198 の、バンクの位置が同じ状態ごとに `with_banks` で並び全体とミクロ燃焼のノードの使い方を作り直すこと（大きさは測っていない）

`examples/depletion/p9-timing/p9_timing.py` の docstring の時間の項に、崩れた文（「`eigenvalue` に入るは互いに重ならない部分で」）がある。

関係する ADR: ADR-0190、ADR-0192、ADR-0216、ADR-0218

## 完了の条件

全炉心の燃焼（Problem 9 の形）で固有値計算の外の時間の内訳（span `constants` の中の内挿と補正、ミクロ燃焼、平衡 Xe、その他）を測り、縮める形
（複数のスレッド、解の中の使い回しなど）を比べて決める。履歴は今の形とバイトで同じか、差を記録する。
