# AWS の再開で前の区間の statepoint が S3 から消える

## 問題

AWS の OpenMC の燃焼（ADR-0174 の区間 `step-<k>`）は、各ステップの始まりの輸送の statepoint `openmc_simulation_n<k>.h5`
（ピン出力の tally を持つ。1 つ 24〜38 KB）を区間のディレクトリに書き、抽出（examples/depletion/openmc_depletion_assembly.py の
`bos_points`）はそれを読んでピン出力を取り出す。ADR-0174 は「再開した VM が戻した区間より前は、`--delete` の同期で S3 から
消える」と書いており、取り出した結果（references/openmc/aws/m4-assembly、2026-10-23）に残る区間は次のとおり:

| 実行 | ステップ | 残っている区間 |
| ---- | -------- | -------------- |
| 2A   | 0〜40    | 10〜40         |
| 2F   | 0〜40    | 32〜40         |
| 2N   | 0〜40    | 25〜40         |
| 2O   | 0〜70    | 68〜70         |
| 2P   | 0〜70    | 58〜70         |

抽出をやり直す元が無いので、抽出の側の修正（#0159 の規格化。今回は比べる側の割り直しで済んだ）や新しい取り出し方
（別の tally の読み方）を、過去の実行に当て直せない。OpenMC を再実行すると 1 実行 5〜24 時間かかる。消えているのは
1 ステップ 38 KB で、70 ステップでも 3 MB にならない。

関係する ADR: ADR-0174、ADR-0168

## 完了の条件

再開した VM が前の区間を S3 から消さない形（同期の `--delete` を区間に当てない、または再開時に全区間を戻す）を決めて
直し、以後の実行で全ステップの `openmc_simulation_n<k>.h5` が取り出せること。過去の実行は再実行しない（比べる側の
割り直しで足りている）。

## 経緯
