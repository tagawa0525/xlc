# 公称の状態のテーブルを燃焼の履歴から輸送なしで作るか決める

## 問題

ADR-0196 は、燃焼の履歴の各点に `[depletion]` の `few-group`（ADR-0173）の少数群定数を持てるようにした。ただし、帰結の項のとおり、
p2 の本番の入力（examples/depletion/p2）に `few-group` を書くか、公称の状態のテーブルを履歴から輸送なしで作るかは、
ADR-0196 で決めていない（入力を変えると DVC のステージが changed になるため）。

効果: 燃焼度の点の選び方の検討（#0170、ADR-0192、ADR-0199）で、公称の 1 状態のテーブル
（examples/depletion/branches/branch-<集合体>-all.toml。41〜71 回の輸送、15〜30 分の見込み。2F の入力は 41 点）を省ける。
履歴の点が公称の状態の少数群定数をすでに持つため。

費用: p2 の入力に `few-group` を足すと DVC の deps が変わり、p2 の履歴（7 本、約 6 時間）の再実行が要る。次に避けられない再実行
（#0172 の 2M、ライブラリの変更）に合わせて入れる案を、ユーザーが 2026-10-24 に「今は直さない」と決めた。
15〜30 分と約 6 時間は親のセッションの見積もりで、この issue では確かめていない。

関係する ADR: なし

従う決定: ADR-0196（履歴の `few-group`。この決定を残した項）、ADR-0187（履歴から分岐のテーブルを作る）

## 完了の条件

次のいずれか。

- 次の p2 の再実行（#0172 など）に `few-group` を入れ、公称の状態のテーブルを履歴から作る入力が動き、輸送で作ったテーブルと
  少数群定数が一致することを検証の記録に書く。決定は ADR にする
- 入れないと決め、理由（省ける時間と再実行の費用の比較）を ADR か wontfix の resolution に書く

## 経緯

- 2026-10-24: p2 の再実行のあと、ADR-0196 が決めずに残した 2 点を issue にした
