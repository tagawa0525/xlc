# 出力を変えない整理でも、行の位置が変わると実行ファイルが変わり段階が古くなる

## 問題

DVC の計算の段階は、ビルドした実行ファイルを deps にする（ADR-0159）。実行ファイルのバイトが変わらない変更（テストの
変更など）では段階は古くならないが、本番のファイルの行の位置を変える変更は、計算を変えなくても実行ファイルを変える。
0268e5aa で crates/lattice/src/moc.rs の先頭にコメントの行を 1 つ足すと、lattice の実行ファイルの md5 が変わった
（ADR-0159 の「確認」の (c)、2026-10-14）。そのため、ADR-0144 のリファクタリング（関数の分割など）は、出力がビット一致
しても、通る段階をすべて古くする。

原因の候補は、`tracing` のイベントとパニックの位置（`file!()`、`line!()`、`#[track_caller]`）が、ソースのパスと行番号を
実行ファイルに入れること。実行ファイルは文字列 `crates/lattice/src/moc.rs` を含むが、変わったバイトが行番号かは確かめて
いない。

関係する ADR: [ADR-0159](../adr/0159-depend-stages-on-built-binaries.md)

## 完了の条件

次のどちらかを決める。

- 行の位置を実行ファイルに入れない（stable の Rust で位置の情報を外す手段があるか、`tracing` の位置の情報を外せるか）。
  外すと、パニックとログから位置が分からなくなる
- 行の位置だけが違う実行ファイルを同じとみなす手段を持たない（今のまま）と決め、ADR-0144 のブランチは段階を古いまま残すか
  再実行する（ADR-0130）

## 経緯

- 2026-10-14: ADR-0159 の確認で、行の位置で実行ファイルが変わることが分かった
