# CRAM の時間を本物の燃焼チェーンで測り、記号的な分解を材料の間で再利用するかを決める

## 問題

`xlc_depletion::deplete`（ADR-0161）は、呼び出しごとに疎な LU の記号的な分解を行い、極ごとに数値の分解を行う。時間は
測っていない。ADR-0161 の疎と密の比較は、燃焼行列の非零の数と埋め込みの見積もりによる。同じチェーンの材料は非零の位置が同じなので、
記号的な分解を材料の間で使い回せるが、それが時間のどれほどかは分からない。計画（docs/plans/m4-depletion.md）は、CRAM の時間を
輸送に比べて小さいと見込む（測っていない）。

関係する ADR: なし

## 完了の条件

- 縮約したチェーン（計画の「進め方」2）の燃焼行列で、`deplete` の 1 回の時間（次数 16 と 48）と、そのうちの記号的な分解の割合を
  測り、格子計算の燃焼の 1 本（領域 × 2 回 × ステップ）の CRAM の時間を見積もってある
- 再利用するかを決め、再利用するなら API（記号的な分解を持つ型）を足してある。`DepletionMatrix` が記号的な分解を持つ形
  （同じ行列の予測子と修正子で再利用する）と、極ごとの数値の分解の記憶（faer の `NumericLu` と作業領域）を再利用する形も比べる

## 経緯

- 2026-10-14: ADR-0161 の実装で、時間を測らずに疎な LU を選んだ
- 2026-11-19: 閉じた。格子計算の燃焼の履歴の `seconds` で、CRAM48（全核種の 3,820 核種）はピンセルで 1 回の輸送あたり 0.04 秒以下
  （1 領域）、2A の最初の 10 点（輸送 21 回、39 領域）で 1.75 秒（全体 505.1 秒の 0.35%）と測られた（examples/depletion/verification.md の
  「格子計算の燃焼」の「時間の内訳」と、「集合体の燃焼」の「時間」の xlc 968a7bcf、2026-10-23、Slurm 492）。記号的な分解がその全部でも 0.35% なので、再利用する
  API は足さない。縮約したチェーンでの次数 16 の時間は、CRAM48 が既定（ADR-0173）なので測らない
