# record_provenance.py の .dvc の読み方の残り

## 問題

`examples/record_provenance.py`（ADR-0176 と ADR-0222 の帰結のツール）の `.dvc` の md5 の履歴（`parse_dvc`、`dvc_history`、
`show_dvc`）と、それを使うスキル verification-record の .dvc の項に残る点:

ツール

- `dvc_history` は `.dvc` を触ったコミットの版をすべて `git show` して `parse_dvc` で読んでから履歴をさかのぼる。`.dvc` を消した
  コミットより前に読めない版があると、さかのぼりが止まるはずの所より前の版で全体が `FAILED` になり、版の数だけ `git show` を
  実行する
- `git()` は終了コードが 0 でないときに理由を問わず None を返し、`dvc_history` は `git show` のどんな失敗も `.dvc` を消した
  コミットと同じに扱って、履歴を黙って打ち切る（どの失敗で起きるかは確かめていない）。いちばん新しいコミットの `git show` が
  失敗すると、`dvc_history` と `locked_since` は `uncommitted` と出し、原因を取り違える
- `show_dvc` は `uncommitted` と `unknown` でも終了コード 0 を返す（dvc.lock のステージの `show` も、`locked_since` が
  `unknown` か `uncommitted` を返しても `status` を 0 のままにする）
- 履歴は `git log -- <パス>` の新しい順に並べて同じ md5 が続く間を 1 行にまとめるので、マージの両側が `.dvc` を変えると、
  2 本のブランチのコミットが日付の順に混じり、md5 を入れたコミットを取り違えうる（`locked_since` も同じ）
- `dvc_history` と `locked_since` が、`git log` と `git show <コミット>:./<名前>` で版をさかのぼる同じ処理を別々に持つ
- `uncommitted` のとき、作業ツリーの md5 の行の下にコミット済みの履歴を出す（`locked_since` は `uncommitted` のときコミットを
  出さない）
- `uncommitted` の判定は outs の (パス, md5) だけを比べ、docstring の「作業ツリーの `.dvc` の outs が HEAD と違えば今の md5 の
  行に `uncommitted`」より狭い
- md5 を先頭 8 桁で出すので、ディレクトリの出力の `.dir` の印が出ない（dvc.lock のステージの出力も同じ）。スキルの Y の行の
  確認も先頭 8 桁だけを比べることになり、9 桁目より後だけが違う Y を見分けない
- `git log -- <名前>` は名前を pathspec として読むので、`[`、`*`、`?` を含む名前は別のファイルに当たる（`--literal-pathspecs` が
  候補。xlc の生成物の名前には無い。`git show <コミット>:./<名前>` は木の中のパスをそのまま引くので当たらない）。先頭の `:` と
  `\` も pathspec として読む
- `parse_dvc` と `parse_stage` は手で書いた YAML の読み手で、dvc の書き方ごとに扱いが要る。PyYAML（default の devShell にある）の
  `yaml.safe_load` で読む案は、ADR-0176 の背景の判断の軸の保守の項と合わないので、採るなら ADR-0176 を見直す。今の読み手で dvc が
  書かない形の扱い:
  - `path:` の次の行に引用符で囲んだパスがあると、引用符ごと出す（同じ行の引用符はエラーにする）
  - `-` だけの行（キーを次の行から書く項目）を区切りと認めず、続く行を前の項目に上書きして out を黙って落とす
  - `outs:` の中の 1 桁目の注釈の行で読むのをやめ、`path:` の値の後ろの注釈（`# …`）を剥がさない
  - 改行が `\r\n` の `.dvc` を、原因を示さずに `.dvc has no outs` と報告する
- ディレクトリ（`.dvc` の設定のディレクトリなど）を渡すと `IsADirectoryError` の traceback で止まり、残りの引数を読まない
- テストが無い形: 空の `path:` の後に何行も続く形、`path:` の次の行の引用符、`.dvc` でない引数を混ぜたとき、`show_dvc` の
  ファイルが無いとき。テストの `contextlib` と `io` の import が関数の中に 3 か所ある

スキル verification-record の .dvc の項

- 記録の「コミット X で出した md5 Y」の X を裏づける手段が無い。スキルのとおり「md5 が前の版と同じまま作り直すと、`dvc add` は
  `.dvc` を変えず、行は前の版を入れたコミットを指す」ので、X と行のコミットの祖先の関係はどの形でも誤った X を通す。Y が
  どれかの行にあれば確認を通るので、古い md5 を新しい X と書いた記録も通る。候補: Slurm のジョブのコメントの `commit=<hash>`
  （~/.claude/scripts/slurm-run.sh。nixfiles の PR #627 以後のジョブだけ）。ただし投げた時点の HEAD（`-dirty` が付きうる）で、
  出力の md5 を持たず、`dvc add` はジョブの外で行うので、それだけでは X で Y を作ったことを裏づけない
- X が何を指すか（同じ節の 4 の計算の欄に並ぶ、ステージごとの HEAD と分岐点のどれか）を書いていない。`dvc add` の生成物の
  計算の欄の例は、examples/depletion/verification.md の、制御棒を途中まで入れて抜く燃焼（2A）の節の計算の欄にある
- Y の行が無いときの原因の候補（「作り直した後の `dvc add` の漏れと、記録の Y の誤りの 2 つ」）は、`.dvc` の削除と追加のし直し、
  out のパスの変更、`git show` の失敗（上の `git()` の点）で履歴が途中で切れたときを入れていない。そのときも書かずに止まるので、
  正しい Y の記録を書けない
- 「生成物の中身が `.dvc` と合うかは見ない」はツールの範囲を書いた文だが、`dvc add` の漏れ（置き場の生成物の md5 が `.dvc` と
  違う）を見分ける確認を止めるようにも読める
- 「rebase の後は前後を決められないので使わない」の前後を使う手順が、今の項に無い
- `unknown` / `uncommitted` の扱いは dvc.lock の項で決め、.dvc の項は Y の行の確認から「下の」で項の終わりを、項の終わりから
  「上と同じく」で dvc.lock の項を指す（2 段に指す）

関係する ADR: なし

## 完了の条件

上の点を直すか、直さない理由を書いて閉じる。

## 検討して捨てた形

- 記録の X を、`.dvc` の履歴の Y の行のコミットとの祖先の関係（`git merge-base --is-ancestor`）で確かめる手順: 記録の X と Y
  からは md5 が前の版から変わったかを決められないので、どの向きでも誤った X を通すか正しい記録を落とす。片方向（行のコミットが X
  か X の子孫）は、md5 が同じまま作り直した正しい記録でも 1 で終わる。両方向は、生成物をコミット W で作り、W の子孫 C で `dvc add`
  した記録に、C より後の実行していない X を書いても通る（C が X の祖先なので）ので捨てた
- 記録の X の書き方の例として examples/depletion/verification.md の 151〜153 行を指すこと: その行の `depletion.msgpack` には実行
  したコミットが無く（確かめていないと書いてある）、dvc.lock のステージの出力で `dvc add` の生成物でないので、例から外した
- md5 が前の版と同じまま作り直したとき、記録に Y を入れた行のコミットと、X で作り直した事実の出どころとして X のジョブのログの
  両方を書く形: ジョブのログには実行したコミットが入らず（slurm-run.sh はコミットをジョブのコメントにだけ付ける）、同じ節の 4 の
  計算の欄の X と別の、第 3 のコミットを記録に足すので捨てた
