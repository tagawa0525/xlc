## 完了の条件

整理の範囲と方法を決めて実行する。候補（確かめていない）:

- ADR の「決定と理由」に、実装の詳細（検査の規則、キーの名前、関数の名前）を書かない書き方を docs/adr/README.md に足し、
  今の ADR の詳細はコードとテストを指す形にする（xlc の CLAUDE.md の「コードには How」）。docs/adr/README.md の「運用」の
  「今ある ADR を新しい形に書き直すことはしない」（nixfiles の ADR-0067）と食い違うので、その規則を変える決定が先に要る。凍結した部分を変えるので、
  「## 変更」で一度に直すか、新しい ADR で決めるかを先に決める
- 検証の記録の古い本文を消して書き直す（#0224。ADR-0117）
- 閉じた issue の経緯の長い本文を短くするか（git に残る）
- 根本の原因の対処（1 つ目の候補の書き方を What と How で分けたもの。docs/adr/README.md の「運用」の規則を変える決定が先に要るのは同じ）: ADR の「決定と理由」には What（入力の形、出力の形、規則）だけを書き、How（検査の順、コードの中身、テーブルの
  検査の規則）は書かない。実装の詳細はコードとテストに任せ、ADR からは「実装は crates/… のテスト」のように指すだけにする。
