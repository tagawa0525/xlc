# 分岐のテーブルの状態をまたぐ並列の要否を次の波の見積もりで決める

## 問題

分岐のテーブルは、1 状態を 1 回の輸送（16 スレッド）で解き、状態は順に続ける。16 スレッドの並列の効率は、2A の 1 輸送で
ピンの UFG が 1 スレッドの 11.7 倍（効率 73%）、MOC のスイープが 5.6 倍（35%）で、直列の部分は 1 輸送 2.75 秒
（examples/vera/verification.md の「格子計算の並列の効率（2A）」とその「直列の部分（#0163）」。xlc 20dfd3d73 時点の記録。数値を出したコミットと
日付は記録の本文にある）。

2 状態を 8 スレッドずつ同時に解けば、効率の低い部分が減り、処理量は 1.2〜1.3 倍になる見込み（親のセッションの見積もりで、測っていない）。
費用は、メモリが 2 倍になることと、チェックポイント（ADR-0196 の `checkpoint::solve_states`）が状態の順序を前提にしていて、同時に解くと
再開の扱いが増えることである。

ユーザーが 2026-10-24 に「今は直さない」と決めた。

関係する ADR: なし

従う決定: ADR-0196（状態ごとのチェックポイント）、ADR-0187（履歴から分岐のテーブルを作る）。関連する issue: #0163

## 完了の条件

次の波（9 種のテーブル。docs/plans/m4-depletion.md の「進め方」の 7 の core の燃焼に要るもの。種類の数は確かめていない）の時間の見積もりを、
新しい bin で出し直す。その結果から、状態をまたぐ並列を作るか、作らない（wontfix: 理由と見積もり）かを決める。作るなら ADR で
チェックポイントとの関係とメモリを決めたうえで、2 状態同時の処理量を 1 回測って記録に書く。
