# M4 燃焼

下書き。この計画は新しい決定を加えず、決めることは「ADR で決める」として項目だけを挙げる。

## 目的

M3 までで、零出力（HZP）の新しい燃料の炉心を、格子計算の少数群定数のテーブルと 3D NEM で解ける。M4 では、燃料と
可燃性毒物の燃焼を、格子計算（ピンごとの燃焼と、燃焼度の軸を持つ分岐のテーブル）と炉心計算（ノードごとのミクロ燃焼と
サイクルの追跡）に入れ、VERA の Problem 9（WBN1 サイクル 1 の燃焼）の臨界ホウ素濃度の実測値と比べられるところまで
進める。格子計算の燃焼は、同じ核データで作った OpenMC の燃焼の参照解と比べ、[ADR-0032](../adr/0032-target-lattice-accuracy.md) の目標（燃焼を通じて
k ±100 pcm、ピン出力 rms 0.2%）で確かめる。

格子計算の燃焼と分岐のテーブル、OpenMC の燃焼の参照解は、M4 の計算の中で最も CPU の時間を食う（「CPU と記憶の
見積もり」）。

### 熱水力のフィードバック

[ADR-0029](../adr/0029-defer-thermal-hydraulic-feedback.md) は熱水力のフィードバックを初期のマイルストーンで扱わず、燃焼後の結果を実機と比べる段階で入れるとした。Problem 6〜9
はどれも HFP で、仕様書は熱水力のフィードバックを求める。Problem 9 の臨界ホウ素濃度を実測と比べるには、出力の軸方向の
分布と燃料の温度が燃焼の分布に効くので、少なくとも 1 次元の流路の減速材の密度と、燃料の実効温度のモデルが要る見込み
（確かめていない）。Problem 10 の比べる状態は HZP なので、熱水力は要らない（燃焼の履歴を通じてだけ効く）。

- ADR-0029 の決定は「燃焼後の結果を実機データと比べる段階で導入する」で、帰結と docs/plans/architecture.md は熱水力を含む
  比較（BEAVRS）を M4 の後に置く。ADR で決める: Problem 9 の実測との比較をその段階とみて M4 で熱水力を入れるか、
  入れるならモデルの粒度（集合体ごとの
  1 次元の流路か、ピンごとか）と、燃料の温度のモデル（熱伝導度の燃焼度依存、ギャップのコンダクタンス）。仕様書は熱水力の
  物性を与えない（Problem 6 の MATERIAL PROPERTIES）

### 範囲に入れないもの

- 動特性と冷却計算そのもの（M4 の後。[docs/plans/architecture.md](architecture.md)）。ただし、それらが使うデータは M4 の分岐のテーブルに入れる
  （[ADR-0033](../adr/0033-store-kinetics-and-cooling-data-in-m4-tables.md)）
- BEAVRS との比較（M4 の後）
- 3D の全炉心の OpenMC（M3 と同じく作らない）

### 核データ

- 燃焼鎖の元: ENDF/B-VIII.0 の decay（3,821 の評価）、nfy（31 の核分裂する核種）、中性子のデータ（557 の評価）は flake で固定
  してある（[ADR-0124](../adr/0124-pin-reference-assets-with-nix.md)、docs/environment.md）。鎖の形式、収率のエネルギー依存、準安定状態への分岐の出所は
  [ADR-0164](../adr/0164-build-full-chain-from-endf.md) と [ADR-0166](../adr/0166-build-chain-in-its-own-crate.md) で決めた。準安定状態への分岐は、MF8〜10 の状態ごとのチャネルの群の断面積を xs が作る（「進め方」3）。
  ADR で決める: 核分裂の Q 値と捕獲のエネルギー（出力の規格化。「進め方」5）
- 輸送に使う縮約した鎖: 方式は [ADR-0165](../adr/0165-reduce-chain-by-contribution-and-folding.md)（proposed）。閾値と実装、先行事例（OpenMC が配る PWR 向けの鎖、
  CASMO、Polaris、MPACT の鎖の大きさ）の出典は #0116
- xs が処理できる核種の制約: ENDF/B-VIII.0 の中性子のデータ（557 の評価。中性子そのものを除く 556 が燃焼鎖の核種）を
  `crates/xs/examples/survey_neutrons.rs` で調べると（MF2 のすべての範囲の見出しと、0 K の再構成、MF1 MT452、MF4〜6 の読み込み、
  分離共鳴の上端、565 K の非分離共鳴の自己遮蔽まで。多群の処理は走らせない。c0d7b4dd、2026-10-14）、546 が読め、11 が読めない。
  最初の範囲の形式は MLBW 399、Reich-Moore 49、R-matrix limited 10、非分離共鳴だけ 31、共鳴のデータなし 68。分離共鳴の
  MLBW で散乱半径がエネルギーの表で与えられる 52 評価（NRO = 1。I-133、Nd-149 など）は、[ADR-0167](../adr/0167-evaluate-mlbw-energy-dependent-radius.md) で読めるようにした。
  読めない理由は下の表。MF6 の角度のデータは入れない（[ADR-0082](../adr/0082-leave-out-mf6-angular-data.md)）、運動学のしきい値から反応を始める（[ADR-0100](../adr/0100-move-tables-to-kinematic-thresholds.md)）。
  ADR で決める: 読めない形式が残る核種の扱い（実装か、多群だけか、鎖の輸送から外すか。基準は吸収への寄与）

| 理由                                                                                                         | 評価 | 核種                                  | 扱い         |
| ------------------------------------------------------------------------------------------------------------ | ---- | ------------------------------------- | ------------ |
| 非分離共鳴の θ が J, K の表の下限（10^-3）より小さい（565 K）                                                | 5    | Ne-22、Nd-150、Sm-154、Gd-160、Au-197 | #0119        |

- ライブラリの大きさ: examples/vera/dvc.lock の `xs` の段階の出力 vera.msgpack は 55 核種で 123 MB（ポイントワイズの断面積と、
  複数の温度を含む）。同じ割合なら 300 核種で約 0.7 GB（見積もり）。核分裂生成物の多くは自己遮蔽が小さいので、
  ポイントワイズを持たせる核種を絞れる見込み。ADR で決める: ポイントワイズの断面積と σ0 の表を持たせる核種の基準
  （#0045 の「自己遮蔽が効く核種に絞る」案と同じ線引き）
- UFG の範囲（4 eV）より下の共鳴: Pu-242 の 2.67 eV（MOX のピンセルで捕獲が +11%。Pu-240 の 1.06 eV は
  合っている。#0001）と、Gd-155、Gd-157 の熱中性子の共鳴は、燃焼で量が変わる。#0001（milestone: M3）は、Pu が燃焼で生まれる M4 の前に実装して MOX のピンセルで検証するとしている
- 燃焼した燃料の UFG の点の数: 新しい燃料の 2B で 342,106 点。燃焼した燃料ではアクチニドと核分裂生成物の共鳴で点が
  増え、自己遮蔽の時間が点の数に比例して増える見込み（#0045。測っていない）
- Gd の自己遮蔽: Gd 入りの燃料は全断面積が大きく、円筒の衝突確率の弦の求積の精度が落ちうる。接する弦に向けて細かくする
  求積（ブランチ fix/0044-graded-chords）は、Gd を扱う段階で影響を測ってから入れると決めてある（#0044）。光学的に厚い領域では k がトラック間隔に対して不規則に
  動く（ADR-0111）ので、Gd の燃料ではトラックの間隔の収束も測り直す
- IFBA の ZrB2 の層: 厚さ 10 μm、密度 3.85 g/cc、B-10 は 50%（仕様書の表 11）。ADR で決める: 層を独立した領域として
  MOC で解くか（トラックの間隔 0.03 cm（[ADR-0111](../adr/0111-use-30-azimuths-for-vera-assemblies.md)）より 30 倍薄く、トラックから推定した体積の誤差が大きい。
  体積の扱いは #0041 と関係する）、ギャップや燃料の外の
  リングに均すか。B-10 の燃焼で層が薄くなる扱い
- ENDF/B-VIII.0 の中性子のデータがない核種（全核種の鎖の約 3,800 のうち、中性子のデータは 557）の断面積: ADR-0033 は、
  その出所（放射化断面積のライブラリなど）と、状態と履歴への依存の扱いを M4 の計画で決めるとした。ADR で決める
- 冷却材の B-10 の割合の燃焼（#0036）: Problem 9 の実測値は B-10 の割合が分からない（仕様書は BOC で 19.78 at% と置く）。サイクルの中で一定とするか、
  燃焼で減らすか（#0036 の「core が追う」）を ADR で決める。
  また、テーブルは B-10 の割合を 1 つ持ち、ケースの値が違えばエラーにする（ADR-0097）。Problem 9 の 19.78 at% を与えるには、
  #0036 の換算か、19.78 at% でテーブルを作ることが、Problem 9 の計算（「進め方」9）の前に要る

### 格子計算の燃焼

- 燃焼の領域: ADR で決める: ピンごと、燃料のリングごとに燃焼させるか（Gd 入りの燃料は外側から燃えるので、リングを細かく
  する。数は Gd で測って決める）、対称性（[ADR-0112](../adr/0112-use-verified-symmetry-in-moc-and-shielding.md)）を燃焼の領域にも使うか
- 時間の進め方: ADR-0025 は予測子・修正子法とだけ決めている。ADR で決める: 方式（CE/LI、CE/CM、LE/QI など）、燃焼の
  ステップの大きさ（初めの Xe と Sm の平衡、Gd の燃え尽きる 10〜20 GWd/t と、IFBA の B-10 が燃え尽きる
  初めの 10〜15 GWd/t 程度（見積もり。OpenMC の燃焼で確かめる）までの細かいステップ）、出力の規格化（一定の
  出力密度か、一定の中性子束か）、修正子のときに自己遮蔽を解き直すか
- 自己遮蔽の解き直し: 組成が変わるので、燃焼の点ごとに自己遮蔽を解き直す必要がある。2B の 1 状態の時間の 94% が自己遮蔽
  （「CPU と記憶の見積もり（xlc）」）なので、燃焼の時間はほぼ自己遮蔽の回数で決まる。ADR で決める: 解き直す頻度（毎ステップか、数ステップごとか）と、
  その誤差の測り方
- 燃焼度の格子点と分岐のテーブル: ADR-0085 の軸（ホウ素濃度、減速材の温度と密度、燃料の温度、制御棒、支持格子）に燃焼度の
  軸を足す。分岐は燃焼点の組成から始まるので、独立したケースの集まりではない。ADR で決める: テーブルの構造（ADR-0097 の
  直積を燃焼度の点ごとに作るか、燃焼度の点の多くで軸を減らすか、PMAXS のような偏微分の木か。ADR-0097 の「検討した案」）、
  燃焼度の格子点、ファイルの形式（MessagePack のままか HDF5 か）、lattice の 1 回の実行の中で燃焼と分岐を行うか
  （CASMO と同じ）、燃焼点の状態をファイルで渡すか（docs/plans/architecture.md が M4 の計画で決めるとしたもの）
- 履歴: ADR-0035 の履歴の変数と履歴の分岐（条件を変えた燃焼）。ADR-0035 は変数を挙げていない（候補は減速材の密度、
  ホウ素濃度、制御棒の挿入の履歴）。ADR で決める: 履歴の変数と、履歴の分岐の数と条件。Pyrex を抜いた集合体（Problem 10 のサイクル 2 で、サイクル 1 から残る
  集合体）の扱い（毒物を抜いた分岐を燃焼度ごとに持つか、抜いた後を燃焼し直すか）
- ピン出力の再構成の形状関数と ADF の燃焼度依存（[ADR-0096](../adr/0096-reconstruct-pin-power-analytically.md)）: テーブルの軸に燃焼度を足すだけで済むかを、燃焼度の傾きの
  ある集合体（装荷替えで回したもの）で確かめる

### 炉心の燃焼

- ノードごとの燃焼度と主要な核種の数密度（ADR-0035）、集合体ごとの状態（ADR-0036）。ADR で決める: ミクロ燃焼で追う
  核種、ノードの中の燃焼度の分布（ピン出力の再構成からピンごとの燃焼度を持つか）、時間の進め方（炉心でも予測子・修正子に
  するか）
- サイクルの追跡: 表 P9-2 の 30 状態（出力、入口の温度、バンク D の位置）を与える入力。表の値はステップの間の平均で、
  印 * の付いた 5 状態（2、3、28、29、30）だけは端点の値（仕様書の表の注）なので、平均として使うなら直す。
  停止の間の崩壊（表 P9-3、最長 18 日）と、サイクルの間の停止（Problem 10、30 日）の崩壊だけのステップ。EOC の restart
  （Problem 9 が求める）。ADR-0105 のサイクルとケースの入力に、時間の軸と運転の履歴を足す形を ADR で決める
- 装荷替え: ADR-0036 は装荷替えを実機と比べる段階で入れるとしたが、Problem 10 に要る。ADR-0105 の台帳と装荷図は ID と
  回転を持つので、サイクル 2 の装荷図（仕様書の付録 K）を書けば、状態を ID で引き継げる見込み。ADR で決める:
  restart のファイルの形と、取り出した集合体、新しい集合体、Pyrex を抜く集合体の書き方
- 臨界ホウ素濃度の探索: M3 で入れた（[ADR-0145](../adr/0145-search-critical-boron-by-illinois-in-input-bracket.md)）。燃焼のステップごとに探索する
- Xe と Sm: Problem 7 は平衡 Xe、Problem 8 は過渡の Xe、Problem 9 は燃焼の中で追う。ADR で決める: 平衡 Xe をノードの
  出力から直接求めるか、ミクロ燃焼の中で追うか
- 熱水力: 「範囲」の熱水力の ADR による

## 検証

### 参照解と比べる量

- 格子計算の燃焼: 同じ核データ（ENDF/B-VIII.0）から手元で作った OpenMC の燃焼（openmc.deplete）と比べる（コード同士の
  検証。[ADR-0032](../adr/0032-target-lattice-accuracy.md)）。k∞、ピン出力、主要な核種の数密度を燃焼度ごとに。対象の候補は、毒物のない 3.1% の集合体、
  2F（Pyrex 24）、2M（IFBA 128）、2N（IFBA と WABA）、2O と 2P（Gd）と、履歴を変えた燃焼（減速材の密度、制御棒の挿入）。
  VERA の仕様書に燃焼の参照解はない
- 燃焼鎖: xlc の鎖と OpenMC が ENDF から作る鎖（openmc.deplete.Chain.from_endf）を、同じ ENDF から作ったものとして核種、
  崩壊定数、分岐比、収率で比べる。CRAM は解析解のある小さな鎖と、OpenMC の燃焼のソルバに同じ反応率を与えたものと比べる
- 燃焼点からの分岐: OpenMC の燃焼の途中の組成（燃焼の結果から書き出せる）で、分岐の状態の k∞ を直接解いて比べる
- HZP の可燃性毒物: 1E、2L〜2P を KENO-VI の値（ENDF/B-VII.0、参考）と、同じ核データの OpenMC と比べる（M3 の 2E〜2K と同じ）
- 炉心: Problem 9 の臨界ホウ素濃度を実測値（表 P9-4）と比べる（妥当性確認。熱水力のモデル、炉心の燃焼、核データの誤差を
  分けられない）。Problem 6、7 の参照解は仕様書にない。VERA-CS（MPACT）などの公開の結果は、調べてから使うかを決める
  （Serpent などのほかのコードの公開値も同じ）

### OpenMC の燃焼の参照解の物理コア時間（見積もり）

実測の出典: 2D の集合体の OpenMC（1 世代 100 万粒子・400 世代、最初の 100 世代を捨てる、16 スレッド、AMD Ryzen 9 9950X の
16 コア）の計算時間は、2E〜2K で 32.4〜37.0 分、2F で 34.2 分、2Q で 50.4 分（examples/vera/verification.md の「参照解」。
2F は 408cf6ef、2026-10-10）。16 スレッドは物理コア 16 なので、2F の 1 回の輸送は 34.2 分 × 16 = 約 9.1 物理コア時間で、
1 世代あたり平均 5.1 秒（捨てる世代と数える世代の平均。3A では捨てる世代が数える世代の約半分の時間だった。
examples/vera/verification.md の Problem 3）。

これは新しい燃料（燃料の核種 5: U-234、U-235、U-236、U-238、O-16）の時間である。燃焼した燃料は数百の核種を持ち、燃料の中の衝突ごとの巨視的断面積の
計算がそれに比例して重くなるので、1 回の輸送は遅くなる。また openmc.deplete は、燃焼する材料（ピンかリング）ごとに鎖の核種の反応率を tally するので、材料の数 × 核種の数に
比例する時間も加わる。これらを合わせた倍率 s は測っていない。2〜4 倍と見込む（見積もり）。最初に、
燃焼した組成と燃焼の tally を入れたピンごとの材料の短い走行で s と、核種を足したライブラリの記憶量を測る（「進め方」1）。

1 本の集合体を 60 GWd/t まで燃やす（1 ステップの輸送の回数は、予測子・修正子の多くの方式で 2。最後の点を足す）:

| 燃焼                       | ステップ | 輸送の回数 | 物理コア時間（s = 1） | s = 2〜4     |
| -------------------------- | -------- | ---------- | --------------------- | ------------ |
| 毒物なし、Pyrex、WABA      | 30〜50   | 61〜101    | 550〜920              | 1,100〜3,700 |
| Gd、IFBA（細かいステップ） | 60〜80   | 121〜161   | 1,100〜1,500          | 2,200〜5,900 |

候補の一式（上の「参照解と比べる量」の 6 本と、履歴を変えた燃焼 2 本。Gd と IFBA の 4 本を 70 ステップ、ほかの 4 本を 40 ステップで、燃焼点からの
分岐を、履歴を変えた 2 本を除く 6 本 × 5 燃焼点 × 6 状態 = 180 回）は、輸送が 4 × 81 + 4 × 141 + 180 = 1,068 回で、約 9,700 物理コア時間（s = 1）、
s = 2〜4 で約 19,000〜39,000 物理コア時間（見積もり。分岐の 180 回は燃焼の tally が要らないので、s のうち組成の分だけで
済み、この幅より少し小さい）。1 世代の粒子と世代の数（上の見積もりは M2、M3 の 2D の参照解の条件の 100 万 × 400。examples/vera/verification.md の
「参照解」）を減らせば比例して減る。燃焼の途中の点で、ピン出力の統計誤差が ADR-0032 の目標（rms 0.2%）に比べて十分小さい数は、
ADR で決める。外部の計算機（クラウド。別に選ぶ）のコアは 9950X（Zen 5）と速さが違うので、選んだ計算機で短い走行を測って
見積もり直す。CRAM の時間（材料の数 × 鎖の大きさ）は、輸送に比べて小さいと見込む（測っていない）。

参照のライブラリ（NJOY で燃焼鎖の核種を燃料の温度などで処理し、HDF5 にする）は、M2、M3 の参照解のライブラリ（examples/vera/openmc-library.toml。ADR-0130 の段階）に
ない核種が数百あり、作るのに Slurm の重い計算が要る。時間は測っていない（「進め方」1 で作って測る）。

### 精度の目標

格子計算は ADR-0032（燃焼を通じて k ±100 pcm、許容 ±150 pcm、ピン出力 rms 0.2%）。M2、M3 の新しい燃料で目標に届いて
いない分（#0005）は、燃焼でも土台に残る。

## CPU と記憶の見積もり（xlc）

実測の出典: VERA 2B の 1 状態は 136 秒（自己遮蔽 128 秒、MOC 7.4 秒。1/8 の対称性、[ADR-0111](../adr/0111-use-30-azimuths-for-vera-assemblies.md) の方位角 30・間隔 0.03 cm、16 スレッド、
排他のジョブ。1f4fcaaf、2026-10-12、examples/vera/verification.md の「OpenMC との比較」）。最大のメモリは 1/8 で 5.8 GB（64e069de）、
対称性なしで 12.8 GB（b1a4f8f2。同じ記録の「対称性」の節。この節の 1/8 の 1 状態は 1 分 59 秒で、上の 136 秒より前のコードの測定。1f4fcaaf のメモリは測っていない）。以下は新しい燃料のこの時間を使った見積もりで、1/8 の対称性を燃焼の領域にも使えることを仮定する（使えなければ
1 状態は増える。同じ古いコードの「対称性」の節の 1/8 の 1 分 59 秒と対称性なしの 12 分 40 秒の比は約 6.4 で、ほかの計算と
重なった測定なので目安）。燃焼した燃料で UFG の
点が増える倍率 f（#0045）は掛けていない。自己遮蔽が時間の 94% なので、全体はほぼ f 倍になる。

- 集合体 1 種の燃焼: 40 ステップ × 2 回 + 最後の点 = 81 回 × 136 秒 = 約 3.1 時間（16 物理コアで約 49 物理コア時間。OpenMC の表と同じ
  数え方）。Gd で 70 ステップ（141 回）なら約 5.3 時間
- 集合体 1 種の分岐のテーブル: M3 の 27 状態（examples/branches。ホウ素、減速材、燃料の温度の 3 点ずつ）に、ADR-0085 の
  離散の軸（制御棒の有無、支持格子の有無）を掛けた 108 状態を、30 の燃焼点（40 ステップの燃焼の 41 点のうち分岐を取る点。見積もりの仮定）のすべてで解くと（離散の軸を一部の燃焼点だけで
  分岐するなら減る。反射体のテーブルはどちらの軸も持たない。ADR-0097） 3,240 回で、約 122 時間（約 1,960 物理
  コア時間）。直積のまま燃焼度の軸を足すと、燃焼そのものの 40 倍になる。M3 の温度の格子点は HZP の狭い範囲（550〜580 K。
  ADR-0097）で、HFP（Problem 6〜9）は燃料の温度と減速材の密度の範囲が広い見込みなので、軸の点が増えれば
  さらに増える（すべての燃焼点で直積を取るときの見積もり）。分岐のテーブルの離散化（方位角と間隔）も ADR で決める。examples/branches の入力（[ADR-0077](../adr/0077-keep-vera-discretization.md) の方位角 32・
  間隔 0.05 cm）の 1 状態 256 秒（e4aa625、2026-10-09、examples/branches/verification.md。32 スレッド）は、その後の自己遮蔽と MOC を速くする前のもので、スレッド数と
  離散化も違うので、136 秒とそのまま比べられない
- Problem 9: 図 9（仕様書の 1.12 節）の装荷は、濃縮度と Pyrex の本数の組で 10 種前後（数え方は制御棒の位置の集合体の
  扱いで変わる）。10 種で、燃焼と分岐で約 20,000 物理コア時間以上、履歴の分岐を足すとその数割増し（見積もり）。Problem 10 の
  新しい燃料（IFBA の本数と WABA の組、ブランケット、IFBA のない端の部分）で 6〜7 種が加わる（4 本と 8 本の WABA、48 本の IFBA の配置が 1/8 対称かは確かめていない。対称でなければ
  上の仮定が外れる）
- 炉心の燃焼: Problem 9 の 30 状態と停止の崩壊。ノードは 1/4 炉心で数千〜数万、ミクロ燃焼の鎖は小さいので、格子計算に
  比べて小さいと見込む（core の全炉心の時間は測っていない）
- 記憶: 分岐のテーブルは、集合体 1 種で 2 群定数、ピン出力の形状（289 ピン）、追う核種の微視的断面積、ADR-0033 の全核種の
  1 群の微視的断面積を持つ。全核種の鎖（約 3,800 核種。中性子のデータのない核種の断面積の出所は未決）× 5 反応を倍精度で、
  基準の燃焼の 41 点だけに持てば約 6.2 MB、3,240 の分岐の状態すべてに持てば約 500 MB（見積もり）。ADR-0033 はこれを
  冷却計算の燃焼のやり直しに使うとしているので、どの状態で持つかを ADR で決める。ADR-0033 の遅発中性子のデータ
  （ν、族ごとの割合と崩壊定数、スペクトル）と群速度の逆数は、状態ごとに数十の数で、これより小さい。格子計算の 1 状態の記憶は、燃焼した
  燃料の UFG の配列が核種と点の数に比例して増える（#0045 は新しい燃料で 1 ピン約 70 MB、16 本同時で約 1.1 GB と見積もる）

この見積もりでは、格子計算の分岐のテーブルが OpenMC の参照解と同じ桁か、それ以上の CPU を食う。減らす手は、自己遮蔽の速さ（#0039）、
燃焼した燃料の UFG の点（#0045）、分岐のテーブルの構造（燃焼度の点ごとに軸を減らす）、自己遮蔽を解き直す頻度で、
どれも ADR で決める。

## 進め方

依存の順: 核データ → 格子計算の燃焼 → 分岐のテーブル → 炉心の燃焼 → Problem 9、10。項目ごとに状態（済・作業中・未着手）
と、済んだ部分のマージのコミットを書く。

1. OpenMC の燃焼の時間を測る: 燃焼鎖の核種の参照のライブラリを NJOY で作り（その時間も測る）、燃焼した組成（OpenMC が
   ENDF から作る鎖で短く燃やしたもの）の短い走行で、1 世代の時間の
   倍率 s とライブラリの記憶量を測り、参照解の物理コア時間を見積もり直す。外部の計算機を選ぶ検討の入力にする — 未着手
2. 燃焼鎖: xs が decay と nfy から全核種の鎖を作り（ADR-0034）、OpenMC の鎖と比べる。縮約した鎖の方式を ADR で決める
   — 全核種の鎖は済（feat/depletion-chain-type と feat/depletion-chain のマージ。ADR-0164、ADR-0166。記録は
   examples/depletion/verification.md の「燃焼鎖」）。縮約の方式は ADR-0165（proposed）で決め、実装と閾値は #0116
3. 燃焼鎖の核種の断面積: xs の制約（NRO、分離共鳴の形式）の扱いと、ポイントワイズを持たせる核種の基準を決め、ライブラリを
   作る。鎖の反応のチャネル（MF8〜10 の状態ごと。ADR-0164）の群の断面積も作る。M3 の #0001（4 eV より下の共鳴。MOX のピンセルで検証）を先に済ませる — 未着手
4. CRAM と燃焼のソルバ（共通のクレート）と、解析解・OpenMC のソルバとの比較 — 済（feat/cram-depletion-solver のマージ。ADR-0161、
   ADR-0162。記録は examples/depletion/verification.md）
5. 格子計算の燃焼: ピンセル、毒物のない集合体、Pyrex、IFBA と WABA、Gd の順に、OpenMC の燃焼と比べる。#0045（UFG の点）と
   #0044（Gd の求積）をここで測る。1E、2L〜2P の HZP もここ — 未着手
6. 燃焼度の軸を持つ分岐のテーブル（構造と形式の ADR）と、履歴の分岐。軸の範囲は熱水力の ADR（HFP の燃料の温度と減速材の
   密度）で決まるので、本番のテーブルはその後に作る — 未着手
7. core の燃焼: ミクロ燃焼、サイクルの入力、崩壊のステップ、restart、臨界ホウ素の探索の繰り返し — 未着手
8. 熱水力（M4 で入れると ADR で決めたら）と Problem 6、7 — 未着手
9. Problem 9 の燃焼と臨界ホウ素濃度の比較（その前に、BOC の B-10 19.78 at% を扱えるようにする。#0036 の換算か、その値で
   テーブルを作る）、Problem 10 の装荷替え — 未着手

M3 の残り（Problem 4、5 の 3D の炉心、制御棒の部分挿入、2G の AIC の差、UFG の残る偏り #0005、4 eV より下の共鳴 #0001）との関係:

- 2、3、5 は xs と lattice の作業、4 は共通のクレート（あとで core も使う）、1 は OpenMC と NJOY の計算で、M3 の残りの core の作業（Problem 4、5）と別の worktree で並べて書ける。ただし 1、3、5、6 の
  重い計算（OpenMC、NJOY、ライブラリの作り直し、xlc の集合体の燃焼と分岐のテーブル）は、M3 の Problem 3〜5 の参照解と同じ
  Slurm の待ち行列に 1 本ずつ並ぶので、計算は並ばない。OpenMC を外部の計算機で流しても、xlc の分岐のテーブル（同じ桁の
  物理コア時間）は残る
- #0005（燃料の断面積で説明できない k の差）と 2G の AIC の差は、燃焼のすべての点の土台になるので、5 の OpenMC との比較を
  記録に書く前に、原因の候補を分けておく。分けられないときに燃焼の比較をどう記録するかは ADR で決める
- 7 は M3 の core（装荷図と軸方向の層、テーブルの内挿、臨界ホウ素の探索）の上に作るので、Problem 5 の後にする
