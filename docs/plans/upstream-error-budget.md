# 本番の結果の誤差を上流から見積もる順

数値は書かず、記録と issue を指す。「進め方の決まり」は親の案をユーザーが承認したもの（2026-11-19）で、同じ日に、循環する条件と満たせない条件を親が外した（目安の決め方は
ユーザーが親に任せた。2026-11-19）。ほかの決定は ADR を指す。

## 目的

本番の形の結果（Problem 9 に向けた燃焼のテーブルと炉心計算、VERA の検証の数値）の誤差を、核データから炉心計算まで上流から
順に見積もり、大きい順に片付ける。

起こした理由: open の issue が約 200 件たまった。ユーザーは、issue はブランチを 1 つのトピックに保つための置き場で、放置してよい
という意図は無いとし、棚卸しを求めた（ユーザー 2026-11-19 の発言の要約）。親の評価では、issue が「書けば済み」の出口になり、
片付ける作業が計画に入っていなかった。同じ日に、本番の結果が拠る測られていない前提を #0293 に一覧にした。この計画は、#0293 の
26 項目と、2026-11-19 の issue の棚卸しで結果に効くとした issue を 1 つの順に並べる。

## 範囲

- 入れるもの: #0293 の 26 項目と「調べ直していない 3 項目」、結果に効く（本番の形の結果の正しさに関わる）open の issue、
  レビューの残りの issue のうち結果に効く指摘
- 入れないもの: 速度、ツール、文書、整理の issue。複数の燃料で測り終えた前提（#0293 の「確かめてあるもの」）
- 2026-11-19 の棚卸しの時点で表に無い open の issue は、棚卸しの分類で結果に効かないとしたもの。一件ずつ確かめたのは閉じた
  issue だけで、表に無い open の issue に結果に効くものが残りうる。見つけたら表に足す（同じ日のレビューが挙げた #0159 は足し、
  #0160 は測った k の差が 0.1 pcm より小さく、#0015 は当たるファイルが無くエラーで止まるので、足していない）。その後に開く issue は、
  開くときに表に足すかを決める

## 進め方の決まり

目的は、本番の作り直し（ライブラリ、燃焼の履歴、テーブル、参照解）を 1 回で済ませること。作り直しの前に、「作り直しの前」の列が
「要」の項目を小さな計算（ピンセル、1 燃焼度点、比べるための変種のライブラリ）で見積もり、目安を超えるものをまとめて修正してから
作り直す。見積もるための計算は、ここでいう作り直しに入れない。

- 目安は、項目ごとに k の 5 pcm（ADR-0200、ADR-0215 の 1 項あたりの目安）、全体は、核データとライブラリから自己遮蔽と輸送までの段の項目の和を ADR-0032 の目標（同じ核データの
  モンテカルロの参照に対する k とピン出力）に対して見る。テーブルから後の段の全体の目安は、#0293-26（ADR-0032 の目標が臨界ホウ素
  濃度で何 ppm に当たるか）を導くまで無いので、その段は項目ごとの目安で進める。測った値が目安の中なら、
  親が「測った（目安の中）」として進める。目安を超える誤差を修正せずに受け入れるときだけ、値を添えてユーザーに尋ねる
- 「要」の項目のうち、本番の形の計算でしか測れないもの（#0293-4 の 3.1% 以外の燃料の燃焼の履歴、#0293-5 の本番の条件の参照）は、
  作り直しの前に見積もる対象から除き、作り直しの中で測る（#0293-4 の履歴は xlc のライブラリで作るので、作り直しの前に流すと
  作り直しの後に流し直しになる。#0293-5 の OpenMC の参照は xlc と同じ核種を輸送する（#0292）ので、輸送する核種が決まる作り直しで
  作り直す。目安を超えたときは、作り直しが 2 回になる）
- 「作り直しの前」の列: 「要」は、修正すると作り直しが要るもの。空欄は、修正しても作り直さないもの（core の中や、別のテーブルで
  済むもの）。「迷う」は、原因の側によって要るかが変わるもので、着手のときに「要」か空欄に決めて書き換える。ユーザーが順を決めた
  項目は、この列にその判断を引き、その順に従う（#0005 と #0133 の格子の k の偏りは、Problem 9 の臨界ホウ素濃度の比較の後。
  ユーザー 2026-11-06）

状態は、測った、許容と認めた（目安を超える誤差をユーザーが受け入れたもの）、測定中（今の担当のブランチがある）、未測定、のどれか。
一部の燃料や集合体だけで測ったものは、#0293 の最小の測定を済ませていれば「測った（測った範囲）」と書き、範囲を「大きさ」の列で指す。

## 順

段の順は、核データとライブラリ → チェーン → 格子計算の燃焼 → 自己遮蔽と輸送 → テーブル → 炉心計算 → 熱水力 → 検証。
「#0293-N」は #0293 の「問題」の項目 N で、大きさはその項目の「根拠」か「大きさ」の行（どちらにも値の出典が無ければ分からない。この
決め方は #0293 の冒頭）、最小の測定は「確かめる最小の測定」の行にある。その行の無い項目は「決めていない」と書き、決めることが最初の作業。
「扱う issue」は、#0293 の項目の「扱う issue」の行に、棚卸しで同じ前提に当たるとした issue を足したもの（#0293 の行は変えていない）。

## 作り直しのときに入れる xs と lattice の修正

xs と lattice の実行ファイルを変えると、それを呼ぶ重いステージ（ライブラリ、燃焼、テーブル）が changed になる（ADR-0255）。結果を変えない次の
修正は、本番の作り直しでそれらの実行ファイルがどのみち変わる作業の中で入れる。

- lattice の文: crates/lattice/src/history.rs のモジュール、`ValueShape`、`history_branches` の説明は燃焼の領域の照合を（物質、組の代表のセル、体積）と
  書くが、コードは ADR-0226 の `region_mismatch`（組のセルの位置と MOC の領域の数も比べる）を使う。`nominal_state` の前に足した関数が
  `derivative_nuclides` の説明の行を `nominal_state` の説明の先頭に残し、`derivative_nuclides` に説明が無い。解く燃焼点のコメントの「間引いたかに
  よらず」は前の挙動と比べた書き方。値の燃焼点（`rod-burnup`）だけが燃焼点を間引いて基準条件が無いときのエラーの文が `off-nominal-burnup` を名指しする
- スレッドの数の既定（物理コアの数を許された論理 CPU の数で抑えたもの）が、xs の `parallel::cores` と core の `use_threads` に複製され、`RAYON_NUM_THREADS`
  の読み取りが lattice の `use_allowed_cpus` と core に複製されている（lattice の既定は SMT を含む論理 CPU の数で、規則が違う。ADR-0214）。共通の
  クレートに移す（`xlc-numeric` に足すと使わない実行ファイルのバイトも変わった。ADR-0232 の案 S2、#0241）。lattice の既定は変えない
