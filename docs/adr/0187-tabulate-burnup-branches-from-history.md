# ADR-0187: 燃焼度の軸を持つ分岐のテーブルは、公称の燃焼の履歴の組成を固定した瞬時の分岐の直積で作り、core は燃焼度を線形に内挿する

## 背景

格子計算の燃焼（[ADR-0173](0173-deplete-lattice-pins-by-ce-cm.md)）は、公称の 1 つの状態で燃焼させ、燃焼点ごとの k∞、燃焼の領域ごとの全核種の数密度、ピン出力
（[ADR-0181](0181-write-depletion-pin-powers-into-history.md)）を燃焼の履歴（`xlc-depletion-history`）に書く。分岐（`[branches]`）と燃焼は同じ入力に書けない。core の分岐の
テーブル（`xlc-table`。[ADR-0097](0097-tabulate-branches-on-a-full-grid.md)）は、ホウ素濃度、減速材の温度（と密度）、燃料の温度の格子点の直積と、制御棒の離散の軸を持ち、燃焼度の
軸を持たない。[ADR-0026](0026-output-two-group-tables-from-lattice.md) は燃焼度ごとの 2 群定数と、各燃焼点からの分岐のテーブルを lattice が出すとし、[ADR-0085](0085-branch-on-core-states.md) と ADR-0097 は
燃焼度の軸を持つテーブルの構造と形式（HDF5 への移行を含む。[ADR-0011](0011-write-data-files-in-messagepack.md)）を M4 で設計し直すとした。

docs/plans/m4-depletion.md の「進め方」6 で、core の燃焼（「進め方」7: ミクロ燃焼 [ADR-0035](0035-track-history-by-micro-depletion.md)、集合体ごとの状態 [ADR-0036](0036-keep-core-state-per-assembly.md)）の
前提になる、燃焼度で引けるテーブルの作り方、構造、形式、燃焼度の内挿、入力と段階を決める。軸の範囲と格子点（HFP の燃料の温度と減速材の
密度）は熱水力の ADR で決まるので、ここでは決めない。

前提:

- 計画の「CPU と記憶の見積もり（xlc）」: 集合体 1 種の分岐のテーブルは、M3 の 27 状態に制御棒と支持格子の離散の軸を掛けた 108 状態を
  30 の燃焼点で解くと 3,240 回で、約 122 時間（16 物理コア）。1 種の燃焼そのもの（輸送 81 回）の約 40 倍
- 2A の 1 回の輸送は約 72 秒（16 スレッド、排他。計画の「流すだけの手順」の 1 点の試行、2026-10-15）

判断の軸:

- 炉心のノードは、テーブルを作った燃焼の条件と違う状態（ホウ素、温度、制御棒）を瞬時に取る。分岐はその瞬時の変化を表すこと
  （履歴の違いは ADR-0035 のミクロ燃焼と履歴の補正が扱う）
- 格子計算の回数（上の見積もりで、M4 の xlc の時間の大部分）
- ADR-0097 の内挿の性質（格子点で誤差がなく、交差の項を落とさない）を保ち、ファイルと core の実装を作り直さずに足せること
- 重い履歴の段階を、分岐の入力の変更で再実行しないこと

## 検討した案

分岐の作り方:

- 案 B1: 公称の燃焼の履歴の燃焼点の組成（燃焼の領域ごとの数密度）を固定し、分岐の状態（燃料の温度、減速材の温度と密度、ホウ素濃度、
  制御棒）で輸送して少数群定数を作る。分岐の状態では燃焼させない（採用）。燃焼点からの瞬時の分岐で、ADR-0097 の「制御棒の分岐は
  基準の燃焼の組成から瞬時に変えた状態として計算する」と同じ定義。分岐の数だけ輸送を足すが、燃焼は 1 回
- 案 B2: 分岐の状態ごとに燃焼させる（状態ごとの燃焼の履歴の燃焼点の値を表にする）: 表の値は「その状態で燃焼させ続けた」組成の
  定数で、炉心のノードが状態を瞬時に変えたときの定数（組成は今までの履歴のまま）と違う。温度やホウ素の係数に履歴の差が混ざる。
  燃焼の輸送（燃焼点ごとに 2 回）を状態の数だけ繰り返すので、輸送は B1 の約 2 倍になる
- 案 B3: 履歴の効果を別の軸（履歴の変数。減速材の密度の履歴など）に持ち、瞬時の分岐を持たない: 瞬時の状態の効果を表せない。履歴の
  変数は ADR-0035 で、瞬時の分岐に加える補正と決めてある。条件を変えた燃焼（履歴の分岐。examples/depletion/p2 の 2A-density、
  2A-rods）は、それぞれの履歴から B1 で同じ形のテーブルを作れる。それを core がどう組み合わせるかは「進め方」7 で決める

テーブルの構造:

- 案 S1: 燃焼度を ADR-0097 の直積の軸に足し、どの燃焼度の点でも同じ分岐の格子を解く（採用）。燃焼度の点は、履歴の燃焼点から
  入力で選ぶ（履歴のすべての点でなくてよい）
- 案 S2: 燃焼度の点ごとに分岐の格子を変える（多くの燃焼度の点で軸を減らす）: 回数は減るが、直積でなくなり、燃焼度の点の間で
  格子の違う点を混ぜる内挿が要る。減らした点の誤差を測ってから決めるもので、本番の格子点（熱水力の ADR の後）より前には選べない
- 案 S3: 基準の状態と偏微分の木（PMAXS）: ADR-0097 で採らなかった理由（木にない組の交差の項が入らない）がそのまま残る。
  examples/branches/verification.md（6867728、2026-10-09）では、減速材温度係数がホウ素濃度で −1.08 から +15.46 pcm/K まで変わる

形式:

- 案 F1: MessagePack の `xlc-table`（ADR-0011）に燃焼度の軸 `burnup` を足す（採用）
- 案 F2: HDF5（ADR-0011 の帰結が M4 で検討するとしたもの）: 大きな表の一部だけを読めるが、core は炉心のすべてのノードの燃焼度を
  引くので、テーブルの全体を読む。C のライブラリ（libhdf5）への依存が加わる。大きさは、1 状態が 2 群の定数と 17×17 のピンの形状関数
  （2 群）で約 6 KB、3,240 状態で約 20 MB（見積もり）で、ミクロの断面積（下）を足しても全体を記憶に置ける
- 案 F3: 燃焼度の点ごとに別のファイル: core が燃焼度の点の数だけファイルを結ぶことになり、点の並びの検査がファイルの外に出る

燃焼度の内挿:

- 案 I1: 燃焼度 (MWd/kg) について、隣の 2 点で線形（採用）。ADR-0097 の多重線形の 1 つの軸として扱う
- 案 I2: 3 点のラグランジュの 2 次や、スプライン: 燃焼度の点の間の曲がり（初めの Xe と Sm の平衡、Pu の蓄積）を少ない点で拾えるが、
  Gd や IFBA の燃え尽きのような折れ曲がりの近くで振動しうる。多重線形のほかの軸と次数が揃わない。線形の誤差は燃焼度の点を
  増やせば減り、点を増やしても分岐の輸送が増えるだけで、燃焼はやり直さない

入力と段階:

- 案 P1: 燃焼の履歴を読み、選んだ燃焼点で分岐だけを解く lattice の入力（`[history]` の節）にし、履歴の段階と別の段階にする（採用）
- 案 P2: 燃焼の入力（`[depletion]`）に分岐の軸を足し、1 回の実行で燃焼と分岐を行う（CASMO と同じ）: 分岐の軸や燃焼度の点を
  変えるたびに燃焼をやり直す。1 回の実行が燃焼の約 40 倍になり、途中で止まると全体をやり直す
- 案 P3: 副コマンド（`lattice branch <履歴> <入力>`）: lattice は副コマンドを持たず、入力の節で足りる

## 決定と理由

### 分岐の作り方（案 B1）

公称の燃焼の履歴の各燃焼点の組成を固定し、分岐の状態で輸送して少数群定数を作る。分岐の状態では燃焼させない。炉心のノードが状態を
瞬時に変えたときの定数を表し、ADR-0097 の制御棒の分岐の定義と揃う。

- 燃焼の領域（ADR-0173 の、自己遮蔽の対称操作のセルの組と物質の対）ごとに、履歴の数密度を `<物質>@<セル>` の物質（燃焼の輸送と
  同じ名前）として解く。温度は分岐の状態の、その物質の温度（燃料の温度の軸）
- 輸送する核種は履歴の `transportable`（燃焼の温度でライブラリにある核種）とし、数密度が 0 の核種も含める（燃焼の輸送と同じ
  組成なので、公称の状態の分岐は履歴の点の輸送と同じ問題になる）。どれかの核種が分岐の温度のデータを持たなければエラーにする
  （ADR-0173 の案 N2 と同じく、近い温度で代用しない）。負の数密度は燃焼の輸送と同じく 0 として輸送に渡す
- 分岐の入力は、履歴を作った入力と同じ格子であること。履歴の燃焼の領域（物質、セル、体積）と、入力から求めた燃焼の領域が厳密に
  一致し、入力の燃焼させた物質の組成が、履歴の燃焼度 0 の点の数密度と厳密に一致し、入力のライブラリと燃焼させた物質の温度から
  求め直した輸送する核種の集合が履歴の `transportable` と同じことを確かめる（違えばエラー）。燃焼させない物質（被覆管、減速材）は
  履歴に記録がないので確かめられず、入力が履歴の入力と同じであることに頼る。MOC の領域の
  番号は入力から求めるので、案内管の中身を変えた格子（制御棒の分岐）でも、燃料のセルが同じなら同じ履歴を読める
- 履歴の分岐（条件を変えた燃焼）は、それぞれの履歴から同じ方法でテーブルを作る。組み合わせ方は「進め方」7

### 構造と形式（案 S1、F1）

`xlc-table` に連続の軸 `burnup`（`points` は燃焼度 (MWd/kg、初めの重金属)。0 以上で増える）を足す。テーブルを作るときは、燃焼度を
最初の軸（いちばん遅く変わる）に置き、各燃焼度の点の中は ADR-0097 の軸の直積の順のまま。ほかの項目と読み込みの厳密さ（状態の数が
軸の点の数の積、群境界や f* の印が状態の間で同じ）は ADR-0097 のとおり。MessagePack のまま（ADR-0011）で、HDF5 に移さない。

- 燃焼度の点は、分岐の入力で履歴の燃焼点から選ぶ（履歴の燃焼度と厳密に等しい値。ない値はエラー）。点の数と位置（燃焼の
  ステップより粗くてよい）は、本番のテーブルを作るときに内挿の誤差を測って決める
- 制御棒の軸は、M3 と同じく、制御棒を入れた格子の入力で同じ履歴を読んで別に作り、軸を合わせてまとめる
  （examples/core/rod_table.py。制御棒の軸は最後）
- ADR-0035 のミクロ燃焼の核種と ADR-0033 のデータの置き場（形式の置き場だけを決め、持たせる核種と反応の選び方は「進め方」7 で
  決める）:
  - テーブルに核種の名前の列 `nuclides` を 1 つ持つ（基本は履歴の `transportable`）
  - 燃焼度の点ごとに、格子で均質化した数密度（燃焼の領域の体積で重みをつけた平均）を 1 組持つ。組成は燃焼度の点で決まり、分岐の
    状態によらないので、状態ごとに繰り返さない
  - 状態ごとに、核種ごと反応ごとの少数群の微視的断面積（格子で均質化した反応率 / (均質化した数密度 × 均質化した中性子束)）と、
    ADR-0033 の遅発中性子のデータと群速度の逆数を持つ。少数群定数の項目と同じく、状態の格子で多重線形に内挿する
  - ADR-0033 の冷却計算のための全核種の 1 群の微視的断面積は、燃焼度の点ごとに公称の状態（履歴の輸送）の値だけを持つ。全核種
    （約 3,800）× 5 反応を 3,240 の状態すべてに持つと約 500 MB（計画の「記憶」の見積もり）で、燃焼の履歴の点だけなら約 6 MB

### 燃焼度の内挿（案 I1）

core は燃焼度を、ADR-0097 の多重線形のほかの軸と同じく、隣の 2 点で線形に内挿する。範囲の外はエラーにし、外挿しない。点が 1 つの
燃焼度の軸は、その値でだけ使える。

- 状態が 0 でない燃焼度を与えるとき、核分裂のあるテーブル（どれかの状態の νΣf が正）は燃焼度の軸を持つこと。燃焼度 0 は、軸のない
  新しい燃料のテーブルの状態そのものなので、そのまま使う。核分裂のないテーブル（反射体、
  軸方向の反射体）は燃焼しないので、燃焼度の軸を持たずにどの燃焼度でも使える
- 燃焼度の軸を持つテーブルを、燃焼度を与えない状態で使うのはエラー
- 燃焼度は、ケースの状態（`[state.<名前>]` の `burnup`）が、炉心のすべての集合体に同じ値を与える。集合体ごとの燃焼度
  （ADR-0036）は「進め方」7 で、この値をノードごとの値に置き換える

### 入力と段階（案 P1）

lattice の入力に `[history]` を足す:

```toml
[history]
file = "../p2/lattice-2A.msgpack"   # 燃焼の履歴（ADR-0173、ADR-0181）
burnup = [0, 10, 20, 40]            # 分岐を解く燃焼点 (MWd/kg)。履歴の燃焼度から選ぶ
```

`[branches]` と、ファイルに書く `few-group` と組み、燃焼度の軸を持つテーブルを書く。チェーンは読まない（燃焼させない）。
`[depletion]`、`pin-powers`、`medium`、混ぜた物質、媒質とは使えず、燃焼の輸送と同じく自己遮蔽を求める。DVC では、燃焼の履歴の
段階と別の段階にし、履歴の出力を deps にする。分岐の入力（軸の格子点、燃焼度の点）を変えても履歴の段階は再実行しない。
lattice の実行ファイルが変われば、どちらの段階も changed になる（どちらもその実行ファイルの出力なので）。

## 帰結

- 格子計算の回数は、燃焼度の点の数 × ADR-0097 の状態の数（制御棒の値を含む）。計画の見積もり（30 点 × 108 状態で約 122 時間）は
  S1 の直積の値で、減らす手は燃焼度の点を履歴の点より粗くすることと、本番の格子点を決めた後の案 S2
- 燃焼度の点の間の線形の内挿の誤差は、2A で点の間隔 10 MWd/kg に +129 pcm、20 MWd/kg に +763 pcm（「確認」）。本番の燃焼度の点は、
  この誤差を測って細かくする（履歴の点はどれでも選べる）
- ADR-0011 の帰結の HDF5 への移行は行わない
- 確認の 2A のテーブルは段階にしていない（履歴の段階を deps にすると、実行ファイルの変わったブランチでは履歴を再実行するため。
  examples/depletion/verification.md）。本番のテーブルの段階は、熱水力の ADR の後に作る
- ミクロの断面積、均質化した数密度、ADR-0033 のデータは、形式の置き場を決めただけで、まだ書かない（#0153）
- core の燃焼度はケースの状態の一様な値で、集合体ごとの燃焼度は「進め方」7
