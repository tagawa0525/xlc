# ADR-0240: 燃焼させる物質の温度が複数のとき、輸送する核種はすべての燃焼の領域の温度でデータのある核種の 1 つの集合にする

## 背景

格子計算の燃焼は、輸送する核種を [ADR-0173](0173-deplete-lattice-pins-by-ce-cm.md) の案 N1（チェーンの核種のうち、ライブラリが
すべての燃焼の領域の温度そのもので持つもの。ほかは崩壊と生成だけを追い、輸送のたびに warn で示す）で決める。N1 は温度が 1 つの
ピンセルで決めたもので、[ADR-0179](0179-deplete-absorbers-with-their-shielded-cross-sections.md) は吸収体を燃焼させるときに、燃焼させる
物質の温度が複数のときの集合を決めず、温度が複数なら止めた（#0139）。

Problem 9 の本番の燃焼度のテーブルの公称の状態（ブランチ feat/production-burnup-table-grid の案）は燃料 900 K、減速材 580 K で、
吸収体（Pyrex など）は減速材の温度に置くので、燃料と吸収体の温度が違う。吸収体を燃焼させる集合体の履歴は、この決定まで走らない。

前提:

- p2 のライブラリ（examples/depletion/p2/xs.toml、main 6db48b8b8）は、H-1 を除く 89 核種がどれも 565、600 K を持ち、H-1 は S(α,β) の
  550、573.6、600 K を持つ。ブランチ feat/production-burnup-table-grid（3819d4838）の版は、H-1 を除く 89 核種がどれも同じ 13 の温度
  （560〜1350 K。900 K と 580 K を含む）を持ち、H-1 は 550、573.6、600、623.6 K を持つ。どちらのライブラリも、H-1 を除けば核種ごとの
  温度の一覧が同じ
- 燃焼の履歴は輸送する核種の並びを 1 つ（`History::transportable`）持つ。分岐（crates/lattice/src/history.rs）は、その並びを燃焼の
  領域の物質に使い、少数群の微視的断面積の核種をその中の番号で引き、輸送する核種がそれぞれの燃焼させた物質の分岐の温度で
  データを持つことを確かめる（近い温度で代用しない。ADR-0173 の案 N2 を採らない）
- OpenMC 0.15.2 の燃焼（references/openmc の `openmc/deplete/openmc_operator.py`、`coupled_operator.py`）は、断面積のある核種
  （`nuclides_with_data`。温度によらない cross_sections.xml の一覧）の 1 つの集合を、すべての燃焼する物質の組成（`_update_materials`）と
  反応率の tally の核種（`_get_reaction_nuclides`）に使う。参照解（examples/depletion/openmc_depletion.py の `TimedOperator`）は、
  その集合を燃料の温度のデータのある核種に絞り、xlc と同じ集合にする。集合体の参照解はすべての物質を 1 つの温度に置く
  （examples/depletion/openmc_depletion_assembly.py の `build`）

判断の軸:

- 正確さ: 輸送できる核種を落とさない。データのない温度で近い温度を代用しない（黙った代用を足さない）
- 履歴、分岐、少数群の微視的断面積と OpenMC の参照解が、同じ核種の集合で比べられること
- 変える範囲: 履歴の形式と、それを読む分岐、自己遮蔽の履歴の照合

## 検討した案

- 案 T1: すべての燃焼の領域の温度でデータのある核種の共通部分（ADR-0173 の N1 の文言どおり）の 1 つの集合（採用）。履歴の
  `transportable`、分岐の燃焼の領域の物質、微視的断面積の並びは 1 つのまま。OpenMC の燃焼と同じく、すべての燃焼する物質に
  1 つの集合を使う。短所: ある燃焼の温度のデータがない核種は、データのある温度の領域（燃料など）でも崩壊と生成だけになる
  （輸送のたびに warn で示す）
- 案 T2: 燃焼の領域の温度ごとに、その温度のデータのある核種の集合: ライブラリの温度の一覧が核種で揃わないとき、T1 より多くの
  核種を輸送する。物質ごとに輸送する核種と数密度の並びが変わるので、履歴の形式（`transportable` を領域ごとに）、分岐の物質、
  微視的断面積の核種の番号、自己遮蔽の履歴の照合を変える。OpenMC の参照解を同じ集合にするには、`_update_materials` と
  `_get_reaction_nuclides` を物質ごとの集合に変える。T2 でも、データのない温度の領域ではその核種は崩壊だけで、正しく輸送する
  には T1 と同じくライブラリにその温度を足す
- 案 T3: 燃焼の温度ごとの集合が食い違えば（ある燃焼の温度でデータがあり、別の燃焼の温度でデータのない核種があれば）エラーで
  止める: T1 と T2 が違う入力を受けない。燃焼させる物質に現れない核種でも止まる。main の p2 のライブラリで燃料を 565 K、吸収体を
  600 K に置けば、H-1（600 K を持ち 565 K を持たない）で止まる。H-1 の温度は S(α,β) の温度で決まり、燃焼の温度に合わせられない

## 決定と理由

- 燃焼させる物質の温度が複数のとき、輸送する核種は案 T1（すべての燃焼の領域の温度でデータのある核種の 1 つの集合）にする。
  温度が複数でも止めない
- 理由: 前提の 2 つのライブラリは H-1 を除いて核種ごとの温度の一覧が同じなので、ライブラリにある温度の組なら、T1 と T2 は H-1 の
  ほかで同じ集合を輸送し、正確さは変わらない（H-1 は燃焼させる物質の中に反応と崩壊でわずかにできるだけ。ADR-0173 の N1）。T2 が
  T1 より多く輸送するのは、ライブラリの温度が核種で揃わないときだけで、そのときも T2 の領域の一部は崩壊だけになり、修正方法は
  どちらもライブラリに温度を足すこと。T1 はそれを warn で示す。T2 は同じ正確さのまま履歴の形式と分岐を変え、OpenMC の参照解の
  集合とも構造が違う。T3 は燃焼に効かない H-1 で止まる

### 帰結

- 吸収体を減速材の温度に置き、燃料と違う温度で燃焼させる履歴が走る。ライブラリが燃料と吸収体の両方の温度で持たない核種は、
  燃料でも輸送しない（warn の `decay only: no library data at the temperature of the depletion regions`）。ライブラリを作るときは、
  燃焼させるすべての物質の温度を、輸送する核種に持たせる
- 分岐は今のまま、輸送する核種がそれぞれの燃焼させた物質の分岐の温度でデータを持つことを求める（history.rs）
- 物質ごとの温度で燃焼させる OpenMC の参照解は作っていない。作るときは `TimedOperator` の集合を、すべての燃焼する物質の温度の
  データのある核種に絞る

### 確認

- crates/lattice/src/depletion/tests.rs の `absorbers_at_another_temperature_deplete_with_the_fuel`（燃料 600 K、吸収体 580 K の
  履歴が進み、輸送する核種が両方の温度のデータのある核種）、`nuclides_without_data_at_every_depletion_temperature_only_decay`
  （燃料の温度だけのデータを持つ Xe-135 は燃料でも輸送せず、吸収体の Xe-135 は崩壊だけで減る）
- crates/lattice/src/history/tests.rs の `nominal_branches_of_absorbers_at_another_temperature_reproduce_the_history_points`
  （その履歴からの分岐の燃焼の領域は燃焼させた物質の温度で、公称の状態が履歴の点の k を再現する）
