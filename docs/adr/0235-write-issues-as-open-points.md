# ADR-0235: issue の「問題」には今の未解決の点だけを書き、経緯は日付ごとに短く、捨てた形は節に残し、数値は出典を指す

## 背景

issue（docs/issues/）は未解決の問題とやることを書く場所である（docs/issues/README.md）。書き方は ADR-0117 の決定と理由の
「ADR と issue」の項が「経緯の記録なので今の規則のまま。…issue の「経緯」は日付ごとに足していく」と決め、README のテンプレートは
「問題」「完了の条件」「経緯」の 3 つの節だけを持っていた。レビューの周で直さない指摘（/git-merge の「直す指摘の基準」の
non-blocking）は 1 件の issue にまとめるので、周を重ねるブランチでは、残す issue に周ごとの書き足しが積もる。

2026-11-07 にマージした 3 本のブランチでは、担当の 3 周と記録の周の後の例外の周（/git-merge の「3 周目で blocking を直したら」の
例外の項）が、10 周、7 周、4 周に伸びた（マージ ced59c6c7、ce08a31cb、dd5941eed の本文の Impact）。
残した issue は #0248、#0254、#0258 で、その間の issue の書き方は次のとおり（各 issue のコミットの履歴。
`git log --oneline -- docs/issues/<番号>-*.md`）:

- 周ごとに指摘を足すコミットが続いた（件名に周を書いたコミットが #0248 で 22 件中 11 件、#0254 で 15 件中 3 件、#0258 で 8 件中
  2 件）。#0258 の「問題」は今も「2 周目（2026-11-07）で、直さずに残した指摘:」「記録の周の後の例外の周（2026-11-07）で、
  直さずに残した指摘:」の見出しで分かれる
- 書き足した本文が次の周の (c)（本文が引いた先の一次情報と食い違う）になった。直した指摘の再現の行に、#0248 に引き継いだ
  事実の誤り 4 件と「」の引用の食い違い（ced59c6c7）、#0254 の割り込みの例の誤りと #0253 の事実（ce08a31cb）、#0245 が比 0.01 の
  値として書いた範囲と #0242 の値の出典の抜け（dd5941eed）がある。#0258 は、#0245 の項が進めたことを経緯にだけ書き、項の本文が
  決める前の書き方のまま残ると書く
- ほかの文書からコピーした数値が周ごとに食い違った。#0258 の例外の周の項は、BOC の粗メッシュの反復の数と全炉心の時間を
  ADR-0232、#0242、#0244、#0245、verification.md にコピーしており、版と順の書き方が周ごとに食い違ったと書く

親のセッションは、途中で #0248 と #0254 を、「問題」を未解決の点の一覧だけにし、経緯を日付ごとに 1〜2 行にし、捨てた形を節に
残し、数値をコピーせず出典を指す形に組み直させた（#0248 の 6c3842379、#0254 の 5516afd59）。文書の修正方法の判断は、ユーザーが
親に任せていた（ced59c6c7 の本文の Impact。ユーザー 2026-11-07 の判断の要約）。この ADR は、その形を issue の書き方として決める。

判断の軸:

- issue を開いた人が、今残っている点とその再現だけを、周の経緯を読み分けずに読めること
- 試して捨てた形と、捨てた理由を引けること（グローバルの CLAUDE.md の「設計の記録」の「実装の途中で試して捨てた方式
  （レビューで作り直す前の版を含む）は ADR か issue に、何を試し、なぜ捨てたか（測った値や反例）を書く。コミットの本文だけに
  置かない」）
- 同じ値が複数の文書にあって、直すたびに片方だけが直ることを避けること

## 検討した案

- 案 A: 今の形（ADR-0117 のとおり、周ごとに「問題」の項と「経緯」を足していく）。経緯が issue の中で追えるが、上の 3 本では
  直った項と残る項が周の見出しで混じり、書き足した文と数値のコピーが次の周の (c) になって、例外の周が 10 周、7 周、4 周に
  伸びた
- 案 B: 周ごとの経緯（どの周で何を直し、何を残したか）と捨てた形を、マージの本文にだけ残す。マージの本文には /git-merge の
  「直す指摘の基準」のとおり指摘ごとの「再現」「再現なし → <issue の番号>」の行が既にあり、上の 3 本の本文もその行を持つので、
  周の経緯は issue に書かなくても残る。ただし捨てた形をマージの本文にだけ置くのはグローバルの CLAUDE.md の「コミットの本文だけに
  置かない」と食い違い、次にその issue を扱う人は issue を開いてもそれを読まない。また、数値のコピー（#0258 の BOC の項）と、
  直った項が「問題」に残ることは、経緯の置き場を変えても残る
- 案 C（採る）: 「問題」を今の未解決の点の一覧だけにし、経緯は日付ごとに短く、捨てた形は issue の節に、数値は 1 か所の出典を
  指す。周の経緯は案 B と同じくマージの本文の行に残る

## 決定と理由

案 C にする。issue の本文は次のとおりに書く。

1. 「問題」の節は、今の文書とコードに残る未解決の点の一覧だけにする。周の番号、「〜で直した」の見出し、コミットの hash で
   分けない。直った点は消す（経緯は git log にある）
2. 「経緯」は日付ごとに 1〜2 行。hash と過去のコミットの文の引用は書かない
3. 試して捨てた形は「検討して捨てた形」の節に、何を試しなぜ捨てたか（反例、測った値）を 1 行ずつ残す
4. ほかの文書（記録、ADR、別の issue）にある数値はコピーせず、1 か所の出典を名前（文書と節）で指す。値を書くなら出典・
   コミット・日付をそろえた 1 か所だけ

1 と 2 は、issue を ADR-0117 の検証の記録と同じく今の姿で書く。直った点の文と経緯は、git の履歴（`git log -p -- <issue>`）と
マージの本文の「再現」の行に残る。3 は、1 で消す直しのうち、捨てた形の理由だけを issue に残す（グローバルの CLAUDE.md の
「設計の記録」を満たす）。4 は、同じ値を複数の文書に置かず、直す場所を 1 つにする。検証の記録の数値は、名前で指すときも値を書くときも、ADR-0117 の決定と
理由の「記録の辿り方」に従って引く（名前で指すときは値をコピーしない）。添えるコミットが何のためにあるかは ADR-0122 の決定と理由にある。

ADR-0117 の決定と理由の「ADR と issue」の項のうち issue の部分は、この ADR で置き換える（ADR-0117 の「## 変更」）。

### 帰結

- docs/issues/README.md のテンプレートに「検討して捨てた形」の節を足し、「運用」に 1〜4 を書く
- 既存の issue は直さない。新しい issue と、次に触る issue から当てる
- 既存の issue をこの形に書き直すと、ほかの文書が引いた節が消える。2026-11-07 に #0036 を書き直したブランチで、ADR-0237 が消えた
  節を指し、レビューの指摘になった（マージ e6090a405 の本文）。書き直す前に引く文書を探し、書き直す前のコミットを添える手順を
  docs/issues/README.md の「運用」に書く
- この形で例外の周が減るかは確かめていない。次に issue を残すブランチのマージの本文の周の数で見る（#0259）

### 確認

約束事なので、確かめるテストはない。docs/issues/README.md のテンプレートと「運用」に決定を書く。
