# ADR-0234: 炉心の固有値計算を、ノードを市松の 2 色に分けた順で解き、同じ色のノードを複数のスレッドで解く

## 背景

全炉心の燃焼（Problem 9 の形）は、CMFD（[ADR-0232](0232-accelerate-nem-with-node-cmfd.md)。粗メッシュの許容は「## 変更」の 2026-11-06）の後も全体の 97.1 % が
固有値計算で、1 回の解の固有値計算は 1 つのスレッドで解く（examples/depletion/verification.md の「固有値計算の CMFD（小さな炉心と全炉心）」。Slurm 707、
cd4d268bd、2026-11-06。全体 506.3 s、固有値計算 43 回 491.7 s）。全炉心の燃焼の速度の対策は、Xe とホウ素の探索の同時の収束、CMFD、複数のスレッドの順に
進める（ユーザー 2026-11-06 の判断の要約。ADR-0232 の背景）。これはその 3 番目。

NEM のスイープ（`nem::Core::sweep_group`）と粗メッシュの固有値問題（`xlc_cmfd::Coarse::solve` のブロック Gauss-Seidel）は、ノード（セル）を直方体の並びの順に
1 つずつ解き、先に解いた隣の値をすぐ使う。この順のままでは、ノードを並列に解けない。

判断の軸: 正確さ > 実行速度 > 保守（CLAUDE.md の「方針」）。

- 収束の判定（`nem::Options` の許容）は緩めない。解く順を変えた解は、同じ判定を満たす解として許容の 2 倍の中で一致すること
- 結果はスレッドの数によらないこと（[ADR-0137](0137-compute-options-as-input.md) は、スレッドの数を結果を変えない前提で環境変数から読むことを許す）
- 前の解き方（直方体の並びの順に 1 つずつ）を入力で選べる形で残す（ADR-0231 の `initial-guess = "flat"`、ADR-0219 の `xenon-boron = "nested"`、
  ADR-0232 の `acceleration = "none"` と同じ扱い）

## 検討した案

下の時間は、全炉心の BOC の固有値計算 1 回（b1a78aa9 の `trials/p9-timing/boc-1100.toml` に `threads` と `node-order` を足した手元の試行の入力。コミットして
いない）を、区分 trial の Slurm のジョブ（パーティション main。待ち行列にほかのジョブは無かった）で解いた目安。708 は 056790e5c、709 は作業中の版（コミット
していない）、710 は 7f9977c14 と同じコードで、どれも 2026-11-06。粗メッシュの許容は ADR-0232 の「## 変更」の後。

並列にする形:

- 案 P1（採用）: ノードを位置の x + y + z の偶奇で市松の 2 色に分け、スイープと粗メッシュのブロック Gauss-Seidel を色の順に解く。面で接するノードは色が違うので、
  同じ色のノードは互いの値を読まず、色の中を並列に解いても結果は解く順とスレッドの数によらない。BOC（Slurm 710）は 1 スレッド 10.4 s、4 スレッド 3.37 s、
  8 スレッド 2.13 s、16 スレッド 2.31 s、外側の反復 47 回（直方体の並びの順は 51 回）
- 案 P2: 直方体の並びの順のまま、ノードごとに独立な部分（横方向の漏れ、粗メッシュの組み立て、CMFD の更新、規格化）だけを並列にする。BOC（Slurm 710）は
  1 スレッド 12.4 s、16 スレッド 11.7 s で、時間の大半のスイープと粗メッシュの反復が 1 スレッドのまま残る
- 案 P3: 群のスイープの始めの値で全ノードを解く（Jacobi）。比べていない（案 P1 と同じく並列に解け、Gauss-Seidel の半分の値しか新しい値を使わない）
- 案 P4: 炉心を領域に分け、領域ごとにスレッドを割り当てる。比べていない（領域の境界の扱いと分け方の決定が要る）

結果の再現性:

- 案 R1（採用）: スレッドの数によらず同じビットにする。色の中のノードの値はそれぞれ 1 つのスレッドで求め、和（生成率）は決まった順に取る。粗メッシュの
  生成率は、決まった大きさ（256 セル）の塊の部分和を並列に求めて塊の順に足す
- 案 R2: 並列の和の順がスレッドの数で変わることを許し、許容の中の差を認める。テストと記録でスレッドの数ごとの差を見る必要が残る

粗メッシュの和と規格化を、色ごとの解きと同じ並列の呼び出しで取る形（案 R1 の塊の部分和）は、逐次の和の形に比べて、BOC の 16 スレッドの粗メッシュの時間が
3.57 s（Slurm 708）から 1.49 s（Slurm 710）に縮んだ。

既定のスレッドの数（ケースの `threads` も `RAYON_NUM_THREADS` も無いとき）:

- 案 T1（採用）: 物理コアの数を、このプロセスに許された論理 CPU の数で抑えたもの（ADR-0067、xs の `parallel::cores` と同じ規則）。r995 の排他のジョブで 16
- 案 T2: 許された論理 CPU の数（[ADR-0214](0214-default-threads-to-logical-cpus.md) の lattice と同じ）。r995 の排他のジョブで 32。BOC は
  16 スレッドと 32 スレッドで 2.24 s と 3.42 s（Slurm 709）、2.31 s と 2.37 s（Slurm 710）で、32 スレッドは速くならず、ばらつきが大きい

状態を並列に解く形（ケースの名前つきの状態。[ADR-0146](0146-solve-named-states-of-a-case-in-parallel.md)）:

- 案 S1（採用）: 同時に解く状態の数（スレッドの数と状態の数の小さい方）だけのスレッドを作り、それぞれが自分の rayon のプール（スレッドを等分し、余りは前から 1 つ
  ずつ足す）で状態を順に解く
- 案 S2: 1 つの rayon のプールで状態を並列に解き、その中で色の中を並列に解く。色の中の並列の終わりを待つスレッドがほかの状態の解を丸ごと盗んで解き、固有値
  計算の時間（span `nem` の `seconds`）とログの区間がその状態の分を含む（レビューの 1 周目の指摘）

## 決定と理由

炉心の固有値計算（`nem::solve`、`solve_from`、`solve_with`）の既定を、案 P1、R1 にする。

- **解く順**: ケースの `node-order`。既定 `red-black` は、位置の x + y + z の偶奇の市松の 2 色（最初のノードの色を 0 にし、外形の外の位置の数で順が変わらない）を、
  最初のノードの色、もう一方の色の順に解く。各群のスイープは、色の中のノードを rayon のプールで並列に解いてから書き、CMFD の粗メッシュの問題は同じ色で
  `xlc_cmfd::Coarse::colored` にする（セルを色の順に並べ直し、色の中を並列に解く。隣と同じ色のセルがあればエラー）。`lexicographic` は直方体の並びの順に
  1 つずつ解く（比べるため。ADR-0234 の前の解き方と同じビットの解。ノードごとに独立な部分はプールで解く）
- **再現性**: 解はスレッドの数によらず同じビット。ノードごとに独立な部分（横方向の漏れ、粗メッシュの組み立てと逆行列、CMFD の更新、規格化）も並列にし、和は
  決まった順に取る。エラーは色の中のノードの順で最初のもの
- **スレッドの数**: ケースの `threads`（正の整数）、無ければ `RAYON_NUM_THREADS`（正の整数でなければエラー）、どちらも無ければ案 T1。両方を与えればエラー。
  始めにログに `thread pool threads=<数> from=<input | RAYON_NUM_THREADS | default>` を出す。結果を変えないので、燃焼の履歴には書かない
- **状態の並列**: 案 S1

理由: 案 P1 は、Gauss-Seidel の形を保ったまま色の中を並列に解け、BOC の外側の反復も直方体の並びの順より少なかった（47 回と 51 回）。案 P2 はスイープと粗メッシュの
反復が 1 スレッドに残り、16 スレッドでも 6 % しか縮まない。案 R1 は、テストと記録がスレッドの数ごとの差を見ずにビットの一致で確かめられ、和の順を決める費用は
塊の部分和で済む。案 T1 は、32 スレッドが速くならずばらつきが大きいので、ADR-0067 の規則に合わせた。案 S1 は、状態ごとの固有値計算の時間とログを、その状態の
計算だけにする。

### 帰結

- core の結果は、既定の色の順で、直方体の並びの順の解と許容の中の丸めの桁が変わる。examples の core のステージは `bin/core` が変わるので、次に読む作業で再実行する
- 全炉心の燃焼（Problem 9 の形）は 506.3 s から 106.2 s、固有値計算は全体の 85.6 %（「確認」）。外側の反復 1 回は 16 スレッドで平均 67 ms で、粗メッシュの問題の
  並列の効き（BOC で 8 スレッドから縮まない）と組み立ての時間が残る（#0246）
- 状態を並列に解くときの固有値計算の時間は、その状態のスレッドの数で解いた時間になる。ADR-0146 の背景の「各状態の解は 1 スレッドの計算」は、色の順の並列で
  成り立たない（結果がスレッドの数によらないことは変わらない）
- 既定のスレッドの数は、前の rayon の既定（論理 CPU の数。r995 の排他のジョブで 32）から物理コアの数（16）になり、燃焼のミクロ燃焼と平衡 Xe の並列（`depletion.rs`）
  も 16 スレッドで解く。全炉心の燃焼でミクロ燃焼は 1.9 s、平衡 Xe は 1.6 s（「確認」）
- 小さな炉心（1 色 64 ノード）は、ノードを並列に解く塊の下限（64 ノード、粗メッシュの 256 セル）を超えず、色の中は並列にならない（「確認」の小さな炉心）
- スレッドの数の規則は lattice、xs、core の 3 つの実行ファイルに分かれる（#0246）

### 確認

- `crates/cmfd` のテスト: 色の順の解がセルの順の解と許容の 2 倍の中で一致し、比を与えたセルの順に返す（`colored_solves_agree_with_the_cell_order`）、1、2、3、8
  スレッドでビットで同じ（`colored_solves_do_not_depend_on_the_thread_count`）、同じ色の隣と色の数の食い違いのエラー（`colors_must_not_couple_cells_of_the_same_color`）
- `crates/core` のテスト: 色の順の解が CMFD の有無で 1、2、3、8 スレッドでビットで同じ（`red_black_solutions_do_not_depend_on_the_thread_count`）、直方体の並びの
  順と許容の 2 倍の中で一致（`red_black_order_agrees_with_the_lexicographic_order`）、エラーがスレッドの数によらない（`red_black_errors_name_the_first_node_in_order`）、
  燃焼の履歴が 1、2、4 スレッドでビットで同じ（`depletion_does_not_depend_on_the_thread_count`）、探索の許容を詰めた燃焼の点が直方体の並びの順と一致
  （`red_black_order_keeps_the_lexicographic_points`）、入力（`nodes_are_solved_in_red_black_order_unless_lexicographic_is_given`、
  `thread_counts_are_positive_when_given`）、スレッドの数とログ（`crates/core/tests/threads.rs`）、状態の並列のスレッドの分け方
  （`parallel_states_split_the_threads_without_sharing_them`）
- 小さな炉心（examples/depletion/verification.md の「固有値計算の複数のスレッド（小さな炉心と全炉心）」の「小さな炉心」。f9c773ce6、`bin/core` md5 f5891193、手元の目安、
  2026-11-06）: 色の順の履歴は 1、4、16 スレッドでバイトで同じ、直方体の並びの順の履歴は ADR-0234 の前の `bin/core`（md5 7f777e71）の履歴とバイトで同じ。色の順と
  直方体の並びの順の k の差は点と中点で最大 5.4e-10 と 8.2e-8、ホウ素の差は最大 7.9e-5 ppm と 7.1e-4 ppm（探索の許容の中）
- 全炉心（同じ節の「全炉心（Problem 9 の形）」。dd6bbbe02、Slurm 711 の timed、elapsed 00:01:47、16 スレッド、2026-11-06）: Slurm 707（ADR-0234 の前の `bin/core`、
  elapsed 00:08:27）の同じ入力と比べ、全体 506.3 s から 106.2 s（0.210 倍）、固有値計算 491.7 s から 90.9 s（0.185 倍）、外側の反復の和 1,581 回から 1,348 回。
  点と中点の k の差は最大 8.3e-10、ホウ素の差は最大 9.7e-8 ppm、燃焼度と出力の割合の相対差は最大 6.4e-8 と 1.3e-7
- build のステージで、`bin/xs`、`bin/lattice`、`bin/chain` の md5 は main（67e04a4bd の dvc.lock）と同じ
