# ADR-0189: 核種ごとのステージを保ち、核種の中の並列でコアを埋め、スレッドの数を引数で選べるようにする

## 背景

多群ライブラリの作り直し（`xs`）が CPU を使い切っていなかった（ユーザーの指示、2026-10-23「CPU を効率的に使えるようにしてください」）。
examples/depletion の 65 核種を作り直す Slurm の排他のジョブ 473（ラダーの和をベクトル化した [ADR-0188](0188-vectorize-ladder-sums-keeping-bits.md) の後、xlc 27129ed9、
2026-10-23。examples/depletion/verification.md の「燃焼の多群ライブラリ」）は、経過時間 38 分、CPU 時間（sacct の TotalCPU）3 時間 4 分で、
平均 4.8 コアだった（r995 は物理 16 コア）。

- DVC 3.67.1 の `dvc repro` はステージを 1 つずつ実行する（`dvc/repo/reproduce.py` の `_reproduce` が `for stage in stages` で順に呼び、
  `reproduce` は `@locked` で、同じリポジトリで 2 つ目の `dvc repro` を待たせる。`dvc repro` に並列の選択肢はない）。核種ごとのステージ
  （[ADR-0138](0138-split-xs-into-nuclide-stages.md)）は 1 核種ずつ順に走る
- 1 核種のプロセスの中で並列なのは、非分離共鳴の格子点のサンプリング（`unresolved_shielding` の `in_parallel`。[ADR-0177](0177-shield-unresolved-range-by-probability-tables.md)）だけだった。
  温度は順に処理し、格子点の並列は始めるときに空いているスレッドだけを取り、最後まで持っていた
- 空いていたコアの時間の内訳（473 と、ADR-0188 の前のジョブ 452、460 のログ）:
  - ステージの間（前の核種の span が閉じてから次の核種の span が始まるまで。テープの読み込み、結果の書き出し、プロセスの起動、DVC のステージの
    準備）: 473 で 64 回の計 106 秒（平均 1.66 秒）、経過時間の 4.6%。span の始まりは閉じた時刻から `time.busy` を引いて求めた
  - 残りは核種のプロセスの中: 温度ごとの格子点の外の処理（Cm-244 の 4 温度で、1 スレッドの 247 秒のうち格子点の外が温度ごとに約 3.5 秒。
    ADR-0188 の前の手元の測定、main 1f650c35、2026-10-23）と、格子点の並列の末尾（1 温度の格子点は Cd-106 で 17 点、Mo-95 で 29 点（ADR-0177 の「確認」のサンプルの数から）で、最後の点が
    終わるまでほかのスレッドが遊ぶ）。この 2 つは分けて測っていない
- 全コアで 1 スレッドずつ同じ計算を実行したときの 1 スレッドの遅れ（下の「確認」のジョブ 479）: Cm-244 の 565 K を 1 スレッドで、1 本だけで 7.53 秒、
  物理コア 16 個に 1 本ずつ同時に 8.14〜8.57 秒（8〜14% 遅い）。コアを埋めたときの下限は、CPU 時間の和 / 16 にこの遅れを含めたもので見る

判断の軸:

- 出力が直列と同じこと（全核種の msgpack の md5 が dvc.lock と一致）
- 核種ごとのステージの粒度（ADR-0138。1 核種の ENDF か xs.toml のその核種の項目だけを変えたとき、その核種だけを作り直せること）を保つ
  （ユーザーの指摘、2026-10-23）。ステージを 1 つにする案は、粒度を保つ案で同じ効果が得られないときだけ採る
- 全核種の経過時間
- 依存を足さない（rayon を含む。[ADR-0067](0067-default-threads-to-physical-cores.md) と `in_parallel` の注釈）
- 保守の層（スクリプト、`dvc commit` の運用）を増やさない
- スレッドの数とメモリ: 入れ子の並列（核種、温度、格子点）でコアの数を超えない

## 検討した案

時間は examples/depletion の 65 核種（下の「確認」のジョブ 479 と、比べる元のジョブ 473）。「1 核種だけ変えたとき」は、その核種のステージの時間
（範囲と組み立てのステージは数秒で、どの案も同じなので除く）。

| 案                                                                       | 65 核種の経過時間                                                        | 1 核種だけ変えたとき                        | 層                                          |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------- | ------------------------------------------- |
| A: 今のまま                                                              | 2,186 秒（ステージの始めから終わり。ジョブ 473）                         | Am-242m 184 秒、U-238 213 秒（473 の span） | なし                                        |
| B: 1 つのステージで全核種を 1 プロセスが処理し、核種をまたいで並列にする | 763 秒（ジョブ 479。MaxRSS 2.2 GB）                                      | 全核種を作り直す 763 秒                     | なし（ステージの形を戻す）                  |
| C: 核種ごとのステージを保ち、runner が同時に投入して `dvc commit` する   | 720 秒（ジョブ 479 の試行。DVC と `dvc commit` の時間を含まない）        | その核種だけ（D と同じ）                    | runner、CPU 時間の記録、`dvc commit` の運用 |
| D: 核種ごとのステージを保ち、核種の中の並列でコアを埋める（採用）        | 1,154 秒（ジョブ 479。核種のプロセスの和。DVC のステージの間を含まない） | Am-242m 173 秒、U-238 86 秒、U-235 69 秒    | なし                                        |

- 案 A: CPU 時間の和の 1/16（下限 710 秒）の約 3 倍かかる
- 案 B: 全核種を 1 つのプロセスで処理し（`xs <入力>`）、核種、温度、格子点を同じスレッドの予算で並列にする。下限に近いが、1 核種だけの変更で
  全核種を作り直し、ADR-0138 の粒度を失う。粒度を保つ案 D と C がそれぞれ時間の多くを取るので、採らない
- 案 C: 核種ごとのステージは残し、`dvc status` で changed の `xs-nuclide` のステージを挙げ、前回の CPU 時間の長い順に、スレッドの数を
  ceil(CPU 時間 / (CPU 時間の和 / 16)) に決めて、合計 16 スレッドの中で同時に実行し、終わったステージを `dvc commit` で lock に取り込む
  （ユーザーの案、2026-10-23）。479 で同じジョブの CPU 時間を使って試すと 720 秒で、下限にほぼ届いた（Am-242m は 4 スレッド、Pu-239 と
  Eu-151 は 2、ほかは 1）。全核種を 1 スレッドにすると最長の核種の CPU 時間（Am-242m 2,278 秒）が下限を決めるので、重い核種に多くの
  スレッドを配ることが要る。CPU 時間は ENDF の大きさ × 温度の数とほとんど相関しない（479 の 65 核種で、対数の相関係数 0.12）ので、
  前回の時間の記録が要る。DVC の外でステージの cmd を繰り返す runner、時間の記録、`dvc commit` の運用（[ADR-0159](0159-depend-stages-on-built-binaries.md) の
  案 B と #0145 が扱う、lock が実行していない deps を指すおそれ。runner は今の deps で実行するので当たらないが、実行中に deps が変わったときの
  扱いを決める要がある）が増える。D の上に積めるので、D のあとで #0157 で決める
- 案 D: 核種のプロセスの中で、空いたスレッドを途中からでも使い、温度を並列にする。粒度もステージの形も変えず、層を増やさない。経過時間は A の
  約半分（2,186 秒から、核種のプロセスの和 1,154 秒とステージの間（473 で 106 秒）。DVC を通した経過時間は測っていない）

## 決定と理由

案 D を採る。ADR-0138 の核種ごとのステージはそのまま保つ。

- `in_parallel` は、各スレッドが i を取るたびに、残りの i があり予算に空きがあればスレッドを 1 つ足し、取る i がなくなったスレッドはすぐに
  予算に返す。呼んだスレッドも計算し、予算は物理コアの数（ADR-0067）− 1。入れ子の呼び出しのどれかが空けたスレッドを、途中から
  ほかの呼び出しが使う。結果は i の順で、エラーは最も小さい i のもの（スレッドの数と進み方によらない）
- 核種の中の温度を `in_parallel` で並列にする（`process_nuclide`）。温度ごとの格子点の外の処理を、ほかの温度の格子点と重ねる
- ステージに分けない経路（`xs <入力>`）の核種と、テープの読み込みも `in_parallel` にする（核種ごとに予算の外のスレッドを起こしていた）
- `xs --threads <数>` で、同時に使うスレッドの数を選べるようにする。省略すると物理コアの数をこのプロセスに許された CPU の数
  （`available_parallelism`。taskset の affinity を反映する）で抑えたもの。今でも taskset で抑えられるが、DVC が記録する cmd に残り、
  runner（案 C）が核種ごとに決められるように、引数にする。結果はスレッドの数によらない

依存は足さない（標準ライブラリのスレッドとアトミック）。

## 帰結

- 65 核種の作り直しの核種のプロセスの和は 2,080 秒（473 の span の和）から 1,154 秒になる。下限（710 秒）との差の多くは、プロセスの中の
  1 スレッドの部分（U-238 は 86 秒で平均 4.4 コア、H-1 は 47 秒で 3.0 コア。候補は 0 K の再構成、熱中性子散乱、温度ごとの格子点の外の処理で、
  確かめていない）と、ステージの間。入れ子の内側の呼び出しで、取る i がなくなった呼んだスレッドは、残りの i を待つ間も外側の予算の 1 つを
  持つ（核種の中の温度、温度の中の格子点の末尾）。どれだけ効くかは測っていない
- 案 C は #0157 で、D の上に足すかを決める
- `xs` のコードが変わるので、実行ファイルを deps にする全例の xs のステージが changed になる。出力は変わらない（「確認」）ので、
  ADR-0130 のとおり、結果が要るときに作り直す
- 同時に処理する温度の分だけメモリが増える。65 核種のステージで 1 核種のプロセスの MaxRSS は最大 998 MB（479）

## 確認

- 出力（Slurm の排他のジョブ 479、xlc 0fdbdda1（分岐点 102533e8）、2026-10-23。手順は examples/depletion/issue-0157/measure.sh。DVC を通さない。0fdbdda1 の後のコミットは、パニックのときの止め方とログの span だけを変えた）:
  - 核種ごとのステージの形（`xs nuclide`、既定のスレッドの数）、案 C の試行（`--threads` 1〜4）の 65 核種の msgpack は、どちらも 65 核種すべての
    md5 が examples/depletion/dvc.lock（ジョブ 473 の出力）と一致した
  - `xs <入力>`（案 B の形）の `depletion.msgpack` の md5 は dvc.lock と同じ ea77045e689e9684bd0ef26cabf4012a
  - Cm-244 の 565 K を 1 スレッドで 17 本（1 本だけと、16 本を同時に）作り、md5 が同じだった
- 時間（同じジョブ 479）: 核種ごとのステージの形のプロセスの経過時間の和 1,154 秒（CPU 時間の和 11,358 秒、平均 9.8 コア）、`xs <入力>` 763 秒
  （CPU 時間 11,486 秒）、案 C の試行 720 秒。比べる元は 473 のステージの始めから終わりの 2,186 秒（核種の span の和 2,080 秒、ステージの間 106 秒）
- 単体テスト: `in_parallel` が途中で空いたスレッドを使うこと、i を使い切ったスレッドが予算に返ること、入れ子でも予算 + 呼んだスレッドの
  数を超えないこと、呼んだスレッドのパニックでもほかのスレッドが止まること、足したスレッドのログが呼んだスレッドの span に入ること
  （crates/xs/src/parallel/tests.rs）。`--threads` の読み方（crates/xs/src/main/tests.rs）
