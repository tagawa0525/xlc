# ADR-0138: xs を、ポイントワイズの範囲、核種ごとの処理、組み立ての副コマンドに分ける

## 背景

examples の DVC のステージ（ADR-0123）では、`xs` が入力の全核種を 1 つの段階で処理する。1 つの核種の項目（温度、ENDF）だけを
変えても、全核種を処理し直す。OpenMC のライブラリは、すでに核種ごとの段階と組み立ての段階に分けてある（ADR-0130）。

xs の処理は核種ごとに独立だが、1 つだけ全核種にまたがる値がある。ポイントワイズの範囲（`Settings::pointwise_range`）は、
全核種の分離共鳴の上端のうち最も高いものから決まり、どの核種の処理にも入る。核種ごとの段階は、この値を入力に持つ
必要がある。

## 検討した案

- 案 A: 分けない。1 核種の変更で全核種を処理し直す
- 案 B: 核種ごとの段階が、範囲を自分で求める。範囲を求めるには全核種の ENDF を読むので、どの段階も全核種の ENDF を
  deps にすることになり、核種ごとに分ける意味がない
- 案 C: 範囲を求める段階を先に置き、核種ごとの段階がそのファイルを deps にする（採用）
- 案 D: 核種ごとの出力に新しい形式を作る。ライブラリの形式（`xlc-multigroup`）が 1 核種だけのライブラリを表せるので、
  形式を増やさず、同じ形式で書く
- 案 E: すべての例（m0、reflector）を同時に分ける。m0 は 4 核種で得るものがなく、reflector は 100 近い核種を持つが、
  今回は vera だけにする（#0081）

## 決定と理由

案 C と案 D を採る。`xs` に副コマンドを足す（引数が入力ファイルだけのときは、これまでどおり全核種を処理して
`output` に書く。同じ関数を使う）:

- `xs range <入力> <範囲のファイル>`: 全核種のテープから範囲を求めて TOML に書く。範囲がなければ空の配列を書く（項目は欠かさない。
  ADR-0129）。浮動小数点数は最短の往復できる表記で書く
- `xs nuclide <入力> <範囲のファイル> <核種> <出力>`: その核種だけを、そのファイルの範囲で処理し、1 核種のライブラリ
  （`xlc-multigroup`）を書く
- `xs assemble <入力> <範囲のファイル> <ディレクトリ>`: `<ディレクトリ>/<核種>.msgpack` を入力の核種の順に読み、各ファイルが
  入力のその核種の結果であること（1 核種、名前、温度の値と順）と、入力と範囲のファイルと同じ条件で作られたこと（群構造、
  σ0、範囲、散乱行列の次数）を確かめ、`Library::merge`（群構造、σ0、範囲が同じことを確かめて核種を並べる）で 1 つにして
  `output` に書く。古い結果が残っていても、食い違うライブラリを黙って作らない

DVC のステージ（examples/vera/dvc.yaml。`xs.toml` を `vars` にして核種ごとに `foreach`）:

- `xs-range`: deps は `xs.toml`、ENDF のディレクトリ、コード。出力は `xs-range.toml`
- `xs-nuclide@<核種>`: deps は範囲のファイル、その核種の ENDF、熱中性子散乱の ENDF のディレクトリ（固定してある。
  ADR-0124）、コード。入力は `xs.toml` の params のうち、`sigma0`、`scattering-order`、`nuclide.<核種>` だけ。
  `scattering-order` は、params で名指しするため、vera の `xs.toml` に 3 を書いた（省略時の値と同じ。ADR-0076）
- `xs`（組み立て）: deps は `xs.toml`、`xs-range.toml`、`xs-nuclides/`、コード

## 帰結

- 1 つの核種の項目を変えると、その核種の段階、`xs-range`（`xs.toml` を deps にするので走るが、結果の md5 が同じなら下流は
  走らない）、組み立てが走る。ほかの核種の段階は走らない（確認）
- 分離共鳴の上端が最大の核種の変更や、核種の追加と削除で範囲が変わると、全核種が走る。xs のコードを変えても全核種が走る
- 全核種を作り直すとき、DVC のステージは逐次で走るので、全核種を並列に処理する 1 回の実行より遅い。共有（`-c 2`）で、段階に
  分けた 55 核種に 31 分、1 回の実行（`-c 8`）に 17 分かかった（xlc 6705fd4f、2026-10-12。共有のジョブで、時間は当てにならない。
  計算の条件が違うので、比べる値としても使わない）。核種の変更が多く、全体の作り直しが少ないあいだは、この引き換えを受ける
- m0 と reflector の `xs` は、1 つの段階のまま。同じ形で分けるのは、核種の変更が続くようになってから（#0081）
- 組み立てた結果の検査は、各ファイルが入力のその核種の結果であること。古い核種ごとのファイルが残っても、名前と温度が
  入力と違えば止まる。範囲が違う核種のファイルは、`Library::merge` が止める

### 確認

- 段階に分けて作った `vera.msgpack` が、1 回の実行で作ったものとバイト単位で一致した（md5 3d1a8cc29b76d93cd46fa5e058ff615e、
  size 123378257。xlc 6705fd4f、2026-10-12）
- `xs.toml` の Ni-62 の温度を 1 つ足して `dvc repro` すると、`xs-range`、`xs-nuclide@Ni-62`、`xs` だけが走り、`dvc.lock` の
  差は、その 3 段階のものだけだった（`xs-range` の出力は変わらず、足した温度は元に戻して確認した）
- `Library::merge` と、範囲のファイル、核種ごとの結果の検査（名前と温度、条件）の単体テスト
