# ADR-0191: core の燃焼は、状態の search でステップの各解（点と中点）の臨界ホウ素を探す

## 背景

[ADR-0190](0190-advance-node-burnups-by-midpoint-steps.md) は、ケースの `[depletion]` でノードの燃焼度を EFPD のステップに沿って中点の形で進め、1 ステップに 2 回（初めの点と
中点）解くと決めた。ケースの状態はちょうど 1 つで、そのホウ素濃度をすべてのステップに使い、状態に `search`（[ADR-0145](0145-search-critical-boron-by-illinois-in-input-bracket.md) の臨界
ホウ素の探索）を書けばエラーにした。ステップごとの探索は「`steps` の各ステップの表に項目を足す形」で後の ADR にするとした。

VERA Problem 9 は、サイクルの各状態で臨界ホウ素濃度を求め、実測（表 P9-4）と比べる。実測のホウ素は、32.0 EFPD の 858 ppm から
下がり、401.4 EFPD で 7 ppm、その後の 410.7、418.8、438.5 EFPD は 9 ppm で、出力は 89.9、83.4、65.3 % に下がっている（表 P9-4。
CASL-U-2012-0131-004、93 ページ）。サイクルの終わりは、ホウ素がほぼ 0 のまま出力を下げて（コーストダウン）臨界を保つ。表 P9-2
（90 ページ）はホウ素の列を持たず、最後の 3 状態 28〜30（410.7、423.6、441.0 EFPD）の出力は 89.9、78.8、64.5 % の端点の値である。
ホウ素は 32.0 から 401.4 EFPD で 851 ppm 下がる（平均 2.30 ppm/EFPD）ので、表の約 15 EFPD のステップの半分では約 17 ppm 動く。

判断の軸:

- 正確さ: ADR-0190 の中点の形の次数を保つこと。中点の出力分布は、臨界の炉心の中点の燃焼度の出力分布であること
- 解く回数: 1 回の評価が炉心の固有値計算で、探索はそれを数回繰り返す
- 黙った既定を作らない。効かない入力を受けない。怪しい状態はエラーで止める（CLAUDE.md）
- ADR-0145 の「入力で与えた範囲を囲い込んだまま探す」と整合すること

## 検討した案

どの解で探すか:

- 案 S1: 燃焼点（0 と各ステップの終わり）の解だけで探し、中点はステップの初めの点のホウ素で解く: 探索は 1 ステップに 1 回。
  中点のホウ素は臨界の値から、ホウ素のステップの中の変化の半分（Problem 9 の 15 EFPD のステップで約 17 ppm）ずれる。中点の
  出力の割合の誤差がステップの長さ Δ に比例し、それで進めた燃焼度の 1 ステップの誤差が O(Δ²) になるので、ホウ素を通した部分の
  誤差は 1 次になる（ADR-0190 の 2 次が、ホウ素で出力分布の変わる炉心で 1 次に落ちる）
- 案 S2: 点と中点の両方で探す（採用）: 中点の解は、中点の燃焼度で臨界にした炉心の出力分布で、ADR-0190 の中点の形がそのまま
  2 次になる。探索は 1 ステップに 2 回
- 案 S3: 中点のホウ素を、前の点の値から外挿する（または前の点と次の点の予測から内挿する）: 外挿の誤差が O(Δ²) なら 2 次を保つが、
  最初のステップに前の点がなく、外挿の規則（何点から何次で）が黙った既定になる。中点の k は目標から外れたまま解く

集合体 1 体（反射境界、ノード 1 つ）では出力の割合が 1 なので、どの案でも燃焼度は同じで、差は出ない。燃焼度の違う集合体が並ぶ炉心で
ホウ素の価値が集合体ごとに違えば、ホウ素で出力の割合が動く。その大きさ（S1 と S2 の燃焼度の差）は測っていない。

探索の範囲:

- 案 B1: 状態の `search` の範囲（例: [0, 1300] ppm）を、すべての探索に使う（採用）: ADR-0145 のとおり、範囲は入力が与え、両端で目標を
  挟むことを確かめる。探索ごとに両端の 2 回を解くので、探索の回数は「両端 + 割線の数回」になる
- 案 B2: 前の点のホウ素の周りに範囲を動かす（幅を入力で与える）: 端を解の近くに置けるので割線の回数が減りうるが、解が幅の外に
  出たときに範囲を広げる規則が要る（ADR-0145 が「1 点の初期値から探す」案で採らなかった、黙った既定）。幅の外に出たらエラーに
  するなら、ステップの長さに合わせて幅を選ぶ手間が増える
- 案 B3: 前の点のホウ素を最初の評価点にし、入力の範囲で囲い込む: Illinois 法の初めの 2 点を両端でなくするので、囲い込みを保つには
  範囲の片側をもう 1 回解く必要があり、回数は B1 と変わらない見込み（確かめていない）

範囲の下端で k が目標より小さいとき（サイクルの終わり。上端で目標より大きいとき、すなわち初めの点も同じ扱い）:

- 案 E1: ADR-0145 のとおりエラーで止める（採用）: 範囲が解を挟まないエラーで、両端の k と、どのステップの点か中点かを示す。それまでの
  点は標準出力に出してある（ADR-0190）
- 案 E2: 範囲の端のホウ素（0 ppm）で解き、k が目標と違うまま点を記録して燃焼を続ける: Problem 9 の終わりの状態はホウ素ではなく
  出力を下げて臨界を保つ（表 P9-4 の 9 ppm、65〜90 %）。出力の割合と熱水力のフィードバック（Xe を含む）がまだないので、0 ppm で
  定格の出力の点は実機のどの状態でもない。また、探索の状態が、ある点から黙って与えた濃度の状態に変わる
- 案 E3: エラーにするが、それまでの点の履歴のファイルを書く: 履歴のファイルは、ケースのステップをすべて解いたものという ADR-0190 の
  形を変える。止まった点までの値は標準出力の `point` の行にある

入力の置き場:

- 案 I1: ケースの状態の `search`（ADR-0145 の形）を、燃焼のケースでも書けるようにし、すべての解に使う（採用）: ADR-0190 は、状態を
  すべてのステップに使うと決めた。ホウ素を与えるか探すかは状態の項目なので、燃焼でない状態の探索と同じ入力・同じ検査になる。
  新しい書き方を足さない
- 案 I2: `[depletion]` に `search` を 1 つ書く: I1 と同じ情報を別の場所に書くことになり、状態の `boron` と `search` のどちらか一方と
  いう ADR-0145 の規則を、状態と `[depletion]` の間で確かめ直す必要がある
- 案 I3: `steps` の各ステップの表に書く（ADR-0190 の予定）: 範囲（案 B1）、目標の k、許容、回数をステップごとに変える場面が今はない。
  目標の k を燃焼度で変える（炉心の計算の偏りを補う、実機の解析の慣行）なら、ステップの項目が要る。そのときに、状態の `search` を
  ステップの項目で上書きする形で足せる

出力:

- 案 O1: 履歴の点に `boron`（その点を解いたホウ素濃度、ppm）と `solves`（その点の固有値計算の回数）を足し、`state` は入力と同じく
  `boron`（与えた濃度）か `search`（探索の設定）のどちらか一方を持つ（採用）: 点のホウ素は与えたケースでも書くので、読む側は
  探索したかによらず点の `boron` を読める。与えたケースの `state` は今の形のまま（ADR-0190 の比べるツールがそのまま読める）
- 案 O2: 点に中点のホウ素と回数も書く: ADR-0190 は中点の解を点に残さない（点の値は、その点の燃焼度で解いた値）。中点の値は
  ログ（tracing）に出す

## 決定と理由

これは ADR-0190 の「`[depletion]` のあるケースは…ホウ素の探索（`search`）もエラー（ステップごとの探索は別の ADR）」の部分と、
「この ADR の範囲の外」の「ステップごとの臨界ホウ素の探索（ADR-0145）」を `steps` の項目として足すという部分を置き換える。ほかの
部分（時間の進め方、ノードの燃焼度の増分、`burnup` を書けばエラー、バンクの位置、出力の形の残りの項目）は変わらない。

### 入力（案 I1、案 B1）

燃焼のケースの状態は、`boron` の代わりに ADR-0145 の `search` を書ける:

```toml
[state.hfp]
b10 = 0.199
moderator = 565
fuel = 565
search = { boron = [0.0, 1300.0], k = 1.0, tolerance = 1.0e-6, max-solves = 20 }

[depletion]
specific-power = 38.41
steps = [{ efpd = 9.0 }, { efpd = 32.0 }]
history = "history.msgpack"
```

範囲、目標、許容、回数の上限の意味と検査は ADR-0145 と同じ（許容が固有値の反復の判定以下ならエラー。解く前に確かめる）。すべての
探索が同じ範囲を使い、範囲がテーブルのホウ素の軸の外ならテーブルの内挿のエラーで止まる。

### 探索する解（案 S2）

燃焼点（0 と各ステップの終わり）と、各ステップの中点の解のすべてで、その燃焼度の分布のまま k が目標になるホウ素濃度を Illinois 法で
探す（ADR-0145）。中点の出力の割合は、中点の燃焼度で臨界にした炉心のもので、ADR-0190 の中点の形の 2 次がホウ素で出力分布の変わる
炉心でも保たれる。1 ステップの固有値計算は、2 回の探索の回数の和になる（ADR-0190 の 2 回から、探索 1 回の回数の 2 倍に増える）。

### 解を挟まない範囲（案 E1）

点でも中点でも、範囲の両端の k が目標を挟まなければ、ADR-0145 のとおりエラーで止める。エラーは、ステップの終わりの EFPD と、点か
中点かを示す。サイクルの終わりで 0 ppm でも k が目標より小さい状態（Problem 9 の最後の 3 状態）は、出力の割合と熱水力（Xe を含む）の
ADR でステップの項目を足すまで扱わない。ケースのステップを、ホウ素が範囲の中に残る EFPD までにする。

### 出力（案 O1）

- 燃焼の履歴（`xlc-core-history`）の点に、`boron`（その点を解いたホウ素濃度、ppm）と `solves`（その点で解いた固有値計算の回数。
  与えた濃度なら 1、探索なら ADR-0145 の回数（両端を含む））を足す
- 履歴の `states`（状態の名前 → 状態。[ADR-0218](0218-give-depletion-steps-power-decay-and-states.md)）の各状態は、`boron`（与えた濃度、ppm）か
  `search`（`{boron: [下端, 上端], k, tolerance, max_solves}`）のどちらか一方を持つ（両方、どちらもない履歴は読むときのエラー）
- 標準出力の点の行は `point <EFPD> <炉心の平均の燃焼度 (MWd/kg)> <k> <ホウ素濃度 (ppm)> <固有値計算の回数>`
- 中点で求めたホウ素と回数は、ログ（tracing の info）に出す
- 履歴は、中点のホウ素の決め方 `midpoint_boron`（`search` か `start`。次の項）を持つ

### 比べるための案 S1 の入力

`[depletion] midpoint-boron = "start"` で、`search` の状態のステップの中点を、ステップの初めの点で探したホウ素濃度で解く（案 S1）。
採用した案 S2 との差を測るためで、省いたとき（`"search"`）は案 S2。`search` の状態を解く出力のステップがないケースに書けばエラー
（効かない入力）。

### 帰結

- 探索のケースは、1 ステップに解く回数が「探索の回数 × 2」になる。探索ごとに範囲の両端を解き直す（ADR-0145 の帰結の、前の評価の
  中性子束から始めない扱いも同じ）。全炉心の燃焼の時間（#0156）で探索の回数が効くと分かれば、範囲の動かし方（案 B2、B3）か
  初期値の受け渡しを測ってから決める
- 中点のホウ素の効き（案 S1 と S2 の差）は、集合体 1 体では 0。小さな炉心で測った差は「確認」の最後の項（案 S1 は比べるための入力の
  項目 `midpoint-boron = "start"` で選べる。既定は案 S2）
- 0 ppm で臨界にならないサイクルの終わり（コーストダウン）は、出力の割合と熱水力の項目を足すまでエラーになる
- 目標の k を燃焼度で変える（ステップごとの目標）は、要るときに `steps` の項目として、状態の `search` を上書きする形で足す

## 変更

- 2026-10-29: 「出力（案 O1）」に履歴の `midpoint_boron` を、「比べるための案 S1 の入力」の節を足した。前は、出力の項目は「中点で求めたホウ素と
  回数は、ログ（tracing の info）に出す」までで、中点のホウ素を選ぶ入力はなかった。帰結の「中点のホウ素の効き（案 S1 と S2 の差）は…炉心では
  測っていない。計画の「進め方」7 の小さな炉心で…測る」の測定に、案 S1 を本番のコードで解く入力が要るため（既定は案 S2 のまま。測った差は「確認」）
- 2026-10-30: 「出力（案 O1）」の履歴の状態。前は「履歴の `state` は、`boron`（与えた濃度、ppm）か `search`（`{boron: [下端, 上端], k, tolerance, max_solves}`）のどちらか一方を
  持つ（両方、どちらもない履歴は読むときのエラー）」。ステップごとに状態が変わり、履歴が状態を 1 つしか持てなくなったため、状態の名前ごとの表
  `states` に移した（各状態の `boron` か `search` の規則は同じ）。比べた案は ADR-0218
