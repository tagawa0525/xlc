# ADR-0224: 制御棒の分岐は、値ごとに基準の形状のセルを置き換えるセルで書き、値ごとに形状を作り直して同じ格子計算で解く

## 背景

[ADR-0097](0097-tabulate-branches-on-a-full-grid.md) は、制御棒の有無を分岐の離散の軸とし、格子計算の入力では基準の形状（制御棒のない集合体）に対する変更（案内管に制御棒を
入れる）として書くと決めた。M4 で、制御棒の分岐を基準の燃焼の組成から瞬時に変えた状態として計算するためである。
[ADR-0127](0127-weight-partially-rodded-nodes-by-axial-fine-mesh-flux.md) は、テーブルの制御棒の軸 `rod` を値の名前の列 `values`（`out` は棒のない状態、ほかは棒の区間の材料の名前）と決め、
core はノードの区間ごとにその値を選ぶ。形式（`xlc-table`）と core はこれを実装したが、格子計算は制御棒の分岐を作れない（#0093）。
制御棒を入れた集合体は別の格子計算の入力で解き、examples/core/rod_table.py が値ごとのテーブルを 1 つにまとめている。

決まっていないのは、格子計算の入力での変更の書き方と、値ごとに違う形状をどう解くかである。

- VERA の制御棒（仕様書の 1.6 節、表 8）は、案内管の中の水を、吸収体（AIC か B4C）、間隙、被覆管（SS304）、水の帯に
  置き換える。吸収体の外半径は AIC 0.382 cm、B4C 0.373 cm で違う（examples/core/assembly-aic.toml と assembly-b4c.toml）。
  集合体の 24 本の案内管すべてに入る（計装管には入らない）
- 軸方向の反射体の上の層（プレナム、上の端栓とギャップ）の制御棒の値は、層の物質を、案内管の中の水を棒に置き換えて体積で
  混ぜた物質に替える。その入力の書き方は、燃料の分岐とそろえて決めると [ADR-0128](0128-make-axial-reflector-constants-in-a-full-height-slab.md) の「制御棒の軸」が残している。平板の層も
  格子のセルである
- 判断の軸: 棒のない状態の離散化を棒の形に引きずられないこと（別の格子計算と同じ問題を解くこと）、燃料の分岐と軸方向の
  平板で同じ書き方を使えること、M4 の燃焼の分岐（[ADR-0200](0200-tabulate-burnup-branches-by-cut-hdmr.md) の制御棒の有無ごとの組）と食い違わないこと

## 検討した案

- 値ごとの別の格子計算の入力のテーブルを、後で 1 つにまとめる（今の examples/core/rod_table.py）: ADR-0097 が、M4 で制御棒の
  分岐を基準の燃焼の組成から作れないので採らないと決めている
- 形状を 1 つにし、値ごとに帯の物質を替える: 基準の形状の案内管の帯を、すべての値の棒の半径（AIC と B4C の吸収体の外半径、
  間隙、被覆管）で前もって分け、値ごとにその帯の物質を水から棒の物質に替える。トラッキングと対称操作の判定が 1 回で済むが、
  棒のない状態の案内管の水が、使わない棒の半径とリングの数で分かれ、別の格子計算の基準の形状（案内管の中の水 3 リング）と
  違う問題になる。棒の型を足すたびに基準の形状のリングが変わり、値どうしで半径の違う帯（AIC の 0.373〜0.382 cm）の扱いも要る
- 値ごとに、基準の形状の行（`rows`）の位置ごとに置き換えるセルを書く: 案内管の一部にだけ棒を入れる形も書けるが、制御棒は
  集合体の案内管すべてに入るので要らず、17 × 17 の行を値ごとに繰り返すと、基準の形状との食い違いを入力の誤りとして
  見つけにくい
- 値ごとに、基準の形状のセルの名前を、置き換えるセルの名前に替える（採用）

## 決定と理由

格子計算の入力の `[branches]` に、制御棒の値ごとに、基準の形状のセルを置き換えるセルを書く。

```toml
[branches.rod]
aic = { gt = "gt-aic" }   # 値 aic: 基準の形状のセル gt をすべてセル gt-aic に置き換える
b4c = { gt = "gt-b4c" }
```

- 値の名前は、テーブルの制御棒の軸の値（ADR-0127。core の炉心の形の制御棒の型の区間が使う名前）になる。軸の値は、棒のない
  状態 `out`（基準の形状）を先に、書いた値を名前の順に続ける。`out` は書けない（基準の形状の値）。`[branches.rod]` は値を 1 つ以上持ち、値ごとに 1 つ以上の
  セルを置き換え、置き換えられるセルは基準の形状の `rows` にあり、置き換えるセルは定義されていて基準の形状の `rows` に
  ないこと（違えばエラー）。置き換えるセルは、物質と帯を自由に書ける普通のセルで、基準の形状のセルと同じ書き方
- 値ごとに、`rows` のセルの名前を置き換えた形状を作り、トラッキング、対称操作の判定、自己遮蔽を値ごとに行う。棒のない
  状態は基準の形状そのものを解き、値 `aic` の状態は、`rows` の gt を gt-aic に書き替えた別の入力と同じ問題を解く。帯の
  物質だけを替える案と違い、棒のない状態の離散化が棒の形に引きずられない。吸収体の自己遮蔽（[ADR-0142](0142-shield-absorber-rods-by-slowing-down.md)）は、棒のセルの形状から
  別の入力と同じく決まる
- 軸方向の平板（ADR-0128）の上の層も同じ書き方で書く: プレナムの層のセルを、層の物質を棒を混ぜた物質に替えたセルに
  置き換える。平板の層の物質を替える別の書き方を持たない
- 連続の軸の状態（直積か部分格子。ADR-0097、ADR-0200）は、どの値でも同じものを解く。解く順は値ごと（`out` から）で、値の中は
  今の順（軸の直積の順）。テーブルの軸は、ホウ素濃度、減速材、燃料の温度に続けて制御棒の軸を最後に置き、点は辞書式の順
  （値が最も速く変わる）に並べる（rod_table.py の出力と同じ並び）
- 標準出力の状態の番号（`state <番号> k`）は、テーブルの軸の直積の順の番号（制御棒の値が最も速く変わる）で、解く順の番号ではない
- MOC の反復を始める解（[ADR-0195](0195-start-moc-from-the-previous-transport.md)）は、値の中でだけ引き継ぐ。値の最初の状態は、形状が違う前の値の解を使わず平らな
  初期値から始める（領域の数が違う。同じ値の状態の並びは、別の入力の格子計算と同じ順と同じ始める解になる）。チェックポイント
  （[ADR-0196](0196-resume-lattice-runs-from-checkpoints.md)）は、値と連続の軸の状態を通した番号で書き、止めた値の途中から続ける
- 細かい群の媒質の出力（ADR-0128）は、棒のない値の状態だけを書き（ADR-0128 の「分岐が離散の軸を持つ格子では、棒も
  支持格子もない値の状態だけを書き」）、媒質を読む平板は、どの値でも媒質の同じ連続の軸の状態を使う（ADR-0128 の「媒質は
  制御棒の軸を持たない」）
- 燃焼の履歴からの分岐（`[history]`。[ADR-0187](0187-tabulate-burnup-branches-from-history.md)）と制御棒の軸は、この ADR では組まない（入力をエラーにする）。M4 の制御棒の
  有無ごとの組（ADR-0200）は、値ごとに形状を作り直して同じ履歴の組成を置けば、この書き方と食い違わない。燃焼の領域
  （燃料のセル）は置き換えないので、履歴の領域と値ごとの形状の燃焼の領域の対応は変わらない見込み（確かめていない。#0213）

### 帰結

- 格子計算は、制御棒の分岐を 1 つの入力で解き、制御棒の軸を持つテーブルを書く。examples/core は、3 つの格子計算と
  rod_table.py の結合を、1 つの格子計算に置き換える
- トラッキングと対称操作の判定は値の数だけ、状態を解く前にすべての値で行う（置き換えたセルの形状の誤りと、強制した対称性が
  成り立たない値を、棒のない状態を解く前に止める）。値ごとのトラッキングは実行の終わりまでメモリに残り、自己遮蔽は値を解き
  終えたら捨てる
- examples/vera/p5 の HZP のテーブル（rod_table.py でまとめた 8 本）と、燃焼の履歴からの分岐の制御棒の組（examples/depletion、
  ADR-0200 の「lattice の入力」の rod_table.py の項）は、まだ rod_table.py を使う。履歴からの分岐に制御棒の軸を入れてから、
  rod_table.py を消す（#0213）
- 軸方向の反射体の上の層の制御棒の値の定数（平板の入力と core の扱い）は #0030 で作る。格子計算の書き方はこの ADR のもの
- 支持格子の分岐（ADR-0097 の「セルの外周に支持格子を足す」）も、セルを置き換える形で書ける見込みだが、決めていない（#0011）

### 確認

- 入力: `rod_branches_replace_cells_of_the_base_rows`、`invalid_rod_branches_are_errors`（crates/lattice/src/branches/tests.rs）
- 結合の形との一致: `rod_branches_match_separate_lattices`（crates/lattice/tests/rod_branch.rs）。2 群の合成のライブラリの
  小さい格子で、制御棒の分岐のテーブルの各状態が、セルを置き換えた別の入力の格子計算の状態とビットで一致する
- VERA の集合体（examples/core の 2G と 2H の定数）: 1 つの入力の制御棒の分岐のテーブルと、3 つの格子計算を rod_table.py で
  まとめたテーブルの比較は examples/core/verification.md
