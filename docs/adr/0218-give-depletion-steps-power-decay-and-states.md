# ADR-0218: core の燃焼のステップに、出力の割合、崩壊だけのステップ、ステップごとの状態を持たせる

## 背景

[ADR-0190](0190-advance-node-burnups-by-midpoint-steps.md) の `[depletion]` は、定格の出力密度 1 つと、ステップの終わりの累積の EFPD だけを持つ。ケースの状態は名前つきの
1 つで、すべてのステップに使う（バンクの位置は書けるが、すべてのステップで同じ）。ADR-0190 は、出力の割合（表 P9-2 の %）、入口の温度、
バンク D の位置、崩壊だけのステップを、`steps` の各ステップの表に後で足す項目とした。出力の割合を入れなかった理由は、燃焼度の増分は
EFPD だけで決まり、出力の水準が効くのは熱水力のフィードバックと Xe で、どちらもまだないことだった。core のミクロ燃焼
（[ADR-0216](0216-tabulate-micro-depletion-cross-sections-per-state.md)）が入り、Xe-135 と I-135 を時間で追うので、出力の水準とステップの時間が結果に効くようになった。部分挿入のノードの
ミクロ燃焼（[ADR-0217](0217-mix-partial-node-micro-cross-sections-by-segment-fluxes.md)）で、バンク D を部分挿入にした燃焼も解ける。

VERA Problem 9（CASL-U-2012-0131-004、86〜90 ページ）のサイクルの追跡に要るのは次の項目:

- 表 P9-2（90 ページ）: 30 の状態ごとの累積の EFPD、サイクルの燃焼度（GWd/MT）、出力（%）、入口の温度（°F）、バンク D の位置（ステップ）。
  燃焼度の列は出力の割合によらず EFPD に比例する（状態 2 は 9.0 EFPD、65.7 % で 0.346 GWd/MT。38.41 W/g × 9.0 日 = 0.3457 MWd/kg）。
  EFPD は定格の出力で換算した日数で、出力の割合をすでに含む
- 表の値はステップの間の平均（87 ページの注 8: 定格に近い主の燃焼は区間ごとの燃焼度で重みを付けた平均）。印 * の 2、3、28、29、30 は、
  起動と停止の間を端点の値で与えた傾き（注 7: 値はステップの終わりの条件で、ステップの平均の出力を保つように選んだ）。端点の値を平均に直した
  値は「計算するか著者から得られる」（表の脚注）
- 表 P9-3（90 ページ）: 運転中の 10 回の停止の EFPD と長さ（日）。最長は 157.2 EFPD の 18.0 日。停止の EFPD は表 P9-2 の点と重ならない
  （157.2 EFPD は状態 12 と 13 の間の 148.4〜163.3 EFPD のステップの中）
- 仕様の本文（86 ページ）: 各ステップは出力、流量、入口の温度、制御棒のバンクの位置などの運転の条件を持ってよく、ステップの間で平均して
  燃焼度の分布とスペクトルの履歴を保つ。後の運転の状態の同位体組成に大きく効かなければ、短い過渡や停止を明示的に模擬しなくてよい

判断の軸:

- 燃焼度の定義を変えない: 燃焼度の増分は定格の出力密度 × EFPD の増分（ADR-0190）。表 P9-2 の EFPD と燃焼度の列がそのまま結ばれる
- 黙った既定を作らない。入力で効かない項目を受けない（CLAUDE.md）
- ADR-0190 の中点の形（2 次）と、ミクロ燃焼の CE/CM（ADR-0216）の 1 ステップの式を、ステップの中で状態が一定のときに保つ
- 表 P9-2 と表 P9-3 の値を、換算せずに入力に書けること

## 検討した案

出力の割合と、ステップの長さの与え方:

- 案 A1: ステップは ADR-0190 のまま累積の EFPD で書き、出力の割合 `power`（定格に対する比）を足す（採用）: 燃焼度の増分は EFPD の増分
  だけで決まり（ADR-0190 の式のまま）、出力の割合はステップの時間（日 = EFPD の増分 / 割合）と出力の水準（ノードの出力密度に割合を掛ける）を
  決める。表 P9-2 の EFPD と出力の列をそのまま書ける
- 案 A2: 燃焼度の増分を「割合 × EFPD の増分」にする: EFPD はすでに出力の割合を含む（定格の出力で換算した日数）ので、出力の割合を
  2 回掛けることになる。表 P9-2 の状態 2 は 9.0 EFPD で 0.346 GWd/MT だが、この案では 0.657 × 38.41 × 9.0 / 1000 = 0.227 MWd/kg になる
- 案 A3: ステップを暦の日数と出力の割合で書き、燃焼度の増分を「割合 × 定格の出力密度 × 日数」にする: 崩壊だけのステップと同じ形
  （割合 0）で書けるが、表 P9-2 の EFPD を日数に直す（EFPD の増分 / 割合。0.657 などで割り切れない）入力になる。EFPD は日数の和になるので、
  ADR-0190 が避けた丸めの積み上げ（テーブルの最後の燃焼度の点を越えて止まる）が戻る

崩壊だけのステップ:

- 案 B1: `{ decay-days = <日> }` の項目（採用）: 出力 0 の日数。ミクロ燃焼の核種（追う核種と補助の核種）を、反応率 0 の行列（崩壊の項だけ）で
  CRAM で進める。燃焼度と累積の EFPD は進まない。ステップの終わりの点を解いて記録する
- 案 B2: `{ efpd = <前と同じ>, power = 0 }` か、A3 の `{ days, power = 0 }`: EFPD が増えないステップを EFPD で書くと、ADR-0190 の
  「EFPD は増える」の検査に例外が要る。A3 は採らない
- 案 B3: 停止を模擬しない: 仕様は、後の同位体組成に大きく効かなければ模擬しなくてよいとする。停止の間に Xe-135、Sm-149、Pu-241、Np-239 などが
  崩壊で動き、効くかは測っていない。B1 は書かなければ停止を模擬しないので、B3 も入力で選べる

`micro` のないケースの崩壊だけのステップと出力の割合:

- 案 M1: エラーにする（採用）: `micro` のないケースは組成を持たないので、崩壊だけのステップで変わるものがない。出力の割合は、燃焼度の
  増分（EFPD だけで決まる）にも、ノードの固有値計算（熱水力のフィードバックがない）にも効かない。効かない項目を受けると黙った無視になる
- 案 M2: 受けて無視する: 黙った無視になる

ステップごとの状態の書き方（バンク D の位置、ホウ素の探索の目標、減速材の温度、燃料の温度）:

- 案 C1: ステップに `state = "<名前>"` を書き、ケースの名前つきの状態（`[state.<名前>]`、ADR-0105、[ADR-0146](0146-solve-named-states-of-a-case-in-parallel.md)）を指す。
  省けば前のステップと同じ（採用）: 状態の検査（`boron` か `search` の一方、ADR-0145 の探索の設定、炉心の形の制御棒のバンクをすべて書くこと。
  [ADR-0127](0127-weight-partially-rodded-nodes-by-axial-fine-mesh-flux.md)）が、燃焼でない状態と同じになる。core は状態ごとに制御棒の並び（`with_banks`）を 1 度だけ作れる。燃焼の履歴は状態を
  名前で引ける。Problem 9 では状態が 30 になり、名前の表が長くなる
- 案 C2: ステップの表に状態の項目（`boron`、`search`、`moderator`、`fuel`、`banks`）を直に書く: 表 P9-2 の 1 行が 1 つのステップの表に
  なり短いが、項目ごとに「省けば前のステップと同じ」の規則が要り、`boron` と `search` の一方、`banks` のすべてのバンクの検査を、
  状態とステップの 2 か所で持つことになる。燃焼でないケースの状態と書き方が分かれる

状態が変わる点（ステップの境）の解:

- 案 P1: 点は、そこで終わるステップの状態で解く: 点の値は、その点までの条件で解いたものになる。次のステップの初めの解（ADR-0190 の
  中点を予測する出力の割合と、ADR-0216 の予測子の反応率）が前のステップの状態の解になり、状態の変わる炉心で、中点の燃焼度と組成の予測が
  状態の差の分（ステップの長さによらない大きさ）ずれる。状態の変わる点ごとに、状態の差に比例する Δ² の誤差が終わりの燃焼度に入る
  （状態が一定のステップの CE/CM の 1 ステップの誤差 Δ³ より 1 次低い）。ステップを細かくしても状態の変わる点の数は変わらないので、全体では
  Δ² で減るが、その係数が状態の差で決まる
- 案 P2: 点は、そこから始まるステップの状態で解く。最後の点は最後のステップの状態（採用）: 各ステップの初めの点、中点、終わりへの修正子が
  すべてそのステップの状態の解で、状態が一定のステップの CE/CM（ADR-0190、ADR-0216）がそのまま成り立つ。解く回数は ADR-0190 と同じ。
  記録する点の k とホウ素は、次のステップの条件の値
- 案 P3: 状態の変わる点で、終わるステップの状態と始まるステップの状態の両方で解く: 記録の点を終わりの条件にでき、予測も正しいが、
  Problem 9 では状態がほぼステップごとに変わるので、解く回数が約 1.5 倍になる（2 × ステップの数 + 1 から 3 × ステップの数 + 1）

## 決定と理由

これは ADR-0190 の「入力（案 P1、案 L1）」のうち「名前つきの状態をちょうど 1 つ持ち、その状態をすべてのステップに使う」「バンクの位置は
書ける（すべてのステップで同じ）」の部分と、「出力」のうち履歴の `state` の部分、「この ADR の範囲の外」の「出力の割合…バンク D の位置」と
「崩壊だけのステップ」を置き換え、[ADR-0191](0191-search-critical-boron-at-each-depletion-solve.md) の「出力（案 O1）」の「履歴の `state` は `boron` か `search` のどちらか一方を持つ」を、
状態ごとの表に移す。ほかの部分（時間の進め方、ノードの燃焼度の増分の式、状態に `burnup` を書けばエラー、点と中点のすべての解で探索する
こと）は変わらない。

### 入力（案 A1、B1、C1、M1）

```toml
[state.s2]        # 表 P9-2 の状態ごとに 1 つ（燃焼でない状態と同じ項目。burnup は書かない）
search = { boron = [0.0, 1300.0], k = 1.0, tolerance = 1.0e-6, max-solves = 20 }
b10 = 0.199
moderator = 565
fuel = 565
banks = { D = 192 }

[depletion]
specific-power = 38.41
history = "history.msgpack"
micro = { chain = "chain.msgpack" }
steps = [
  { efpd = 9.0, power = 0.657, state = "s2" },
  { efpd = 32.0, power = 0.997, state = "s3" },
  { efpd = 157.2, power = 0.951, state = "s12" },
  { decay-days = 18.0 },                         # 表 P9-3 の停止。状態は前のステップと同じ
  { efpd = 163.3, power = 0.951 },
]
```

- ステップは `efpd`（ステップの終わりの累積の EFPD）か `decay-days`（崩壊だけのステップの日数）のどちらか一方を持つ。`efpd` は、それまでの
  `efpd` のステップより大きい（崩壊だけのステップは EFPD を進めない）。最初の `efpd` は 0 より大きい。`decay-days` は 0 より大きい。
  `efpd` のステップを 1 つ以上持つ
- `power` は `efpd` のステップの出力の割合（定格に対する比。0 より大きい有限の値。1 を超えてよい: 表 P9-2 の状態 16、18 は 100.1、100.2 %）。
  省けば 1（定格。ADR-0190 のステップと同じ）。崩壊だけのステップには書けない
- `state` は名前つきの状態の名前。省けば前のステップと同じ。状態が 2 つ以上のケースは、最初のステップに `state` を書く。状態が 1 つなら
  どのステップも省ける。どのステップも指さない状態はエラー（効かない入力）
- `micro` のないケースに、`decay-days` のステップか `power` を書けばエラー（案 M1）

### ステップの解き方（案 P2）

燃焼点 0 は最初のステップの状態で解く。燃焼点 i（i ≥ 1）は、ステップ i + 1 の状態で解く（最後の点は最後のステップの状態）。
`efpd` のステップは、ADR-0190 の中点の形と ADR-0216 の CE/CM のまま、初めの点の解、中点の解（そのステップの状態）、修正子で進める:

- 燃焼度の増分: ADR-0190 の式のまま（定格の出力密度 × 累積の EFPD − 炉心の平均の燃焼度）。出力の割合によらない
- ステップの時間: (EFPD の増分 / 出力の割合) 日
- ノードの出力密度（ミクロ燃焼の反応率の規格化。ADR-0216 の案 P1）: 出力の割合 × 定格の出力密度 × 解の核分裂率の割合 × 炉心の質量 /
  ノードの体積。燃焼度の増分と同じエネルギーを、割合で伸びた時間で出す

崩壊だけのステップは、核分裂のある各ノードの組成を、崩壊の項だけの行列（追う核種と補助の核種。反応率 0）で日数だけ CRAM48（ADR-0173）で
進め、ノードの燃焼度と EFPD を変えない。固有値計算はステップの終わりの点の 1 回だけ（初めの点と中点の解は使わない）。

状態ごとの制御棒の並び（`with_banks`、ADR-0127）とミクロ燃焼のノードの使い方（一様か部分挿入か。ADR-0217）は、解く前に状態ごとに 1 度
作る。どの状態の並びでも、ミクロ燃焼するノード（核分裂のあるノード）は同じ位置であること（違えばエラー。組成は位置ごとに持つ）。

### 表の値（ステップの間の平均）の扱い

core は、ステップの状態と出力の割合をステップの中で一定とし、ステップの初めの点、中点、修正子の解に使う（案 P2）。表 P9-2 の印 * の
端点の値を平均に直すのは入力を作る側で、core は値の意味を区別しない（平均の求め方は Problem 9 の入力を作るときに決める。docs/plans/m4-depletion.md の
「炉心の燃焼」）。入口の温度は熱水力の ADR（計画の「範囲」）の後で、この ADR では状態の減速材の温度（密度はテーブルの減速材の軸の
格子点の組で決まる）を状態ごとに書く形にとどめ、入口の温度からの換算は入れない。

### 出力

燃焼の履歴（`xlc-core-history`）:

- `state`（1 つの状態）の代わりに `states`（状態の名前 → 状態。各状態の項目は ADR-0191 の `state` と同じで、`boron` か `search` の一方を
  持つ）を書く。燃焼で使った状態だけ
- 点ごとに `state`（その点を解いた状態の名前）、`days`（燃焼点 0 からの経過の日数。崩壊だけのステップの日数を含む）、`power`（その点で
  終わるステップの出力の割合。崩壊だけのステップは 0。燃焼点 0 は書かない）を足す。`efpd` は崩壊だけのステップの前後で同じ値になる
- 標準出力の `point` の行は変えない（ADR-0191）

## 帰結

- 表 P9-2 の 30 の状態を、名前つきの 30 の状態と、`efpd`、`power`、`state` を持つステップで書ける。表 P9-3 の停止は、停止の EFPD で
  ステップを分け（両側に同じ平均の値）、間に `decay-days` のステップを入れる。印 * の端点の値を平均に直すのは、Problem 9 の入力を作るときに
  決める
- 記録する点の k とホウ素は、その点から始まるステップの状態で解いた値になる（案 P2）。点の条件と測定の条件の対応（Problem 9 の臨界ホウ素の
  比較）は、Problem 9 の比較のときに決める
- `micro` のないケースは、出力の割合も崩壊だけのステップも書けない。熱水力のフィードバックが入れば出力の割合が固有値計算に効くので、
  その ADR で `micro` のないケースにも開く
- 状態ごとに制御棒の並びとミクロ燃焼のノードの使い方を作るので、解く前の準備が状態の数に比例する。解く回数は ADR-0190 と同じ
  2 × (`efpd` のステップの数) + 1 と、崩壊だけのステップごとに 1（#0156 の時間の見積もりに足す）
- 履歴の変数（[ADR-0215](0215-correct-untracked-history-by-history-branches.md) の減速材の密度と制御棒の挿入の燃焼度で重みを付けた平均）は、このブランチでは進めない（#0190）。ステップごとに
  減速材の温度とバンクの位置が変わるので、ノードごとの履歴の変数を燃焼のステップで進める入力がそろい、#0190 の前提になる。ステップの状態の
  減速材の密度と、ノードごとの制御棒の挿入の割合（ADR-0217 の区間の長さ）を、燃焼度の増分の重みで平均すればよい
- 平衡 Xe（#0193）は、崩壊だけのステップと別の扱い（燃焼のステップは Xe を時間で追う）。崩壊だけのステップは平衡 Xe の入力を決めない
- 燃焼の履歴の形式が変わり（`state` → `states`、点の `state`、`days`、`power`）、今までの履歴のファイルは読めない。examples/depletion の
  比較のツールは新しい形を読む

  ステップしかないケース）、`invalid_depletions_are_errors`（`micro` のないケースの `power` と `decay-days`）
