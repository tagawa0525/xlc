# ADR-0190: core はケースの EFPD のステップに沿って、ノードの燃焼度を中点の出力分布で進める

## 背景

燃焼度の軸を持つ分岐のテーブル（[ADR-0187](0187-tabulate-burnup-branches-from-history.md)）ができ、core は燃焼度を線形に内挿してテーブルを引ける。ただし燃焼度は
ケースの状態（`[state.<名前>]` の `burnup`）が炉心のすべての集合体に与える一様な値で、炉心の燃焼（docs/plans/m4-depletion.md の
「進め方」7）はまだない。計画は、ノードごとの燃焼度と主要な核種の数密度（[ADR-0035](0035-track-history-by-micro-depletion.md) のミクロ燃焼）、集合体ごとの状態
（[ADR-0036](0036-keep-core-state-per-assembly.md)）、時間の進め方（炉心でも予測子・修正子にするか）、サイクルの追跡（表 P9-2 の 30 状態、印 * の端点、崩壊のステップ、
restart）を ADR で決めるとした。

この ADR は、その最初の縦切り（計画の 7 の最初の確認「1 本の集合体で lattice の結果を再現する」）の決定である: ノードの燃焼度を
サイクルのステップに沿って進め、各ステップでテーブルを引いて解く。ミクロ燃焼の核種、崩壊のステップ、restart、ステップごとの
臨界ホウ素の探索（[ADR-0145](0145-search-critical-boron-by-illinois-in-input-bracket.md)）、装荷替え、Xe の扱い、熱水力はこの ADR の範囲の外で、それぞれ別の ADR にする。
入力と出力の形は、それらを後で足せる形にする（足す前提で汎用化はしない）。

前提:

- 燃焼度は初めの重金属（Z ≥ 90）の MWd/kg で、格子計算は一定の出力密度（W/g）で燃焼させる（[ADR-0173](0173-deplete-lattice-pins-by-ce-cm.md)）。重金属の質量は
  ライブラリの AWR から求める。テーブルは燃焼度の点ごとの少数群定数と形状関数を持ち、重金属の質量も、核分裂のエネルギーの断面積
  （κΣf）も持たない
- VERA の表 P9-2（CASL-U-2012-0131-004、90 ページ）は、状態ごとに累積の EFPD、サイクルの燃焼度（GWd/MT）、出力（%）、入口の温度、
  バンク D の位置を与える。441.0 EFPD で 16.939 GWd/MT なので、定格の出力密度は 38.41 W/g（初めの重金属）。出力の履歴は、
  as-built の集合体と仕様の重金属の質量の差（+0.2%）を補うよう規格化し直してある（87 ページの注 5）。表の値はステップの間の平均で、
  印 * の 2、3、28、29、30 は端点の値（注 7）
- core の固有値計算（NEM）の時間: VERA Problem 5 の全炉心の 34 状態を並列に解いて 1,091 秒（examples/vera/verification.md、438a041d、
  2026-10-14、排他のジョブ）。表 P9-2 の 30 状態で解く回数を 2 倍にしても、格子計算のテーブル（計画の見積もりで
  集合体 1 種に約 122 時間）より桁で小さい

判断の軸:

- 正確さ: ステップの大きさに対する誤差の次数。集合体 1 体の一様な出力で、燃焼度が解析的な値（出力密度 × EFPD）に一致すること
- ミクロ燃焼（ADR-0035）を後で足したとき、同じ時間の進め方の枠にそのまま入ること。格子計算（ADR-0173 の CE/CM）と方式が揃うこと
- 黙った既定を作らない。入力で効かない項目を受けない（CLAUDE.md）
- 燃焼度の定義が格子計算の燃焼度の軸と同じであること（燃焼度の軸を引く値なので、定義がずれると内挿の点がずれる）

## 検討した案

時間の進め方（Δ はステップの炉心の平均の燃焼度の増分、s(B) は燃焼度 B のノードの出力の割合から決まる燃焼度の増分の重み。下の
「ノードの燃焼度の増分」）:

- 案 T1: ステップの初めの出力分布で進める陽的な形（B₁ = B₀ + Δ s(B₀)）: 1 ステップに解くのは 1 回（初めの点の解）で、1 次。出力分布が
  燃焼で動く（新しい燃料の出力が下がり、燃えた燃料に移る）炉心では、ステップを細かくしないと燃焼度の分布が初めの分布に引きずられる
- 案 T2: 中点の出力分布（CE/CM の形。B½ = B₀ + Δ/2 s(B₀)、B₁ = B₀ + Δ s(B½)）（採用）: 2 次で、1 ステップに解くのは 2 回（初めの点と
  中点）。格子計算の CE/CM（ADR-0173）と同じ形で、ミクロ燃焼を足すときは、ノードの数密度を同じ 2 つの解の反応率で CE/CM で
  進められる。点の k と出力分布は、その点の燃焼度で解いた値になる（中点の解は点に残さない。ADR-0181 の点の定義と同じ）
- 案 T3: 初めと予測した終わりの出力分布の平均（台形。B₁ = B₀ + Δ/2 (s(B₀) + s(B₀ + Δ s(B₀)))）: 2 次で解くのは 2 回。予測した終わりの
  解は、修正した終わりの燃焼度の解と違うので、点の値に使えず捨てる。ミクロ燃焼では CE/LI（ADR-0173 の案 T3）に当たり、格子計算と
  方式が揃わない
- 案 T4: 終わりの出力分布と燃焼度が一致するまで繰り返す（陰的な形）: 解く回数がステップごとに決まらない。T2 で 2 次なので、
  繰り返しで得る精度を、ステップを細かくして得られる

ステップの出力の与え方:

- 案 P1: 定格の出力密度（W/g、炉心の平均、初めの重金属）と累積の EFPD（採用）: 表 P9-2 の EFPD とサイクルの燃焼度の列が、
  この 2 つでそのまま結ばれる（燃焼度の増分 = 出力密度 × EFPD の増分）。炉心のモデルの重金属の質量が実機と少し違っても（注 5）、
  炉心の平均の燃焼度と EFPD の関係は表と同じになる。格子計算の `[depletion]` の `power`（W/g）と同じ量で、集合体 1 体の確認では
  履歴の燃焼度が解析的に再現される
- 案 P2: 定格の熱出力（MW）と EFPD: 炉心の平均の燃焼度の増分が、モデルの重金属の質量で変わる。実機の運転のデータはこの形だが、
  P1 と同じ情報（MW = W/g × 炉心の重金属の質量）で、要るときに足せる
- 案 P3: 炉心の平均の燃焼度（MWd/kg）の点で書く（格子計算の `[depletion]` の `burnup` と同じ）: 燃焼度の増分は P1 と同じに決まるが、
  時間を持たないので、崩壊のステップ（日）と Xe（時間と出力の水準）を足すときに出力密度と時間の両方が要る。表 P9-2 の主の列は EFPD
- 出力の割合（表 P9-2 の %）: この ADR では入れない。燃焼度の増分は EFPD だけで決まり、出力の水準が効くのは熱水力のフィードバックと
  Xe で、どちらもまだない。効かない項目を受けると黙った無視になる。熱水力か Xe の ADR で、ステップの項目として足す

ノードの重金属の質量:

- 案 M1: 台帳の設計（`[design.<名前>]`）に集合体の重金属の質量を書く: 仕様の値を手でコピーすることになり、格子計算が燃焼度の定義に使う
  質量（ライブラリの AWR と入力の組成から求めた値）と食い違いうる。食い違うと、core の燃焼度とテーブルの燃焼度の軸の定義がずれる
- 案 M2: テーブルに、初めの重金属の質量（高さ 1 cm あたり、g/cm）を持たせ、lattice が燃焼の履歴の燃焼度 0 の数密度、燃焼の領域の
  体積、ライブラリの AWR から、格子計算の燃焼（ADR-0173）と同じ式で書く（採用）: 燃焼度の定義がテーブルと同じになる。テーブル全体で
  1 つの値（分岐の状態と燃焼度によらない）
- 案 M3: ADR-0187 が置き場を決めた、燃焼度の点ごとの均質化した数密度（#0153）から core が求める: まだ書いていない。core が AWR と
  重金属の判定を持つことになる

ノードの出力:

- 案 W1: ノードの核分裂率 Σf φ V の割合（採用）: テーブルの今の項目で求まる。格子計算は Q で重みをつけた Σ N σf φ Q で規格化する
  ので、核種の Q の違い（U-235 193.41 MeV、Pu-239 198.58 MeV、examples/depletion/chain.msgpack）の分だけ、Pu の多いノードの出力を
  小さく見積もる（燃焼度の違うノードが並ぶ炉心で効く。集合体 1 体では割合が 1 で効かない）
- 案 W2: κΣf（Q で重みをつけた核分裂の断面積）の割合: テーブルに状態ごとの κΣf が要り、lattice の出力を変える。#0154 で入れる

入力の置き場所（[ADR-0105](0105-load-core-by-assembly-ids.md) の 4 つのファイル）:

- 案 L1: ケースの `[depletion]` に書く（採用）: ADR-0105 は状態（ホウ素、温度、バンクの位置）をケースに置いた。ステップの列は時間に
  沿った状態の並びで、ケースの状態と同じ置き場になる。サイクル（装荷図）を変えずに、ステップの細かさを変えて比べられる
- 案 L2: サイクルに書く: サイクルは装荷と前のサイクルの状態（restart）の置き場（ADR-0105）。ステップの細かさは計算の選択なので、
  ケースで変えたい

## 決定と理由

### 時間の進め方（案 T2）

ステップごとに、初めの燃焼度 B₀ で解いた出力分布で中点の燃焼度 B½ = B₀ + Δ/2 s(B₀) を求め、B½ で解いた出力分布で
B₁ = B₀ + Δ s(B½) とする（中点の形。ADR-0173 の CE/CM と同じ）。ステップの中の出力は一定（定格の出力密度で、EFPD の増分の間）。
燃焼点（0 と各ステップの終わり）の k、燃焼度、出力分布は、その点の燃焼度で解いた値。1 ステップに 2 回、全体で 2 × ステップの数 + 1 回
解く。

精度の確かめ方: 中点の形が 2 次であることを、出力の割合が燃焼度で変わる 2 ノードの問題（解析的な割合の関数）で、ステップを半分に
したときの誤差の比で単体のテストで確かめる。炉心での誤差の大きさ（ステップの長さの選び方）は、計画の 7 の次の「小さな炉心」で、
ステップを半分にした計算との差で測って決める。集合体 1 体の一様な出力では、割合が 1 なので方式によらず燃焼度は解析的な値になり、
差はテーブルの内挿だけになる（「確認」）。

### ノードの燃焼度の増分

ノード n の初めの重金属の質量 Mₙ (g) は、ノードのテーブルの `heavy_metal` (g/cm) × ノードの高さ (cm)。炉心の質量 M = Σ Mₙ。
ノードの出力の割合 fₙ は、ノードの核分裂率 Σ_g Σf,g φ_g V の割合（案 W1。和が 1）。定格の出力密度 p (W/g) で累積の EFPD が E に
なるステップの、炉心の平均の燃焼度の増分は Δ = p E / 1000 − B̄₀（MWd/kg。B̄₀ はステップの初めの炉心の平均の燃焼度、質量の重み）で、
ノードの燃焼度の増分は Δ fₙ M / Mₙ。ステップの EFPD の差 p (E − E₀) / 1000 を足し合わせる形にしないのは、丸めの誤差がステップの数だけ
積み上がり、テーブルの最後の燃焼度の点で終わるケースがその点をわずかに越えて内挿のエラーになるため（2A の履歴の 40 点で
60.00000000000002 MWd/kg になった）。

- `heavy_metal` を持たないテーブルのノードは燃焼しない。そのノードが核分裂する（どこかの群で Σf φ > 0）ならエラーにする
  （燃焼度の定義の質量がないので推測しない）。反射体と、集合体の設計の核分裂のない層（軸方向の反射体）は燃焼度 0 のまま。どの層も
  質量を持たない集合体はエラー（集合体の燃焼度を定義できない）
- 部分挿入のノード（[ADR-0127](0127-weight-partially-rodded-nodes-by-axial-fine-mesh-flux.md)）の質量は、そのノードの層のファイルのテーブルの値。区間は同じファイルの制御棒の値
- `radial-nodes` が 1 でないケースはエラー（テーブルの質量は格子全体の 1 つの値で、部分ノードごとの質量を持たない）

### 入力（案 P1、案 L1）

ケースに `[depletion]` を足す:

```toml
[depletion]
specific-power = 38.41                          # 定格の出力密度 (W/g、炉心の平均、初めの重金属)
steps = [{ efpd = 9.0 }, { efpd = 32.0 }]       # ステップの終わりの累積の EFPD。0 より大きく増える
history = "history.msgpack"                     # 燃焼の履歴の出力（ケースのファイルのあるディレクトリから）
```

- `[depletion]` のあるケースは、名前つきの状態をちょうど 1 つ持ち、その状態をすべてのステップに使う。状態に `burnup` を書けば
  エラー（燃焼度はノードごとに進める）。ホウ素の探索（`search`）もエラー（ステップごとの探索は別の ADR）。バンクの位置は書ける
  （すべてのステップで同じ）
- 初めの燃焼度はすべてのノードで 0（新しい燃料の炉心）。前のサイクルの状態（restart）は別の ADR
- `pin-powers` と `axial-pin-powers` とは使えない（点ごとのピン出力の出し方は別に決める）
- テーブルの燃焼度の範囲の外に出るノードは、内挿のエラーで止まる（ADR-0187。外挿しない）

### 出力

点ごとの値を、解くたびに標準出力（`point <EFPD> <炉心の平均の燃焼度> <k>`）に出し（後のステップで止まっても、それまでの点が
残る）、終わりに燃焼の履歴のファイル（MessagePack、`format` は
`xlc-core-history`。ADR-0181 の点ごとに値を並べる形）に書く:

- `specific_power`（W/g）、`axial_mesh`（ケースの軸方向の境界、cm）、`assemblies`（集合体の ID。名前の順）、`heavy_metal`
  （`[集合体][軸方向のノード]` の初めの重金属の質量、g。下から）
- `points`: 点ごとに `efpd`、`burnup`（炉心の平均、MWd/kg。質量の重み）、`k`、`assembly_burnups`（集合体ごとの燃焼度。質量の重み）、
  `burnups`（`[集合体][軸方向のノード]`）、`powers`（`[集合体][軸方向のノード]` の出力の割合。炉心の和が 1）

状態を集合体の ID ごと、集合体の中の軸方向のノードの並びで持つのは ADR-0036 の形。`radial-nodes` が 1 なので、集合体の中の向き
（回転）によらない。

### lattice のテーブルの `heavy_metal`（案 M2）

`xlc-table` に `heavy_metal`（初めの重金属の質量、高さ 1 cm あたり g/cm。正の数）を足す。燃焼の履歴からの分岐（ADR-0187 の
`[history]`）は、履歴の燃焼度 0 の点の数密度、燃焼の領域の体積、ライブラリの AWR から、格子計算の燃焼と同じ式（Z ≥ 90 の核種、
AWR × 中性子の質量）で書く。新しい燃料の分岐のテーブル（`[history]` のないもの）と核分裂のないテーブルは、キーを書かない（軸の
`b10` や `density` と同じく、持つテーブルだけが書く項目。nil を書いてキーを省けなくする形（ADR-0129 の `height`）は、どのテーブルにも
意味のある項目のためのもので、燃焼の履歴を持たないテーブルには質量を求める組成の定義（燃焼の領域）がない）。

ADR-0187 の、変える範囲を lattice の外に出さない方針との関係: 質量は燃焼度の定義に要る量で、テーブルの外（台帳）に置くと定義が
食い違いうる（案 M1）ので、lattice を変える。

### この ADR の範囲の外（後の ADR で足す項目）

入力の `steps` の各ステップの表（`{ efpd = … }`）に、次の項目を足す形にする:

- 出力の割合（表 P9-2 の %）、入口の温度、バンク D の位置: 熱水力と Xe の ADR とともに。表 P9-2 の印 * の 5 状態は端点の値なので、
  ステップの平均として使うなら直す（計画の「炉心の燃焼」）
- 崩壊だけのステップ（表 P9-3 の停止、Problem 10 の 30 日）: 日で書く項目（出力 0）。ミクロ燃焼の ADR とともに
- ステップごとの臨界ホウ素の探索（ADR-0145）
- 前のサイクルの状態（restart）と装荷替え: サイクルの置き場（ADR-0105）。燃焼の履歴の最後の点の集合体ごとの状態を読む形にする
- ミクロ燃焼の数密度（ADR-0035、#0153）: 燃焼の履歴の点に、集合体ごと・ノードごとの数密度を足し、時間の進め方は同じ中点の形で進める
- ノードの出力の κΣf の重み（#0154）

## 帰結

- core は `[depletion]` のケースで、ノードごとに燃焼度の違う定数を内挿する（ノードの数だけ内挿する。一様な状態の計算は今のまま）。
  全炉心での内挿と固有値計算の時間は測っていない（#0154 とは別に #0156）
- テーブルの `heavy_metal` は、分岐の入力のライブラリの AWR と ZA から求め直す。履歴の燃焼に使ったライブラリと同じことは、輸送する
  核種の集合でしか確かめられない（ADR-0187 の、ライブラリのデータそのものを段階の deps に頼るのと同じ）。2A では、チェーンの Z で
  選んだ質量とビットで一致した（「確認」）
- ノードの出力の割合は核分裂率で、格子計算の Q の重みと違う（#0154）。集合体 1 体では効かない
- `radial-nodes` が 1 でないケースは燃焼できない。部分ノードごとの質量は、分けたノードの燃焼を扱うときに決める
- テーブルの形式に `heavy_metal` が加わる。履歴から作ったテーブル（ADR-0187 の確認の 2A のものを含む）は、作り直すまで質量を持たず、
  core の燃焼で使うとエラーになる。新しい燃料のテーブルは今のファイルのまま読める

## 確認

- 時間の進め方とノードの増分（crates/core/src/depletion/tests.rs）: `advance_shares_the_core_increment_by_power_per_heavy_metal`、
