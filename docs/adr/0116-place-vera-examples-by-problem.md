# ADR-0116: VERA の例は問題ごとのディレクトリに置き、共有するものと検証の記録は上に残す

## 背景

examples/vera/ には、問題 1（ピンセル）と問題 2（集合体）の入力、2B を元にした ADF と NEM の比較の入力、OpenMC の
参照解、共有のライブラリの入力（xs.toml）、スクリプト、検証の記録が平たく並んでいた（24 ファイル）。M3 で問題 3〜5 の
入力（集合体の種類ごとの格子、炉心、OpenMC のモデル）が加わると、どのファイルがどの問題のものか分かりにくくなる。
検証の記録は、ADR-0115 で今の姿に書き直す（#0057）。

- ファイルがどの問題のものかを、場所で分かること
- 問題をまたいで使うもの（ライブラリ、スクリプト）を重複させないこと
- 問題をまたぐ検証の結果（方位角の奇偶の 1B と 2B など）を、自然に置けること

## 検討した案

- 案 A: 平たいまま。問題 3〜5 でファイルが倍以上に増え、名前の接頭辞でしか問題を見分けられない
- 案 B（採用）: 問題ごとの入力と参照解（OpenMC のピン出力）を p1/、p2/ … に置き、共有のライブラリの入力（xs.toml と、
  追跡しない vera.msgpack）、スクリプト、検証の記録は examples/vera/ に残す
- 案 C: 案 B に加えて、検証の記録も問題ごとに分ける。参照解の作り方、離散化の誤差、自己遮蔽の検証、対称性の結果の多くは
  1B と 2B をまたいで比べるので、どちらかの問題に寄せると、もう片方から探しにくい。ADR と issue が記録を
  examples/vera/verification.md で引いている

## 決定と理由

案 B にする。

- 問題 n の入力と参照解は `examples/vera/p<n>/` に置く。2B を元にした比較の入力（ADF と NEM、真空の辺の集合体）も
  2B と同じ p2/ に置く
- 入力の中のライブラリは `../vera.msgpack` で引く（入力の中の相対パスは、その入力のファイルからのパス）。計算の出力
  （pins-*.msgpack、fg-*.msgpack）は入力と同じディレクトリに書く
- スクリプトは引数でファイルを受け取るので、場所によらない。examples/vera/ に残す
- 検証の記録は examples/vera/verification.md の 1 つにし、題目ごとの節に書く（ADR-0115）

## 確認

約束事なので、確かめるテストはない。置き直したあとで、p1/ と p2/ の入力が解けることを確かめた（#0057）。

## 結果

- 問題 3〜5 の入力は p3/、p4/、p5/ に作る
- ほかの例（examples/branches、split、reflector）は、題目ごとのディレクトリのまま
