# ADR-0146: 1 つのケースに名前つきの状態を複数書いて並列に解き、価値と係数は比較のツールが k の差から求める

## 背景

VERA Problem 5 の零出力試験の量は、ほとんどが状態の違う 2 つの場合の k の差である（仕様書の表 P5-2、P5-6、P5-7。
反応度の差は ρ = (1/k₁ − 1/k₂) × 10⁵ pcm）。

- 制御棒バンクの価値: 1170 ppm の ARO（場合 11）と、バンクを 1 つずつ全挿入した場合 12〜19 の差（8 バンク）
- 微分ホウ素価値（DBW）: ARO の 1291 ppm（場合 2）と 1170 ppm（場合 11）の差をホウ素濃度の差で割る
- 等温温度係数（ITC）: ARO の 560 K（場合 20）と 570 K（場合 21）の差を温度の差で割る（表 P5-7 は pcm/°F）
- D バンクの積分価値: 1230 ppm で D バンクを 0〜230 ステップに置いた場合 22〜32
- 臨界の場合 1〜10 は、k そのものを実測の臨界（1）と比べる。場合 1、2 の臨界ホウ素濃度の探索は別に決める

いまの core は、ケースのファイル 1 つで状態を 1 つ解く（[ADR-0105](0105-load-core-by-assembly-ids.md)、[ADR-0097](0097-tabulate-branches-on-a-full-grid.md)）。NEM の固有値計算は
1 つのスレッドで解く。差を取る 2 つの場合は、状態（ホウ素濃度、温度、バンクの位置）のほかは、炉心の形、装荷、
軸方向のメッシュ、境界の条件、定数がすべて同じでなければならない（違えば差に離散化の誤差の変化が入る）。

判断の軸（ユーザーの優先順位）: 正確さ > 実行の速さ > 保守の容易さ。

## 検討した案

- 案 A: いまの形のまま、場合ごとに別のケースのファイル（Problem 5 で約 32）を書き、比較のツールが出力の k から差を
  取る。core を変えない。メッシュ、境界、サイクルの指定がファイルごとに重複し、書き換えの漏れで場合の間に違いが入り
  うる（比較のツールで全ファイルの一致を確かめれば防げる）。固有値計算は 1 スレッドなので、DVC のステージ（`dvc repro` は
  段階を順に実行する）では場合を順に解く。並列に流すには、場合を流す run shell（[ADR-0122](0122-run-trials-from-committed-inputs.md) で作らない）か、場合ごとの
  Slurm のジョブが要る
- 案 B（採用）: 1 つのケースのファイルに名前つきの状態を複数書く。状態のほかの指定は 1 か所なので、差を取る場合が同じ
  メッシュと境界を持つことが入力の形で保証される。状態どうしは独立なので、1 つの実行の中で並列に解ける（コアの数まで
  速くなる。各状態の解は 1 スレッドの計算なので、結果はスレッドの数によらない）。差は比較のツールが取る
- 案 C: 案 B に加えて、core が差（価値、係数）も求める（入力に状態の組と割る量を書く）。差の定義（どの組か、
  pcm/°F への換算、ITC を両方の温度を動かした差とすること）は Problem 5 の比較の決まりで、core の物理の計算ではない。
  k を十分な桁で出せば、ツールで引いても正確さは変わらない。入力の形と検査が増える
- 案 D: 係数を摂動論で直接求める（随伴の中性子束で 1 次の摂動）。core に随伴の計算がない。仕様書の値は有限の差
  （5 K、121 ppm）で定義されているので、差の非線形を含む直接の差のほうが比べる量に合う
- 案 E: 案 B の状態を 1 つずつ順に解き、前の状態の中性子束から始める。`nem::solve` は初期値を受けず、並列のほうが
  速くなる幅が大きい

## 決定と理由

案 B を採る。

```toml
cycle = "cycle.toml"
axial-mesh = [...]
radial-nodes = 1
boundary = { ... }

[state.aro-1170]
boron = 1170
b10 = 0.199
moderator = 565
fuel = 565

[state.aro-1291]
boron = 1291
b10 = 0.199
moderator = 565
fuel = 565
```

- `[state.<名前>]` に状態を 1 つずつ書く。中身はいまの `[state]`（ホウ素濃度、B-10 の割合、減速材と燃料の温度。
  ADR-0097）。バンクの位置は [ADR-0127](0127-weight-partially-rodded-nodes-by-axial-fine-mesh-flux.md) で状態に書くと決めており、その実装
  （#0063）の形のまま各状態に入る。名前は図の記号と区別できること（台帳の ID と同じ検査）
- `[state]` を書かないケースは、いまと同じく軸のないテーブルで 1 つ解く
- core は状態を並列に解き、名前の順に、状態ごとに `state <名前>` の行に続けて k、漏れ、集合体の核分裂率を出す。k は小数 8 桁で出す（差をツールで取るので、出力の丸めの誤差を ρ で 10⁻³ pcm 以下にし、
  固有値の反復の判定 1e-8 より小さくする。k の誤差そのものは反復の収束で決まり、判定の値より大きくなりうる。その大きさは
  確かめていない）。ログは状態ごとの区間（span）で分ける
- ピン出力（`pin-powers`）は、状態が 1 つ以下のケースだけで書ける（状態が複数ならエラー）。Problem 5 のピン出力の
  比較は初臨界の場合だけなので、状態ごとのファイルの指定は要るまで作らない
- 差、係数、実測値と KENO-VI の値との比較は、Problem 5 の比較のツール（examples/vera/p5/compare_hzp.py）が、core の
  出力の k とケースの状態から求める。ツールは、表 P5-6 の KENO-VI の k から表 P5-7 の KENO-VI の価値と DBW を
  計算し直して一致を確かめ、定義の取り違えを防ぐ

案 A に比べて、場合の間で状態のほかの指定が違うことが入力の形で起こらず（正確さ）、場合を並列に解ける（速さ）。
案 C の差の計算は、比較の決まりを core に入れることになり、正確さを変えずに保守を増やす。

### 帰結

- ケースの `[state]` の形が `[state.<名前>]` に変わる。後方互換は作らない。いまの `[state]` を使う例
  （examples/branches）は書き換える
- ADR-0127 の実装（#0063）がバンクの位置を状態に足すときは、`[state.<名前>]` の各状態に足す
- すべての状態の解（問題と中性子束）を出力まで持つので、メモリは状態の数に比例する
- core の k の出力は小数 8 桁になる（記録の 6 桁の値は変わらない）

### 確認

- 入力（crates/core/src/input/tests.rs）: 名前つきの状態を名前の順に読むこと、誤った状態（項目の欠け、知らない項目、
  図の記号と紛らわしい名前、中身のない `[state]`、名前のない `[state]`）をエラーにすること、状態が複数で `pin-powers` があればエラー
- 炉心（crates/core/src/case/tests.rs）: 複数の状態を並列に解いた k が、それぞれを 1 つずつ解いた k と一致すること
  （したがって価値と係数は、別々に解いた 2 つの k の差と一致する）
- 炉心の 2 × 2 の集合体の小さな問題で、4 つの状態（ホウ素濃度 2 つ、温度 2 つ）を並列に解いた k が 1 つずつ解いた k と
  ビット単位で一致し、1 スレッドと 4 スレッドの k も一致し、範囲の外の状態のエラーがほかの状態の解を止めないこと（f7be71eb、2026-10-12）
- 比較のツール: 表 P5-6 の KENO-VI の k から、表 P5-7 の KENO-VI の価値（8 バンクと合計）を 1 pcm 以内、DBW
  （−10.21 pcm/ppm）を 0.01 以内で再現する。ITC は場合 20、21 の 2 点の差で −3.19 pcm/°F、表 P5-7 は付録 G の
  当てはめで −3.18 pcm/°F（f7be71eb、2026-10-12）
- 3D の全炉心の入力（examples/vera/p5/core-hzp.toml）は、バンクを挿入しない場合の状態だけの骨組みで、炉心の形、
  軸方向の層、定数、バンクの位置は #0092
