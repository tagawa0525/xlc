# ADR-0001: 計算を xs・lattice・core の3ステージのクレートに分け、ファイルで受け渡す

## 背景

ENDF 形式の評価済み核データから出発し、PWR 炉心全体の解析までを自前で行う。核データ処理、格子計算、炉心計算には
それぞれ既存のコードがあり、ステージごとに検証したい。

- ステージごとに単独で検証できること
- 既存コードの出力と差し替えて比べられること

## 検討した案

- ステージごとのクレートに分け、ステージ間はファイルでデータを受け渡す（採用）

計画には、ほかの構成を比べた記録はない。

## 決定と理由

計算を3つのステージに分け、Cargo workspace のステージごとのクレートとして実装する。ステージ間はファイルでデータを受け渡す。

| クレート  | 入力                           | 出力                        | 相当する既存コード |
| --------- | ------------------------------ | --------------------------- | ------------------ |
| `xs`      | ENDF/B-VIII.0                  | 多群断面積ライブラリ        | NJOY               |
| `lattice` | 多群ライブラリ、集合体の仕様   | 少数群定数テーブル          | CASMO, DRAGON      |
| `core`    | 少数群定数テーブル、炉心の仕様 | k_eff、出力分布、燃焼度分布 | SIMULATE, PARCS    |

ステージ間の依存がファイル形式だけになり、ステージごとに単独で検証できる。既存コードの出力（NJOY で作ったライブラリなど）を
差し込んで比べることもできる。

`core` のパッケージ名は `xlc-core` とする（M0 で決めた）。`core` にすると Rust 標準の `core` クレートと衝突するため。

## 確認

構成の約束事で、確かめるテストはない。xs のライブラリを NJOY の出力と比べる例（`crates/xs/examples/compare_njoy_*.rs`）が、
ステージごとに単独で検証できることを使っている。

## 帰結

- ステージのクレートの間の依存は [ADR-0002](0002-keep-stage-crates-independent.md) で決める
- ステージが共有するデータファイルの形式と計算は、共通のクレート（`xlc-format`、`xlc-numeric`）に置く（[ADR-0002](0002-keep-stage-crates-independent.md)、[ADR-0003](0003-extract-shared-computation-on-second-use.md)）
