# ADR-0115: 検証の記録とコードのコメントは、今の姿だけを書く

## 背景

検証の記録（examples/*/verification.md）は、時系列に節を足し、過去の節は書き換えず、誤りは日付つきの注記で直す決まり
だった（CLAUDE.md）。そのため、古くなった測定と、それを打ち消す注記が積み重なり、今の結果がどれかを読み取りにくく
なった（examples/vera/verification.md は 600 行を超え、注記で前の節を打ち消す箇所が多い）。コードのコメントにも、
「以前は〜」「#NNNN の前は〜」のような経緯が残りがちだった。経緯は git の履歴、ADR、閉じた issue にすでにある。

- 今の結果と今の挙動を、すぐに読み取れること
- 過去の測定や判断を、必要なときに辿れること
- 決定の記録（ADR）の意味を変えないこと

## 検討した案

- 案 A: 今のまま（時系列に足し、過去の節は書き換えず、日付つきの注記で直す）。経緯は文書の中で追えるが、今の結果を
  読むのに古い節と注記を読み分ける必要がある
- 案 B（採用）: 検証の記録とコードのコメントは、今の姿だけを書く。経緯は git、ADR、閉じた issue に任せる
- 案 C: 案 B に加えて、accepted の ADR も今の姿に書き直す。ADR は「いつ、何を、なぜ決めたか」の記録で、書き直すと
  決定の時点の根拠が分からなくなる

## 決定と理由

案 B にする。

- **検証の記録**: 題目ごとの節に、今の結果を書く。古くなった測定、誤りの注記、置き換えた設定での結果は、消して書き直す。
  節を分けたり、ファイルを分けたりして読みやすくしてよい。結果ごとに、測ったときの xlc のコミットと日付を書く
  （分からない過去の測定は日付だけ）
- **過去の記録の辿り方**: ADR と issue は、測った数値を引くときに、記録のファイルとコミットと日付を書く（docs/adr/README.md
  の書き方のまま）。記録が書き直されても、`git log -p` やそのコミットの時点の記録で辿れる
- **コードとコメント**: 今の挙動とその理由を書く。以前の挙動や、どの issue で変わったかは書かない（コミットと ADR に任せる）
- **ADR と閉じた issue**: 経緯の記録なので、今の規則（ADR は accepted のあと、誤字、リンクとパスの直し、`status` と
  `superseded-by` の変更だけ）のまま。案 C は採らない

## 確認

約束事なので、確かめるテストはない。CLAUDE.md の「文書」の節にこの規則を書く。

## 結果

- examples/vera/verification.md などの既存の記録は、今の姿に書き直していく（VERA は問題ごとの置き方の変更と合わせて行う）
- 記録の中で、ある節がほかの節の数値を打ち消す注記は、今後は書かない
