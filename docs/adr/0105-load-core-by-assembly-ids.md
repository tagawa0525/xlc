# ADR-0105: 炉心の装荷図には集合体の ID を置き、炉心の形、集合体の台帳、サイクルの装荷、計算のケースを別のファイルに書く

## 背景

core の入力は1つの少数群定数で均質な直方体しか書けず、種類の違う集合体と反射体を並べられない（#0031）。実務では
集合体をサイクルごとに動かす（シャッフリング）ので、同じ集合体を初装荷から取り出しまで同じ ID で追う必要がある
（2026-10-09 のユーザーの指摘）。M3 は初装荷の HZP で燃焼を扱わないが、M4 で形式を作り直さないように、ID を軸にする。

- サイクルをまたいで同じ集合体を同じ ID で追えること
- 書き誤り（重複、未定義、層とメッシュのずれ）を推測せずにエラーにできること
- xlc の lattice の入力（`rows` に名前を並べる）と書き方がそろうこと

## 検討した案

位置と集合体の結び方:

- 装荷図に集合体の種類を置く（PARCS の `rad_conf` と `assy_type`。マニュアルは手に入らず、記憶による）: 燃焼した
  集合体を次のサイクルで動かすと、同じ集合体として追えない
- 装荷図に前のサイクルの位置のラベルを置く（VERAin の `shuffle_label`。`L-10`、`2:H-08` のように、ユニット:サイクル
  と前の位置を書き、新燃料は `+F32`。組成は前のサイクルの restart から位置で引き継ぐ。VERA Training, Full Core
  Examples、26〜31 ページ、https://vera.ornl.gov/wp-content/uploads/2023/10/4_Full_Core_Examples.pdf ）: 前の位置の
  チェーンをたどるので、プールに置いて何サイクルも後に戻した燃料ではチェーンが長くなる
- 装荷図に集合体の ID を置き、ID ごとの設計を台帳に書く（採用）。商用の炉心計算は集合体の製造番号で追うと記憶して
  いるが、一次資料では確かめていない

その他の書き方:

- 対称: VERAin は 1/4、1/8 の図を書いて展開できる。全炉心だけ（採用）なら展開の誤りが入らない。ソルバで対称を
  使うかは別に決める
- 反射体: VERAin はバッフルを形状で書く（MOC で直接解くため）。ノード法では反射体のノードが要るので、装荷図に
  反射体の種類を置く（採用）
- 軸方向: VERAin は `axial ASSY 6.053 GAP 10.281 PLUG …` と高さと断面の名前を交互に書く（VERA Training,
  3D Assemblies、https://vera.ornl.gov/wp-content/uploads/2023/10/3_Single-Assembly-3D.pdf ）。同じ中身を、境界の
  高さと層ごとのファイルの2つの配列にする（採用）。面ごとに組成を並べる形（PARCS）は層の境界が読みにくい
- 軸方向のメッシュ: 自動の分割より、明示して層の境界がメッシュに乗っていなければエラーにする（採用。推測で割らない）

## 決定と理由

入力は、変わる頻度で4つのファイルに分ける（2026-10-09 のユーザーの提案。反射体と 193 体の位置はサイクルを通じて
ほとんど変わらず、軸方向のメッシュや集合体の分割は計算のケースによって変わる）。実行するのはケースのファイルで、
ケースがサイクルを、サイクルが炉心の形と台帳を指す。パスは、それを書いたファイルのあるディレクトリから辿る。

炉心の形（例: `plant.toml`。プラントでほとんど変わらない）:

- `pitch`（集合体のピッチ、cm）、`height`（炉心の高さ、cm）
- `[reflector.<名前>]`: 反射体の種類（バッフル、水など。ID で追わない）。`bounds`（軸方向の層の境界の高さ、cm。0 から始まり増え、最後が
  `height`）と `layers`（層ごとの少数群定数のファイル。`bounds` より1つ少ない）。核分裂する層を持てばエラーにする
  （燃料は、燃焼を扱わない試験の問題でも ID を付けて台帳に書く）
- `map`: 上の行（+y）から、位置ごとに `*`（集合体を装荷する位置）、反射体の種類の名前、`-`（ノードを置かない
  位置）を空白で区切って並べる。全炉心で書く。反射体の名前にも `@90` のように回転を添えて、燃料に面する辺の向きを
  合わせられる。`-` に面する面の扱い（外形に沿った境界）は #0034 で決め、それまでは
  `-` をエラーにする

台帳（例: `assemblies.toml`。サイクルをまたいで追記していく）:

- `[design.<名前>]`: 集合体の設計。`bounds` と `layers` は上と同じ
- `[assembly.<ID>]`: `design`（設計の名前）。ID は利用者が付ける文字列で、台帳の中で一意（TOML の表のキーなので
  重複は読み込みのエラーになる）。燃焼の状態（M4）は ID ごとに、集合体の自分の座標系で持つ。集合体ごとの項目
  （バッチ、製造の情報など）は、使う機能を作るときにこの表に足す

サイクル（例: `cycle-1.toml`。サイクルごとに変わる）:

- `plant`（炉心の形のパス）、`inventory`（台帳のパス）
- `loading`: 炉心の形の `map` と同じ行と列で、`*` の位置に集合体の ID を、ほかの位置に `.` を置く。ID の後ろに `@90`
  のように反時計回りの回転（0、90、180、270）を添えられる。回転は辺ごとの量（ADF、真空の辺の比、f* の印）を回す。
  集合体の中の燃焼度の傾きの向きは、主にどの象限のどの位置に移すかで選ぶが、回転もあって困るものではないので
  入れておく（2026-10-09 のユーザーの判断）

ケース（例: `hzp.toml`。計算ごとに変わる）:

- `cycle`（サイクルのパス）
- `axial-mesh`（軸方向のノードの境界の高さ。0 から始まり増え、最後が炉心の高さ）
- `radial-nodes`（集合体1体を各方向に何個のノードに分けるか）。ADF は1ノードの問題で定義している（ADR-0103）ので、
  分割したノードの ADF を決めるまで（#0033）1 以外をエラーにする
- `boundary`（今の6面の書き方のまま。対称面で切るかどうかはケースで選ぶ）

次は読み込みでエラーにする: 同じ ID が2か所にある、台帳にない ID、台帳にない設計、`*` と `.` の位置が炉心の形と
合わない、行の長さの違い、層の境界が `axial-mesh` に乗っていない（同じ数で書く）、層の最後やメッシュの最後が炉心の
高さと違う、知らない回転。

あとで足すものと置き場所（入れるときに形式を作り直さないように、いま置き場所を決める）:

- 制御棒の位置とバンク（`rods`）: 炉心の形。RCCA は位置に固定される
- 支持格子（`grids`）: 設計（台帳）。集合体の設計で決まる
- 可燃性毒物棒などの挿入物（`inserts`）: サイクル
- 状態（`[state]`。ホウ素濃度、温度、バンクの位置）: ケース。分岐のテーブル（ADR-0097）と一緒に入れる
- 前のサイクルの燃焼の状態（restart）: サイクル。M4 で入れる
- 対称（1/4 などで解く）: ケース。入力の図は全炉心のまま

## 確認

- 読み込みのテスト（crates/core/src/input/tests.rs）: 上のエラーのそれぞれ、回転で辺の量が回ること、装荷図と層から
  ノードごとの物質が正しく並ぶこと、反射体の層の核分裂をエラーにすること（6ced2c9、7bda1ce）
- M0 の均質な炉心、VERA の 9 × 9 の1ノード、反射体の I 型（等価性と f* の方法）を4つの入力に書き換え、前の入力や
  ライブラリの API で組んだ問題と k が一致した（examples/m0、examples/vera、examples/reflector の verification.md）

## 結果

- 装荷図の位置は ID で、設計は台帳でたどれる。シャッフリングではサイクルの `loading` の ID の並びだけを変える
- 炉心の外形に沿った境界と、燃料に接しない反射体の定数は #0034 で扱う
