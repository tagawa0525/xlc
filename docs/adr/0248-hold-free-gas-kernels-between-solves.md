# ADR-0248: 自由ガスの核の区間と D の値を減速計算の間で持ち、持つ区間に両端の格子点を持つ

## 背景

ADR-0213 は、自由ガスの核の D の散乱源の区間と 2 次式を、1 回の減速計算の中で最初のスイープに作って持ち、2 回目以降のスイープは
積分だけに使うようにした。持つ形は形 C2（両端と 2 次式の係数の 40 B）で、区間の両端の格子点は積分の前に `locate_from` で探し直す。
形 C3（両端の格子点の u32 を 2 つ足した 48 B）とは「探し直しの手間は、C3 と比べて測っていない」とした。減速計算（自己遮蔽のピン、
自己遮蔽の呼び出し）の間では、区間と D を作り直す。

2A の本番の形のテーブル（#0278）の 1 状態の内訳（#0180 の「2A の本番の形のテーブルの自己遮蔽の内訳（2 回目。厳密なまま減らせる
計算）」。Slurm 764 の debug のログ、1 本のピンの 1 回目の自己遮蔽、39 本の平均）では、自由ガスの散乱源 15.7 スレッド秒のうち、
2 次式の作成（核の評価 `Gas::correction` 4,824 万回 × 117 ns）が 5.66 秒、持った区間の積分（2 スイープ）が 8.62 秒で、区間とリングの
組の積分 1 回あたり、作った区間（格子点は作るときに探した値）は 29 ns、持った区間は 46 ns だった。

区間と D は、自由ガスの核種の核（`Gas::bits`）、範囲の上端、格子の最後の点、区間の細かさと、出射の格子点のレサジーとエネルギーだけで
決まり、弾性散乱断面積（ピンの間引いた格子で補間する）、個数密度、中性子束、ほかの格子点に依らない（`Gas::cells`、`Gas::correction`）。
ピンの間引いた格子は組成で違う（ADR-0185）ので、同じ格子点がどれだけ重なるかを DEBUG のログ（`UFG free-gas evaluations`）で数えた
（#0180 の「3 回目」の節。Slurm 768 の 3 燃焼点の入力）: 1 回の自己遮蔽の核の評価のうち、ほかのピンと同じ格子点の評価は 0.5、32、
60 MWd/kg で 96.2%、89.8%、88.8% で、同じ状態の摂動の自己遮蔽の評価のうち、それより前の自己遮蔽に無い格子点の分は 0.0008%、0.41%、
0.37% と、ほぼすべて公称と重なる。燃焼点の間は、1 回の自己遮蔽の重ならない評価のうち前の燃焼点にもあった分が 10%（32 MWd/kg）、
25%（60 MWd/kg）だけ。

判断の軸は ADR-0213 と同じ: 結果をビットで変えない（近似ではない）、増えるメモリがピンの数で決まらない、持つ量は機械から決まる。

## 検討した案

減速計算の間で持つもの:

- 案 A: 持たない（今のまま）
- 案 B: 格子点ごとの区間と、その両端と中点の D（`Gas::correction` の値。1 区間 40 B）を、核と格子点のビットを鍵に、自己遮蔽の前処理
  （`ShieldingReuse` の `ShareCellCache`。ADR-0213 の案 F と同じ置き場）に持ち、ピンと塊と自己遮蔽の間で共有する。σs × D の
  2 次式は、減速計算が自分の弾性散乱断面積の補間を D に掛けて作る（作るときと同じ積なのでビットで同じ）。表を引けなかった減速計算は
  ロックの外で作って入れ、同時に作った減速計算は先に入れた方を使う（ADR-0213 の ShareCell と同じ）
- 案 C: 2 次式（σs × D）を持つ。σs がピンの格子で違うので、同じ格子点でもピンの間で使えない。採らない
- 案 D: 自己遮蔽の始めに全ピンの格子を作り、格子点の和集合の D を先に求めてから解く。最初の 32 本のピンが同じ格子点を同時に作る分
  （案 B ではそれぞれが作る）も減らせるが、ピンの格子の作成を減速計算の外に出す構造の変更になる。案 B の結果を見て決める
  （「帰結」）

案 B の量の上限:

- 上限なし: 1 回の自己遮蔽で重ならない格子点の区間は 60 MWd/kg で約 1 億（4 GB）で、間引かない格子や重なりの少ない問題では、
  ピンの数とともに増えうる。採らない
- ADR-0213 の全体の量を、同時に解く減速計算の数 + 1 で分け、表に減速計算 1 つの分を充てる（採用）: 表も、同時に解く減速計算と同じく
  全体の量から分ける。2A（32 スレッドで 39 本）は全体の量 64 GB ほどから 1.9 GB で、60 MWd/kg の重ならない区間の半分ほど
- 捨て方（上の 4 つは、自己遮蔽の始めに前の自己遮蔽で使わなかった格子点を捨てる）:
  - 上限に届いても捨てない（Slurm 769 の版）: 前の燃焼点の摂動の自己遮蔽で使った格子点が次の燃焼点に残り、燃焼点の間の重なりは
    10〜25% なので、次の燃焼点の格子点を締め出す（2 回目のレビューの指摘。3 燃焼点の入力では測っていない）
  - 上限に届いたら、今の自己遮蔽で使っていない格子点を捨てる（Slurm 771）: 摂動の自己遮蔽で、後に解くピンがまだ使う公称の格子点を
    捨て、60 MWd/kg の摂動で表から引いた格子点が 65 万から 38 万に減った。採らない
  - 上の捨て方を、今の自己遮蔽で表から引けた格子点が上限で入れなかった格子点より多くないときに限る（Slurm 772）: 同時に始める
    32 本のピンが、どれも引く前に入れられない格子点を出しうるので、1 状態の摂動で 43 万に減った（3 燃焼点の入力の 2 つ目からの摂動は
    64.5 万、65.0 万）。数え方の競り合いで決まるので採らない
  - 上限に届いたら、自己遮蔽ごとに 1 度、前の自己遮蔽より前に入れて今の自己遮蔽で使っていない格子点を捨てる（xlc fbc1fcbef〜78073aee0。
    時間は測っていない）: 燃焼点の境を自己遮蔽の呼び出しの順（公称、摂動）から推すので、本番の形のテーブルのように 1 つの燃焼点で
    多くの状態（ホウ素、減速材、燃料の温度の分岐で 114）と摂動を解くと、同じ燃焼点の格子点を 3 つ目の自己遮蔽から捨てうる。
    呼び出しの順を変えると、効きが黙って変わる。採らない（6 回目のレビューの指摘。親の決定 2026-11-12）
  - 格子点を最後に使った燃焼点で数え、燃焼点の境を呼び出し側が渡す（採用）: 燃焼点の境で、直前の燃焼点で使わなかった格子点を
    捨てる（直前の燃焼点で使った格子点は、燃焼点の間の重なりとして残す）。同じ燃焼点の中では、自己遮蔽がいくつあっても捨てず、
    上限に届いたら、燃焼点ごとに 1 度、今の燃焼点で使っていない格子点（前の燃焼点のもの）を捨てる。呼び出しの順に依らない
  - 使った順の LRU で上限まで持つ形: 摂動の自己遮蔽では、上限で持てない格子点を入れるたびに、まだ引いていない公称の格子点を
    追い出し（上限より大きい順の走査で LRU が外す形）、得が小さい

持つ区間の形（ADR-0213 の形）:

- 形 C2 のまま（ADR-0213）
- 形 C3（採用）: 作るときに探した格子点（`locate_from` は起点によらず `locate` と同じ格子点。
  `locate_from_finds_the_point_of_locate_from_any_hint`）を区間に持ち、積分で使う。1 区間 40 → 48 B。2A の 1 本のピン（2,300 万区間）で
  0.92 → 1.10 GB
- 両端の格子点を区間の始まりの格子点からの差（u16 など）で持つ: 間引かない格子と下端の側の広い区間で桁が変わり、収まらない区間の
  扱いが要る。形 C3 の 8 B を 4 B ほどにするだけで、採らない

## 決定と理由

案 B（全体の量を同時に解く減速計算の数 + 1 で分けた上限、呼び出し側が渡す燃焼点の境で直前の燃焼点で使わなかった格子点を捨て、
上限に届いたら今の燃焼点で使っていない格子点を捨てる）と形 C3 にする。

- 表は `ShareCellCache` の中の `KernelCache` で、核の鍵（自由ガスの核種のすべての `Gas::bits`、範囲の上端、格子の最後の点、区間の
  細かさのビット、D を評価しない核種の印）ごとの、格子点（レサジーとエネルギーのビット）から区間と D の値と、最後に使った燃焼点の
  番号への表。上限は、燃料の自己遮蔽がピンを解く前に `KernelCache::start` と `KernelCache::limit` で決める。前の自己遮蔽から残った表（大きさ B）は全体の量の中に入れ、
  新たに確保できる量（`hold_total`）は、`ufg-hold-memory` があればその量 − B、無ければ使用可能メモリ + B（表は使用可能メモリを
  減らしているので足し戻す）からの全体の量 − B。上限は、表を使うリングの中性子束の移行（既定。ADR-0207）で
  (新たに確保できる量 + B) / (同時に解くピン + 1)（`ufg::kernel_cap`）、表を使わない無限希釈の形の移行と、解くピンの無い自己遮蔽で B（増やさない）。上限が B より小さくても、今の燃焼点で使った格子点は捨てず、増やさないだけにする
  （使用可能メモリが表の分だけ減るたびに捨てると、公称の後の摂動が空の表から始まる。4 回目のレビューの指摘）。前の燃焼点の格子点は、
  今の燃焼点の格子点を入れようとして上限に届いたときに捨てる。ピンの 1 回の量は
  `held_cells(新たに確保できる量 − 増えうる量, 同時に解くピン)`、塊は `held_cells(新たに確保できる量 − 増えうる量, 棒の塊)`（増えうる量は上限 − B か 0。塊は
  ピンの後に同じ表を使う）で、表とピンと塊を合わせて全体の量まで
- 燃焼点の境: 自己遮蔽の前処理（`ShieldingReuse::at_point`）に呼び出し側の燃焼点の番号を渡し、直前と違えば
  `KernelCache::next_point` が表を次の燃焼点に進める。分岐のテーブル（main.rs）は状態の燃焼度の点（`HistoryBranches::point_of`。
  状態の参照と数密度の微分の摂動の組成は状態の点。履歴からの分岐でない分岐の状態はすべて 1 つの点）、燃焼（depletion.rs）は点の
  輸送ごとに 1 つ（続く中点の輸送は同じ点）。渡さない呼び出しは、すべてを 1 つの燃焼点とする（上限まで捨てない）
- 上限に届いて前の燃焼点の格子点を捨てる間、同時に余地を確かめるほかの減速計算は、捨て終えるまで待って余地を確かめ直す（待たずに
  余地が無いとすると、捨てた後の余地に入れ損ねる。6 回目のレビューの指摘）
- 持ち続ける期間: 表は自己遮蔽の前処理にあり、自己遮蔽の間（輸送の MOC の間も）持ち続ける。ADR-0213 の「スイープを終えたら捨て」は、
  1 回の減速計算の中で持つ区間と 2 次式（形 C3）のことで、それは変えない。表は減速計算の外の別の量で、その大きさを次の自己遮蔽の
  全体の量（`ufg-hold-memory` か使用可能メモリからの量）の中に数える（親の決定 2026-11-12。「確認」のテスト）。MOC の間は、上限
  （全体の量の 1 /(同時に解くピン + 1)）までの表が残る
- 個数密度がちょうど 0 の核種: 自由ガスの散乱源は、個数密度が 0 のリングを積分せず、どのリングでも 0 の核種は D を評価しない。0 は
  符号つきの 0 しか足さないので、散乱源はビットで同じ。核種の区間は並びから外さない（外すと、ほかの核種の区間の塊の分け方と和の
  順が変わる）。表の核の鍵に D を評価しない核種の印を足し、その核種に個数密度のある減速計算と表を分ける。0 でない微小な値（CRAM の
  誤差の水準）の扱いは #0280
- 表の大きさは、格子点ごとに配列の確保した大きさと、`KernelPoint` と表の項目（鍵、番号、`Arc` の参照の計数）で数える。`HashMap` の
  空きの枠は数えない
- 持つ区間の格子点は u32 で持つ。格子点の数が u32 を超える格子では区間を持たない（作り直す。結果は同じ）。間引かない格子でも
  127 万点ほどで、届かない
- 理由: どれも結果はビットで同じ（テーブルの md5 と k が main と同じ。「確認」）で、1 状態の時間は形 C3 で −1.2%、表と合わせて
  −4.6%（60 MWd/kg、Slurm 769 の版）、燃焼点で捨てる版と 0 の核種を飛ばす直しを合わせて −9.4%（Slurm 776）。表は 2A で 1.9 GB、
  形 C3 は持つ区間の 2 割で、どちらも全体の量の中

### 帰結

- 2A の 60 MWd/kg の 1 状態の MaxRSS は 44.1〜44.2 → 51.5〜51.6 GB（Slurm 776。表 1.9 GB と形 C3 の 2 割の増え）。どちらも全体の量の
  中で、上限は ADR-0213 のまま
- 表の上限が 60 MWd/kg の重ならない区間の半分ほどで、公称の自己遮蔽は格子点の 59〜62%、摂動の自己遮蔽は 83% を表から引く（Slurm 776。
  上限が足りれば、摂動はほぼすべてを引ける）。上限の充て方を変えるか、案 D にするかは、測った値（#0180）を見て決める
- 最初の 32 本のピンは同じ格子点を同時に作るので、1 回目の自己遮蔽の中の重なり（89〜96%）の大半は減らない（案 D の対象）
- 全体の量で区間を持ち切れない問題では、持てる区間が形 C2 の 1/1.2 に、ピンの 1 回の量が同時に解く数 / (数 + 1) に減る
- 燃焼点の間の重なり（10〜25%）は、直前の燃焼点で使った格子点のうち、今の燃焼点の格子点が上限に届く前に引いたものだけが使える
