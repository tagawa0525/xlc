# ADR-0220: core のサイクルの燃焼は、前のサイクルの燃焼の履歴の最後の点から集合体の ID で状態を引き継ぎ、装荷替えは装荷図の ID と回転で書く

## 背景

core の燃焼（[ADR-0190](0190-advance-node-burnups-by-midpoint-steps.md)、[ADR-0216](0216-tabulate-micro-depletion-cross-sections-per-state.md)、[ADR-0218](0218-give-depletion-steps-power-decay-and-states.md)、[ADR-0219](0219-solve-cycle-depletion-xenon-at-equilibrium.md)）は、すべてのノードの燃焼度 0 とテーブルの燃焼度 0 の
組成（新しい燃料の炉心）から始まる。VERA Problem 10（CASL-U-2012-0131-004。docs/plans/m4-depletion.md の「対象の問題」）はサイクル 1 の
燃焼（Problem 9）の後、30 日の停止を挟んで、新しい燃料 84 体と残る集合体を並べ替えたサイクル 2 を解く。計画の「進め方」7 の残りの
「restart と装荷替え」で、Problem 10 に要る。

決まっていること:

- 前のサイクルの状態（restart）の置き場はサイクルのファイル（[ADR-0105](0105-load-core-by-assembly-ids.md) の「あとで足すものと置き場所」）。形は、燃焼の履歴の最後の点の
  集合体ごとの状態を読む（ADR-0190 の「この ADR の範囲の外」）
- ノードの状態は集合体ごとに持ち、集合体に結びつけて保存する（[ADR-0036](0036-keep-core-state-per-assembly.md)）。装荷図の位置には集合体の ID と回転（`@90` など）を置き、
  シャッフリングは ID の並びだけを変える（ADR-0105）。ADR-0036 の帰結は装荷替えを「実機のデータ（BEAVRS など）と比べる段階で入れる」としたが、
  Problem 10 に要るので今入れる
- 燃焼の履歴（`xlc-core-history`）は、集合体の ID（名前の順）、軸方向のメッシュ、ノードの初めの重金属の質量、点ごとのノードの燃焼度と、ミクロ燃焼なら
  追う核種の名前と点ごとの追う核種の数密度を持つ（crates/core/src/depletion.rs の `CoreHistory`、`CorePoint`）

コードで確かめた事実（crates/core/src/depletion.rs、crates/core/src/micro.rs、crates/core/src/input.rs。main の 3fa838e1）:

- ミクロ燃焼はステップの間で、追う核種と補助の核種（追う核種へチェーンの崩壊で流れ込む、生まれうる核種。2A の 31 核種のチェーンで 143。ADR-0216）の
  全部を持ち越す（`deplete` の `densities` は `MicroChain::solved` の順の数密度）。履歴の `densities` は、そのうち追う核種だけを書く（`MicroChain::tracked`）。
  初めの組成は、テーブルの燃焼度 0 の追う核種の数密度で、補助の核種は 0（`MicroChain::initial`）
- ステップの炉心の平均の燃焼度の増分は、定格の出力密度 × 終わりの累積の EFPD / 1000 から、今の炉心の平均の燃焼度を引いた値（ADR-0190 の「ノードの燃焼度の
  増分」。丸めを積み上げないため）。燃焼度 0 から始まる炉心でしか、累積の EFPD の燃焼度と炉心の平均が一致しない
- ステップの入力は、最初の `efpd` が 0 より大きいことと `efpd` のステップを 1 つ以上持つことを求め、崩壊だけのステップ（`decay-days`）を最初に置くことは
  止めない（`DepletionInput::new`。ADR-0218 の「入力」も最初のステップの種類を決めていない）
- 平衡 Xe の燃焼（ADR-0219）は、燃焼点 0 と崩壊だけのステップの後の点を、組成を時間で進めた値のまま解く。出力のステップの終わりの点では、平衡に置き換えた
  組成（`equilibrate` の返す組成）が点の組成として履歴に入り、次のステップの初めの組成になる

判断の軸（CLAUDE.md の「方針」）: 入力で選べる形にする。黙ったフォールバックを作らない（怪しい入力は推測せずにエラーにする）。後方互換を作らない
（形式を変えたら古い形式を読まない）。同じ装荷の restart は、1 つのケースで続けて燃焼させた結果と丸めの範囲で一致すること。

## 検討した案

restart の入力:

- 案 R1: サイクルに `restart = { history = "<前のサイクルの燃焼の履歴>", fresh = ["<新しい集合体の ID>", …] }` を書く（採用）: 履歴のパスはサイクルの
  ファイルのあるディレクトリから（ADR-0105 のパスの規則）。読むのは履歴の最後の点
- 案 R2: 履歴の点を番号か EFPD で選ぶ: 最後の点でない点から続けると、その後の点の燃焼が履歴に残ったまま別のサイクルを始めることになる。
  サイクルの途中で装荷を変える運転はなく、要るときに足せる
- 案 R3: 前のサイクルの状態を、履歴と別の restart のファイルに書く: 履歴の最後の点と同じ量を 2 か所に書く。下の「補助の核種」のとおり、履歴に足すのは
  最後の点の補助の核種だけで済む

装荷図の ID と履歴の ID の対応:

- 案 I1: `loading` にあって履歴にある ID は状態を引き継ぎ、履歴にない ID は新しい燃料（テーブルの燃焼度 0）、履歴にあって `loading` にない ID は取り出した
  集合体: ID の書き誤りは台帳で止まるが、台帳にあって前のサイクルの履歴にない ID（2 サイクル以上前に取り出してプールに置き、戻した集合体。ADR-0105 の背景）
  も黙って新しい燃料になる
- 案 I2: I1 の新しい燃料を `fresh` に明示させる（採用）: 履歴にも `fresh` にもない ID、両方にある ID はエラー。戻した集合体は、その集合体の最後の
  サイクルの履歴を読む形（帰結）が要るまで、黙って新しい燃料にならずに止まる
- 案 I3: 台帳の集合体ごとの項目（バッチ、装荷したサイクル）から新しい燃料を判断する: 新しいかはサイクルごとに変わる（ADR-0105 の台帳はサイクルを
  またいで追記する）ので、サイクルのファイルの方が置き場に合う

集合体の設計と履歴の対応:

- 案 D1: 履歴に集合体の設計の名前を書き、台帳の設計と比べる: 名前が同じでもテーブルを作り直せば中身が違い、名前が違っても同じテーブルを指しうる
- 案 D2: 引き継ぐ集合体のノードごとの初めの重金属の質量（今のテーブル × ノードの高さ）が履歴の `heavy_metal` とビットで同じことを求める（採用）:
  燃焼度の定義の質量（ADR-0190）が同じであることを直接確かめる。同じ質量の別の設計（挿入物を抜いた集合体など）は通り、それでよい（燃焼度と
  組成は燃料の量で、挿入物の有無はテーブルが持つ）

補助の核種（追う核種へ崩壊で流れ込む核種）:

- 案 A1: restart で補助の核種を 0 に戻す（今の初めの組成と同じ）: 停止の前の Pm-149（半減期 53 時間。停止の間に Sm-149 になる）と、30 日の停止で
  消えない補助の核種（Nd-147 の 11 日、Pm-147 の 2.6 年。Sm-147 へ）が抜け、restart の燃焼は続けて解いた燃焼と一致しない（2A のテーブルの追う核種は
  31 で、Pm-147、Pm-149、Nd-147 を含まない。branches/table-2A-micro-boron-rod-axis.msgpack の `micro` の `nuclides`）。停止をサイクルの終わりに置けば
  （下の案 S1）Pm-149 は停止の間に Sm-149 に移るが、残りの補助の核種は残る
- 案 A2: 履歴の点ごとの `densities` に、解く核種の全部（追う核種と補助の核種）を書く: 点ごとの大きさが補助の核種の数だけ増える（2A のチェーンで
  31 から 174、5.6 倍）。全炉心の 193 体 × 軸方向 24 ノードとすると（ノードの数は決めていない）、1 点で 193 × 24 × 174 × 8 B = 6.4 MB。比較の
  ツールは `nuclides` の順で `densities` を引くので、並びの意味も変わる
- 案 A3: 履歴の最後の点の補助の核種だけを、補助の核種の名前（`auxiliary`）と数密度（`auxiliary_densities`）として履歴に足す（採用）: restart に要るのは
  最後の点だけ。点ごとの `densities` の形と比較のツールは変わらない

サイクルの間の停止（Problem 10 の 30 日）の置き場:

- 案 S1: 前のサイクルのケースの最後の崩壊だけのステップ（採用）: 履歴の最後の点が停止の後の組成になり、次のサイクルの燃焼点 0 がそのまま BOC（Problem 10
  の HZP の状態）の解になる。停止の間の崩壊は集合体ごとで装荷によらないので、取り出す集合体も同じく崩壊させてよい
- 案 S2: 次のサイクルの最初の崩壊だけのステップ: 入力では書ける（上の事実）が、燃焼点 0 が停止の前の組成を新しい装荷で解いた、どの時刻の炉心でも
  ない点になる。新しい燃料も 30 日崩壊させる（燃焼度 0 の追う核種はウランだけなので、変わるのは丸めの水準）

restart したサイクルの EFPD と燃焼度:

- 案 E1: EFPD と日数は 0 から数え直し、燃焼度はノードごとに引き継ぐ（採用）: ステップの `efpd` はそのサイクルの累積の EFPD（Problem 9、10 の仕様書の
  表と同じ数え方）。炉心の平均の燃焼度の増分の目標に、燃焼点 0 の炉心の平均の燃焼度（装荷した集合体の質量の重み）を足す
- 案 E2: 前のサイクルの EFPD から続けて数える: 装荷替えで炉心の平均の燃焼度が変わるので、EFPD と炉心の平均の燃焼度の関係がサイクルをまたいで
  成り立たない

## 決定と理由

### 入力（案 R1、I2）

```toml
# サイクル（ADR-0105）
plant = "plant.toml"
inventory = "assemblies.toml"
restart = { history = "cycle-1.msgpack", fresh = ["A05"] }   # 前のサイクルの燃焼の履歴と、履歴にない新しい集合体
loading = [
  ".    .       .",
  "A04  A02@90  .",
  "A05  A01     .",
]
```

- `history` は前のサイクルの燃焼の履歴（`xlc-core-history`）。サイクルのファイルのあるディレクトリから辿る。`fresh` は省けば空
- `fresh` の ID は `loading` にあり、重ならないこと（違えば読み込みのエラー）
- restart のサイクルは燃焼のケース（`[depletion]`）でだけ使える。燃焼しないケースで読めばエラー（restart の組成を使わずに新しい燃料で解かない）

### ID の対応（案 I2、D2）

履歴の最後の点を読み、装荷図の ID ごとに:

- 履歴にあり `fresh` にない ID: ノードの燃焼度と、ミクロ燃焼なら解く核種の数密度（下の補助の核種を含む）を引き継ぐ
- `fresh` にあり履歴にない ID: 新しい燃料（燃焼度 0、テーブルの燃焼度 0 の組成。補助の核種は 0）
- 履歴にあって装荷図にない ID: 取り出した集合体。読まない（ログに出す）
- 履歴にも `fresh` にもない ID、両方にある ID: エラー

### 回転

`radial-nodes = 1`（ADR-0190 の燃焼の条件）では、集合体の状態は軸方向のノードの列で、集合体の自分の座標系の向きを持たない。回転（`@90` など）は、
ADR-0105 のとおりテーブルの辺ごとの量（ADF、真空の辺の比、f* の印）とピンの形状を回し、ノードの燃焼度と数密度は回さずに同じ軸方向のノードに
引き継ぐ。

### 確かめてエラーにするもの

黙って合わせない:

- 履歴の点がない、形式が違う（`CoreHistory::from_msgpack`）
- ケースの軸方向のメッシュが履歴の `axial_mesh` とビットで違う
- 引き継ぐ集合体のノードの初めの重金属の質量が、履歴の `heavy_metal` とビットで違う（案 D2）
- ミクロ燃焼の有無が履歴とケースで違う（履歴が `nuclides` を持たないのにケースが `micro` を持つ、またはその逆。補助の核種と追う核種を黙って 0 か
  テーブルの燃焼度 0 の値にするか、数密度を黙って捨てることになる）
- 履歴の追う核種（`nuclides`）がテーブルの `micro` の核種と、補助の核種（`auxiliary`）がチェーンから作る補助の核種と、名前と順で違う
- 引き継ぐノードのうち、ミクロ燃焼する（核分裂のある）ノードと、履歴で数密度を持つノードが違う

定格の出力密度、Xe の扱い（`xenon`）、中点のホウ素（`midpoint-boron`）は、前のサイクルと違ってよい（ノードの燃焼度と組成の意味を変えない）。

### 補助の核種と燃焼の履歴の形式（案 A3）

ミクロ燃焼の履歴に、次の 2 つを足す（ミクロ燃焼の履歴だけが持ち、ミクロ燃焼の履歴は必ず持つ）:

- `auxiliary`: 補助の核種の名前（解く核種の並びの中の順）
- `auxiliary_densities`: 最後の点のノードの補助の核種の数密度（`[集合体][軸方向のノード][補助の核種]`、1/(barn cm)。核分裂のないノードは空）

restart は、最後の点の `densities`（追う核種）と `auxiliary_densities` を、解く核種の並びに戻して引き継ぐ。

### 停止とサイクルの数え方（案 S1、E1）

サイクルの間の停止は、前のサイクルのケースの最後の崩壊だけのステップに書く（Problem 10 の 30 日）。restart したサイクルの EFPD と日数は 0 から数え、
燃焼度はノードごとに引き継ぐ。ステップの炉心の平均の燃焼度の増分は、燃焼点 0 の炉心の平均の燃焼度 B̄ₛ を足して

Δ = B̄ₛ + p E / 1000 − B̄₀

（p は定格の出力密度、E は終わりの累積の EFPD、B̄₀ はステップの初めの炉心の平均）とする。燃焼度 0 から始まる炉心では B̄ₛ = 0 で、ADR-0190 の式と
同じ値になる。

### 燃焼点 0 の Xe（ADR-0219 との関係）

restart の燃焼点 0 は、ADR-0219 の燃焼点 0 と同じく、読んだ組成のまま解く。新しい扱いは足さない:

- `xenon = "equilibrium"`: 前のサイクルの最後が停止の後の点なら、崩壊で進めた Xe（30 日の後はほぼ 0）。最後が出力のステップの終わりの点なら、その点の
  平衡の組成（ADR-0219 の固定点の組成）で、同じ状態で解けば前のサイクルのその点の解と同じになる。燃焼点 0 からのステップの中点と終わりの点は平衡
- `xenon = "tracked"`: 引き継いだ値から時間で追う

### 帰結

- Problem 10 のサイクル 2 は、Problem 9 のケースの最後に 30 日の崩壊だけのステップを足し、その履歴を restart に書いたサイクルで解く。BOC の HZP の
  解は燃焼点 0（最初のステップの状態）。燃焼しないケースで restart を読む形は、Problem 10 の入力を作るときに要るかを決める
- 2 サイクル以上前に取り出した集合体を戻すには、その集合体の最後のサイクルの履歴を読む形（restart を複数の履歴にする、または集合体ごとの状態の
  ファイル）が要る。今はエラーで止まる（#0205）
- `radial-nodes` が 1 でない燃焼（部分ノードの状態）を入れるときは、回転で部分ノードの状態を並べ替える（集合体の自分の座標系で持つ。ADR-0036）
- 挿入物（`inserts`。ADR-0105 のサイクルの置き場）と、設計の違う集合体（IFBA、WABA、ブランケットのテーブル）は、この ADR の範囲の外。挿入物を
  抜いた集合体は、重金属の質量が同じなら restart の検査を通る。そのテーブルの履歴の扱いは [ADR-0215](0215-correct-untracked-history-by-history-branches.md) と #0190
- 履歴の補正の変数（ADR-0215。core はまだ進めない。#0190）を入れるときは、ノードの状態として履歴に書き、restart で同じく引き継ぐ
- 燃焼の履歴の形式が変わり（ミクロ燃焼の履歴の `auxiliary` と `auxiliary_densities`）、今までのミクロ燃焼の履歴は core の `CoreHistory::from_msgpack` で
  読めない（restart に使えない）。Python の比較のツールは足した項目を読まないので、今までの履歴も新しい履歴も読める

- 前のサイクルの最後の点は、最後のステップの状態と（平衡 Xe なら）出力で解く（ADR-0218 の案 P2、ADR-0219）。次のサイクルの最初のステップの状態か出力が
  それと違うと、restart の燃焼点 0 は、続けて解いた燃焼の同じ点（次のステップの状態で解き、平衡 Xe なら次のステップの出力で釣り合う）と違う組成と状態で
  解く。サイクルの間は停止の崩壊だけのステップの後の点（組成を時間で進めた値のまま解く）で切るので、Problem 10 では違わない

  `fresh`、重なる `fresh`、履歴のない restart、知らない項目、燃焼しないケース）
- 燃焼（crates/core/src/depletion/tests.rs）: `restarts_continue_the_depletion_of_one_case`（A と B の炉心を Xe を時間で追う燃焼と平衡 Xe で、途中で
