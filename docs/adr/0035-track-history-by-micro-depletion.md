# ADR-0035: 燃焼履歴は core のミクロ燃焼と、履歴の変数・履歴の分岐による補正で扱う

## 背景

炉心のノードは lattice の基準の燃焼と違う条件（減速材密度、ホウ素濃度、制御棒）で燃焼し、瞬時の分岐では組成が
基準のままなので、その差が入らない（高い燃焼度で数百 pcm）。

## 検討した案

- 炉心側で Xe と Sm の数密度だけを追跡する。計画で一時採った（2026-10-06、3d4eaae。全体計画の最初の版）。実装していない
- 履歴の変数による補正だけ（SIMULATE-3 と同じ）: 近似が多い
- 主要な核種をノードごとにミクロ燃焼で追跡し、残りを履歴の変数と履歴の分岐で補正する（SIMULATE-5 や PARCS と同じ。
  採用）

## 決定と理由

core で燃焼度と主要な核種（U、Np、Pu、Am、Xe、Sm、Gd など）の数密度をノードごとに燃焼方程式で追跡し（ミクロ燃焼）、
追跡しない核種の残りを履歴の変数と履歴の分岐（条件を変えた燃焼計算）で補正する。ノードの断面積はテーブルの補間と
ミクロ燃焼の補正で求める。履歴の変数による補正だけより近似が少なく、データの流れ（lattice の微視的断面積、core の
出力履歴、燃焼のソルバ）が冷却計算と共通になるため。

## 確認

まだ実装していない（M4）。M4 で VERA Problem 6 以降と比べる。

## 帰結

- lattice は主要な核種の微視的断面積と数密度、履歴の補正のデータを出す（[ADR-0026](0026-output-two-group-tables-from-lattice.md)）
- ノードの状態の持ち方は [ADR-0036](0036-keep-core-state-per-assembly.md)、燃焼のソルバは [ADR-0003](0003-extract-shared-computation-on-second-use.md)
