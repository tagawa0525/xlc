# ADR-0175: 仕様書に KENO-VI の値がある問題は、ENDF/B-VII.0 の検証用ライブラリでも xlc を解いて KENO-VI と直接比べる

## 背景

仕様書（CASL-U-2012-0131-004 Rev.4）の参照解は KENO-VI、ENDF/B-VII.0 で、Problem 1〜5、4-2D、REF1-2D、5-2D の k、
ピン・集合体出力、軸方向の出力、制御棒価値、ITC がある。燃焼（Problem 9）と HFP（6〜8）にはない。

xlc の本番のライブラリは ENDF/B-VIII.0（ADR-0020）で、KENO-VI との差には核データの版の差が混じる（3B で
OpenMC − KENO-VI が +124 pcm、2Q で +119 pcm。examples/vera/verification.md）。それを除くため、同じ VIII.0 の
OpenMC の参照解を作ってきた（ADR-0031。ツールの固定は ADR-0124 が引き継いだ）。3D の問題では OpenMC が 1 本 5 時間以上かかる。

判断の軸:

- 手法の差を、核データの差と分けて数値で言えること
- 計算時間（3D の OpenMC は 1 本 5 時間以上）
- 本番のライブラリと、本体のコードを変えないこと

## 検討した案

- 案 A: OpenMC の VIII.0 の参照解を作り続ける。手法の差は取り出せるが、仕様書に KENO-VI の値がある問題でも 3D は
  1 本 5 時間以上かかり、モデルの解釈（KENO-VI の入力は公開されていない）の差も OpenMC のモデルに別に入る
- 案 B: KENO-VI とだけ比べる（本番の VIII.0 のまま）。安いが、差に核データの版の差が混じり、原因を分けられない
- 案 C（採用）: 仕様書に KENO-VI の値がある問題は、xlc を ENDF/B-VII.0 の検証用ライブラリでも解き、KENO-VI と直接比べる。
  核データの版は揃うので、残る差は手法と処理の差になる。OpenMC の参照解は、仕様書に参照がない問題と、診断に反応率が
  要る小さな 2D の問題だけにする

## 決定と理由

案 C にする（ユーザーの決定、2026-10-15）。k の手法の差を何で見るかは 2026-11-25 に変えた（「## 変更」）。

- 検証用ライブラリは、本番の `examples/vera/xs.toml` と同じ核種・温度・群で、ENDF だけ VII.0 にしたもの
  （`endfb70/xs.toml`）。本番のライブラリ（VIII.0）と、その結果は変えない。コードも変えない。ステージは `examples/vera/endfb70/dvc.yaml`（入力は `endfb70/xs.toml`、
  3A・3B の入力は `p3_inputs.py --library-dir endfb70` が `endfb70/p3` に書く）
- 仕様書に KENO-VI の値がある問題（1B〜1D、2A〜2K、2Q、3A、3B）を VII.0 のライブラリで解き、KENO-VI と比べる。ピン出力と
  軸方向の出力の手法の差は、この比較で見る（2B のピン出力は、同じ VII.0 の OpenMC − KENO-VI の RMS が 0.032% で、xlc − KENO-VI の
  0.049% より小さい。`examples/vera/verification-endfb70.md` の「NJOY で処理した ENDF/B-VII.0 の OpenMC との比較（1B、1D、2B）」）
- 2D の格子（Problem 1 と 2 のうち仕様書に KENO-VI の値があるもの。今のステージは 1B〜1D、2A〜2K、2Q）の k の手法の差は、
  本番の核データの版の OpenMC の参照解と比べて見る。同じ VII.0 でも、OpenMC（NJOY）と KENO-VI の k は +94〜+181 pcm 違い
  （「確認」）、xlc − KENO-VI の k から手法の差をこの大きさより細かく読めない。KENO-VI との k の比較も続けるが、手法の差としては読まない
- 3A と 3B の k は、当面 KENO-VI との比較で見て、約 100〜180 pcm の不確かさを受け入れる。本番の核データの版を変えても、この 2 本の
  OpenMC の参照解は作り直さない（1 本 5 時間以上。背景）
- OpenMC の参照解は、上の 2D の格子のほかは、仕様書に参照がない問題（燃焼、ブランチ計算、HFP）と、原因の診断に反応率が要るときの
  2D の小さな問題だけ作る。3D の全炉心と Problem 4 の OpenMC は作らない（ADR-0031 の帰結を維持する）
- ADR-0124 と ADR-0031 の関係: ADR-0124 はツールの固定と `references/` の扱い（案 A、D、F、J、N）を決め、参照解の作り方を
  ADR-0031 から引き継いだ。この ADR は、その引き継いだ「参照解の作り方」のうち、KENO-VI の値がある問題の比べ方だけを
  足す。ADR-0124 の決定（固定の手段）は変えないので、置き換えず `requires` にする。VIII.0 の OpenMC との比較の
  位置づけ（コード同士の検証）も変えない
- 命名の規則: 評価済みデータごとに `examples/vera/<略称>/` と `verification-<略称>.md` を置く（ENDF/B-VII.0 は `endfb70`。
  将来の JENDL-5、JEFF-3.3 は `jendl5`、`jeff33`）。本番（ENDF/B-VIII.0）は `examples/vera/` の直下のまま。版の違う結果を
  1 つの記録に混ぜない

比べるときの注意:

- 同じ評価済みデータでも、KENO-VI の連続エネルギーのライブラリは AMPX で処理したもので、xlc の処理（共鳴の
  再構成、ドップラー拡がり、S(α,β) の温度の内挿。ADR-0080）とは違う。VII.0 での xlc − KENO-VI に残る差は、手法と処理の差で
  ある。核データの版の差は除けるが、処理の差は除けない。k では処理かモデルの解釈の差が手法の差と同じ大きさになる（上の 2D の格子の項）
- 3B の KENO-VI は、H in H2O の S(α,β) を 550 K と 600 K の 2 つの計算から手で内挿している（仕様書の問題 3 の
  「Cross Sections」）。2A、2Q、5-2D、HZP の 565 K も、仕様書は S(α,β) の温度の補正を加えている。xlc は S(α,β) の群定数を
  温度について線形に内挿する（ADR-0080）。KENO-VI は k の値を内挿し、xlc は群定数を内挿するので、同じ内挿ではない。
  差が内挿の違いに当たるかは確かめていない
- ENDF/B-VII.0 には C-12 と C-13 のファイルがなく、天然の C（`n-006_C_000.endf`）だけがある。ADR-0079 は VIII.0 に
  天然の C がないために分けたので、VII.0 のライブラリでは C-12 と C-13 の両方にこの天然の C のファイルを指す
  （入力 `endfb70/xs.toml` で吸収する。コードは変えない）。KENO-VI も天然の C の評価を使うと見込むが、確かめていない

## 確認

xlc の xs は ENDF/B-VII.0 のすべての核種で止まらず、ピンセル 1B〜1D、集合体 2A〜2K、2Q、3A、3B を解けた
（5dac88dd、2026-10-15。`examples/vera/endfb70/`）。結果は `examples/vera/verification-endfb70.md`。

- k: ENDF/B-VII.0 の xlc − KENO-VI は 15 の格子で +115〜+270 pcm（平均 +165）、3A が +181 pcm、3B が +166 pcm。VIII.0 の
  xlc − OpenMC（平均 +39 pcm）と同程度にはならなかった。核データの版の差だけで残りが説明できる、という見込みは k では
  成り立たない。原因は確かめていない（#0131）
- ピン出力: 吸収体のある集合体で、xlc − KENO-VI の RMS は VIII.0 の 0.45〜0.61 倍に下がる
- 上の 2 項は 5dac88dd の値。今のライブラリ（d6cc90d9、2026-11-15）では、15 の格子が +98〜+282 pcm（平均 +176）、3A が +196 pcm、3B が +165 pcm、
  ピン出力の RMS の比が 0.48〜0.60 倍（`examples/vera/verification-endfb70.md` の「結論」）
- NJOY で処理した ENDF/B-VII.0 の OpenMC（1B、1D、2B。776b9134、2026-11-19）: VII.0 の xlc − KENO-VI（+196〜+204 pcm）のうち、+94〜+181 pcm は
  同じ評価済みデータの OpenMC と KENO-VI の間にあり、ライブラリを VIII.0 から VII.0 に替えたときの k の動きは xlc と OpenMC で 26 pcm 以内で合う。
  `examples/vera/verification-endfb70.md` の「NJOY で処理した ENDF/B-VII.0 の OpenMC との比較（1B、1D、2B）」（#0131）

## 帰結

- 3A と 3B と、ピン出力と軸方向の出力は、OpenMC を実行せずに KENO-VI と比べられる。2D の格子の k は、本番の核データの版の OpenMC の
  参照解が要る。本番が VIII.0 の今は、15 の格子の参照解がある（examples/vera/verification.md の「参照解」、xlc との k の差は同じ記録の
  「OpenMC との比較」）
- 本番の核データの版を変えると（ADR-0264）、2D の格子の 15 本の OpenMC の参照解を、その版で作り直す（#0329）。見積もりは r995 の
  16 スレッドの排他で約 37 時間（約 1.5 日）。標準のタリーの組（ADR-0152）を持つ今のモデルの実績（#0301 の表。Slurm 961、2026-11-19）は、
  1B が 97 分（450 世代）、1D が 120 分（450 世代）、2B が 150 分（500 世代）。1C は 120 分と置いた。ほかの集合体は、組を持たない
  VIII.0 の実行の total（examples/vera/verification.md の「参照解」。2A 38.5 分〜2Q 50.4 分）に、2B の比（150 分 / 33.7 分 = 4.5）を掛けて
  144〜224 分とした。2C と 2D は組を持たない total が記録に無いので、2B と同じ 150 分と置いた。集合体ごとにタリーの比が同じかは
  確かめていない。世代の数は VII.0 の診断（#0301 の表）と同じとした。その版の OpenMC のライブラリを NJOY で作る時間は含めない（測っていない）
- 3A と 3B を本番の版の OpenMC で解くのは、r995 に時間があるときに考える（ユーザー 2026-11-25。#0329）。1 本の見積もりは 16 スレッドで
  5.6〜6.2 時間（examples/vera/verification.md の「Problem 3 の参照解」の「計算の条件と時間の見積もり」）
- 検証用ライブラリは本番ではない。VII.0 の zip は ADR-0124 と同じく URL と sha256 で固定し、`.#endf` の木に
  `ENDF-B-VII.0_neutrons/`、`ENDF-B-VII.0_thermal_scatt/` として足す（docs/environment.md）。VIII.0 のディレクトリの中身は変わらない
- 処理の差（AMPX と xlc）は分けられない。分けるには、同じ処理の参照（NJOY の VII.0 での OpenMC）が要り、2D の小さな
  問題でだけ作る
- VII.0 の xlc − KENO-VI の k の差は、手法の差だけではない。1B、1D、2B では、処理かモデルの解釈の差（OpenMC（NJOY）− KENO-VI）が
  +94〜+181 pcm を占める（「確認」）。k については、KENO-VI との直接の比較から xlc の手法の差を 100 pcm より細かく読めない。
  そのため 2D の格子の k は OpenMC と比べ（「決定と理由」）、3A と 3B の k にはこの不確かさが残る。その原因（AMPX と NJOY の処理、
  KENO-VI のモデルの解釈、共鳴の散乱の扱い）は分けていない（#0131）。吸収体のある集合体と 565 K でこの差がどうなるかは測っていない

## 変更

- 2026-11-25: 「決定と理由」で、2D の格子の k の手法の差を本番の核データの版の OpenMC と比べることにし、3A と 3B の k は KENO-VI と比べて
  不確かさを受け入れると書き、ピン出力と軸方向の出力は KENO-VI と比べると明記した。前は「仕様書に KENO-VI の値がある問題（1B〜1D、2A〜2K、
  2Q、3A、3B）を VII.0 のライブラリで解き、KENO-VI と比べる」と「OpenMC の参照解は、仕様書に参照がない問題（燃焼、ブランチ計算、HFP）と、
  原因の診断に反応率が要るときの 2D の小さな問題だけ作る」。版を揃えれば xlc − KENO-VI の残りが手法の差になるという前提が、k では
  成り立たなかったため（同じ VII.0 の OpenMC − KENO-VI が 1B +100 ± 8、1D +181 ± 9、2B +94 ± 5 pcm。「確認」。#0302）。比べた案は
  #0302 の 3 つ: KENO-VI との比較を続けて約 100〜180 pcm の不確かさを受け入れる案は、3A と 3B だけに残した。KENO-VI の値がある問題で
  同じ評価済みデータ（VII.0）の OpenMC と比べる案は、仕様書に参照がない問題で本番の版の OpenMC の参照解がどのみち要るので、それに加えて
  VII.0 の参照解を作ることになり採らなかった。本番の版の OpenMC とだけ比べる案を 2D の格子に採り、3D の 3A と 3B は 1 本 5 時間以上かかるので
  外した。親が k は OpenMC、ピン出力は KENO-VI と推奨し、OpenMC の流し直しに時間がかかることをユーザーが指摘した。親が 2D の格子は OpenMC、
  3A と 3B は KENO-VI のままと返し、ユーザーがそれで当面よく、r995 に時間があれば 3A と 3B も流すことを考えてよいとした（ユーザー 2026-11-25）。
  そのときに親が示した 2D の格子の時間（約 7 時間）は、組を持たない実行の total からのもので、今のモデルの見積もりは「帰結」の約 37 時間
