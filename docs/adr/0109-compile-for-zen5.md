# ADR-0109: 開発のマシンの CPU（Zen 5）の命令でコンパイルする

## 背景

集合体の格子計算の時間を縮める（#0039）中で、ビルドが CPU の指定なし（x86-64 の基本の命令、SSE2）で、xlc のコードが
AVX-512 を使っていないことが分かった。開発のマシンの CPU は AMD Ryzen 9 9950X（Zen 5。512 ビットの AVX-512 を全幅で
実行する）。ユーザーは、AVX-512 で速くなるなら単純なので使うとした。

## 検討した案

VERA 1B のピンセルの自己遮蔽と MOC の時間（指定なしで 4.37 秒と 1.46 秒）:

- `target-cpu=native`: 4.0 秒、1.33 秒。結果はビット単位で同じ。命令がビルドしたマシンで変わり、何を使ったかが入力から
  分からない
- `target-cpu=x86-64-v4`（AVX-512 を含む水準）: LLVM は汎用の水準では 512 ビットのベクトルを使わず（zmm の命令 0）、
  速くならなかった。`-prefer-256-bit` を外す指定を足すと native と同じになるが、正式でない機能の警告がビルドごとに出る
- `target-cpu=znver5`（採用）: native と同じ速さで、警告なし。使う命令が名前で決まる

## 決定と理由

ワークスペースの `.cargo/config.toml` で `-C target-cpu=znver5` を指定する。ホームの `~/.cargo/config.toml` にターゲット別の
`rustflags`（mold でのリンク）があり、ターゲット別の指定は `[build]` の指定より優先されるので、同じ
`[target.x86_64-unknown-linux-gnu]` に書く（配列はつながり、両方が効く）。Rust は浮動小数点の積和を勝手に融合しないので、
結果は変わらない（VERA 1B と 2B で少数群定数がビット単位で同じ）。

## 確認

VERA 2B の集合体（examples/split/assembly-1.toml）の1状態は 182 秒から 167 秒（自己遮蔽 121 秒から 107 秒、MOC 61 秒から
59 秒）で、少数群定数のファイルはビット単位で同じだった（2026-10-10）。

## 結果

- Zen 5 の命令を持たない CPU では、ビルドしたバイナリが動かない。別のマシンで使うときは指定を変える
- コードの側でベクトル化しやすい形（配列の並び）に直すと、さらに効く余地がある
