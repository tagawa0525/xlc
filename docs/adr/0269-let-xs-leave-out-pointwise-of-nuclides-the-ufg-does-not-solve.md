# ADR-0269: xs の入力で、UFG で解かない核種のポイントワイズの断面積をライブラリに持たせないことを選べるようにする

## 背景

ADR-0268 で、入力 `ufg-nuclides` に挙げない中心の物質の核種は、UFG の減速計算で等価原理の群定数の段の断面積を持つ静止した標的として
解かれ、ライブラリのポイントワイズの断面積を読まなくなった（読むのは分離共鳴の上端だけ。crates/lattice/src/ufg.rs の `solve_cell` は、
段の核種のポイントワイズの断面積を `stepped_pointwise` で作り、ライブラリの表を使わない）。輸送する核種をデータのある全核種（版によって
390〜557。別のセッションの走査の報告で、確かめていない）に広げると、そうした核種のポイントワイズの断面積がライブラリの大部分を占める。

測った内訳（#0292 の経緯の 2026-11-20 の項。main の 834ddcaa6 のビルド、手元）:

- 大きさ: 試行のライブラリ（examples/depletion/issue-0292/trial/library/depletion.msgpack、2,112,495,301 バイト、13 温度）では、
  ポイントワイズの断面積が 78.3%（1,653,756,842 バイト）、S(α, β) の移行（UFG だけが読む。H-1 だけ）が 1.3%。燃焼のライブラリ
  （examples/depletion/depletion.msgpack、319,648,491 バイト、65 核種）でも 78.2%
- 17 核種の組（ADR-0268 の確認の `s17`）に入らない足した 48 核種のポイントワイズの断面積は、試行のライブラリの 13.8%（291,816,444 バイト）
- 全核種に広げたとき、足す核種が 48 核種と同じ程度の大きさで UFG で解かないとすると、ポイントワイズの断面積を持たせない分は 390、455、
  557 核種で全体の 41%、45%、49%（外挿で、確かめていない）
- 時間: xs の 1 核種の処理で、ポイントワイズの断面積を取り出して書く分は、範囲の無い処理との差が手元の計り直しのばらつきの中
  （Cs-137 で 8.8 と 10.5 秒、Nd-144 で 11.2 と 10.9 秒）。取り出しは、群定数のために作ったドップラーの格子を 1 回なぞるだけ。組み立て
  （`xs assemble`）は試行のライブラリで 6.4 秒、最大の常駐 6.7 GB で、65 核種の処理（約 45 分。Slurm 942）に比べて小さい

利得は、ライブラリの大きさと読み込みのメモリにあり、xs の時間にはない。

## 決定の要因

- 正確さ > 実行速度 > 保守の容易さ（CLAUDE.md の「方針」）。既定は今の挙動（すべての核種にポイントワイズの断面積を持たせる）のまま
- 黙ったフォールバックを足さない。ポイントワイズの断面積を持たない核種を UFG で解く入力はエラーで止める
- 既存のライブラリ（DVC の出力）を読めなくしない（作り直しは数日から 1 週間の規模。CLAUDE.md の「計算」）
- 核種ごとのステージ（ADR-0138）は、その核種の入力の項目だけを params の deps にする。核種の選択を変えたら、その核種のステージだけが
  changed になる形にする

## 検討した案

入力:

- 案 I1（採る）: 核種の項目 `pointwise = false`（`[nuclide.<名前>]` の中。省くと true）。`activation` と同じ置き場で、核種ごとの
  ステージの params の `nuclide.${key}` に入る
- 案 I2: 最上位の一覧（`pointwise-nuclides = [...]`、または格子の `ufg-nuclides` と同じ一覧）。一覧はすべての核種のステージに共通の項目に
  なり、1 核種を足し引きするだけで全核種のステージが changed になる。格子の入力の `ufg-nuclides` は別の段の入力で、同じ一覧を共有する
  仕組みも要る

形式:

- 案 F1（採る）: 温度の表の `pointwise` を nil にできる（nil は持たない）。核種のすべての温度で nil か、すべてで持つ。nil の表は
  S(α, β) の移行を持たない。既存のライブラリは map を持つので読め、持たせる核種は今とバイトで同じに書く。既存の値の意味は変えないので
  形式の名前（`xlc-multigroup`）は変えない
- 案 F2: 空の配列（`energy` が空）で持たないことを表す。今の検査は、範囲のあるライブラリで範囲を覆わない表を止めるので、それを緩める
  ことになり、壊れた表と持たない表を区別できない
- 案 F3: 核種に新しい項目（`pointwise: bool` など）を足す。項目を欠かせない形にすると既存のライブラリが読めなくなり、省けば既定に
  する形は黙ったフォールバックになる

xs の処理:

- 案 P1（採る）: 群定数の処理は変えず、`pointwise = false` の核種の結果から、ポイントワイズの断面積を外して書く。取り出しの時間は
  背景のとおり測ったばらつきの中で、処理の関数（`process_nuclide`）の引数を増やさない
- 案 P2: 処理の設定に核種ごとの選択を足し、取り出しも行わない。時間の利得は測れないほど小さく、テストの呼び出しの 30 か所あまりが変わる

ポイントワイズの範囲（`xs range`）は、今のとおり輸送するすべての核種の分離共鳴の上端から決める。持たせない核種を除くと、範囲の
ステージが核種の選択に依るようになり、選択を変えるたびに全核種のステージが changed になる。

## 決定と理由

入力は案 I1、形式は案 F1、xs の処理は案 P1 にする。

- xs: `pointwise = false` は、`activation = true`（放射化の核種はもともと持たない）と `thermal`（S(α, β) の核種は減速材の核種で、
  ADR-0268 により UFG で解く）と組めばエラーで止める。`assemble` は、核種ごとの結果がポイントワイズの断面積を持つかが入力の項目と
  合うことを確かめる（古い結果を黙って組み立てない）
- 形式（crates/format）: 温度の表の `pointwise` を `Option<Pointwise>` にする。nil の核種は、温度の間の内挿でも nil のまま（片方だけが
  nil なら止める）
- lattice: `ufg-nuclides` に挙げた核種がポイントワイズの断面積を持たなければ、自己遮蔽の前にエラーで止める。UFG の減速計算は、
  ポイントワイズの断面積で解く核種（`ufg-nuclides` を省いた入力では、すべての核種）が持たなければエラーで止め、`ufg-nuclides` から
  外して等価原理の群定数で解くこと（ADR-0268）を示す。中心でないリングの核種はもともと挙げる必要がある（ADR-0268）ので、持たない
  核種は中心の物質の、挙げない核種の経路だけで使える

### 帰結

- 既定は変わらない。持たせない核種のあるライブラリは、その核種を `ufg-nuclides` に挙げる入力では使えない。全核種のライブラリを
  この形で作るかは #0292 で決める
- 持たせない核種の組を変えると、その核種の xs のステージだけを作り直す
