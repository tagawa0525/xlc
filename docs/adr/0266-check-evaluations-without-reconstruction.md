# ADR-0266: xs check は、ENDF の評価を再構成せずに、xs nuclide が読む MF の読み込みと形式の検査だけで確かめる

## 背景

輸送しない核種の扱い（#0292）で、データのある全核種を輸送する核種にする案が出ている。今の燃焼のライブラリの 65 核種の外の評価を
xs が読めるかは分かっていない。調べるには、4 つの版（ENDF/B-VII.0、VII.1、VIII.0、VIII.1）の中性子のファイル（約 390〜560 ずつ）を
1 つずつ xs に通す。

- `xs nuclide` は 1 つの評価を最後まで処理し、重い核種で CPU 約 1 時間かかるので、全部には流せない
- `xs range` は MF2 の分離共鳴の上端までしか読まず（ADR-0138）、MF1、MF3〜MF8 を確かめない（#0305 の走査はこれによる）
- 棚卸しのツール `crates/chain/examples/survey_neutrons.rs`（ADR-0167 の背景）は、`read_evaluation`（0 K の再構成を含む）と非分離共鳴の
  自己遮蔽のラダーまでを行い、557 評価に Slurm で数十分かかる。MF8 を読まず、xs の外の例のプログラムで、読む順を自分で並べている
- リポジトリの CLAUDE.md は、試行を本番のコードに入力ファイルを与えて行い、選べない選択肢は入力で選べる機能として足すとする

判断の軸:

- 本番の `xs nuclide` が止まる読み込みと形式の検査を、同じコードで通すこと（本番に検査を足せば、この経路にも入る）
- 1 つの評価が秒の桁で終わり、4 つの版の全部を手元で通せること
- 止まった評価の理由を、評価ごとに残すこと（1 つ目で全体を止めない）

## 検討した案

- 案 A: サブコマンド `xs check <報告> <ENDF のファイル>...` を足す。ファイルごとに、輸送する核種として `xs nuclide` が読む MF の
  読み込みと、再構成の前に止まる検査だけを行い、理由をファイルごとに報告に書く（採用）
- 案 B: `xs range` を広げて、MF2 のほかも読む: `xs range` の出力はステージ（`xs-nuclide`）の入力で、全核種の分離共鳴の上端を
  1 つにまとめる。読めるかの評価ごとの結果を書く場所が無く、1 つ目のエラーで止まる
- 案 C: `xs check <入力ファイル>`（ライブラリの入力の TOML）: 入力の核種の名前は `U-235` の形で（`is_nuclide_name`）、天然の元素の
  評価（VII.0 の V、Zn、C など）を書けない。走査には版ごとに 400〜560 の核種の項目と、使わない `temperatures` と `sigma0` を
  書いた入力が要る
- 案 D: `survey_neutrons` から再構成と自己遮蔽を外す: xs の外で読む順を並べ直すので、本番に検査を足しても走査に入らない
- 案 E: `xs nuclide` を時間で打ち切る（#0307 の 30 秒の試行）: 打ち切った評価が後で止まるかが分からない

## 決定と理由

案 A にする。

- 確かめるもの: 物質が 1 つ、MF3 の全部の節の読み込みと運動学のしきい値（ADR-0100）、MF2 の読み込み、範囲の組み合わせ（非分離共鳴の
  LSSF、LSSF = 0 の範囲と分離共鳴の重なり、R 行列の制限形の粒子の対とチャネル）、分離共鳴の上端の s 波の散乱半径、非分離共鳴が 1 つ
  以下で補間則が揃うこと、MF1 の ν と遅発中性子、MF4〜MF6 の出射の分布、反応ごとの中性子の出どころ（分布の無い放出、角度分布の系）、
  核分裂の断面積に ν と χ の材料があること、チェーンの反応の MF8 と、それが挙げる MF9、MF10 の表
- 確かめないもの（後の処理で初めて止まる）: 線形化、共鳴の再構成とドップラー拡がりの数値のエラー、非分離共鳴のラダーの抽出、
  多群化、MF8 の経路の和が反応を超える検査（`chain_reactions` の許容。群の平均の値で決まる）、熱中性子散乱のテープ（S(α, β) は
  入力の `thermal` で与えるもので、ファイルの走査の対象でない）
- 検査は本番と同じ関数で行う。MF3 のしきい値と範囲の組み合わせ（`pointwise` の `RawParts`、`check_range`）、中性子の出どころ
  （`scatter` の `sources`）、出射の分布（`process::read_distributions`）は、本番の処理と共有するように切り出した。本番の
  関数の中にある短い条件（核分裂の材料、遅発中性子と核分裂、非分離共鳴の選び方、MF8 の状態の MF の混在）は、`check` に同じ条件を
  書いた
- 物質の名前は付けず、ファイルのパスだけを報告に書く。チェーンの核種との対応は、走査を集計する側（examples/depletion）が
  ファイルの名前から付ける。報告はパスのバイトの順に並べる（与えた順はシェルのグロブならロケールの照合順で変わり、同じファイルの
  組で報告のバイトが変わる）
- 止まった評価があっても終了コードは 0 にし、報告の `error` に理由を書く。報告が走査の結果で、1 つのエラーで止めると残りが
  分からない。中身が UTF-8 でないか、テープとして読めないのも、そのファイルの理由にする。ファイルが読めない（パスが無い）、報告を
  書けないときは止まる

### 帰結

- `xs check` は輸送する核種の読み込みだけを確かめる。放射化の核種（ADR-0238）の経路の読み込みはその一部（MF3、MF2、MF8）で、
  入力の項目に合わせた検査は持たない
- 本番の関数の中に書いた条件を `check` にも書いたので、片方だけを変えると食い違う（`check` のテストが本番の条件の例を持つ）

### 確認

- `crates/xs/src/check/tests.rs`: 読める評価が通り、しきい値の下の断面積、物質 2 つ、表の無い MF8 の状態、分布の無い放出、ν の
  無い核分裂で止まり、報告がファイルごとに理由を書く
- 4 つの版の中性子のファイルの全部（393、423、557、558）を通した結果は、examples/depletion/verification.md の「中性子のファイルの
  読み込みの走査」（ステージ `read-survey`）。1 つの版が手元の 8 スレッドで 1 秒に満たない
- 同じ節の「走査が見逃す種類」: `xs check` が止めた 6 つの評価は、600 K の `xs nuclide` も同じ文で止まった。`xs check` が通した標本の
  25 のうち、後の処理で止まったのは MF8 の経路の和の検査の 5 つだけ
- 切り出した後の `xs nuclide` の出力は、ENDF/B-VIII.0 の O-16、B-10、Cr-52、Fe-57 で、main の examples/depletion/dvc.lock の md5 と同じ（35e57a2d、
  2026-11-20）
