# VERA の KENO-VI（ENDF/B-VII.0）との比較を、ENDF/B-VII.0 のライブラリで行った記録

仕様書（CASL-U-2012-0131-004）の参照解は KENO-VI、ENDF/B-VII.0 である。本番のライブラリは ENDF/B-VIII.0（ADR-0020）なので、
本番での KENO-VI との差には核データの版の差が混じる（verification.md）。この記録は、同じ核種・温度・群で ENDF/B-VII.0 から作った
検証用のライブラリ（本番ではない）で同じ問題を解き、KENO-VI と核データの版を揃えて比べた結果を書く
（[ADR-0175](../../docs/adr/0175-compare-keno-with-endfb70-library.md)）。本番の結果は verification.md にある。
同じ評価済みデータでも、KENO-VI の連続エネルギーのライブラリは AMPX で処理したもので、xlc の処理（共鳴の再構成、ドップラー拡がり、
S(α,β) の温度の内挿。[ADR-0080](../../docs/adr/0080-interpolate-sab-in-temperature.md)）とは違う。残る差は手法と処理の差である。

対象は、仕様書に KENO-VI の値がある ピンセル 1B〜1D、集合体 2A〜2K、2Q、3D の 1 集合体の炉心 3A、3B。

## ライブラリの入力とステージ

- 入力は `endfb70/xs.toml`。`xs.toml` と同じ核種と温度で、ENDF のディレクトリだけ `references/endf/ENDF-B-VII.0_neutrons`、
  `ENDF-B-VII.0_thermal_scatt`（取得は docs/environment.md）。xlc の xs はすべての核種で止まらなかった（コードは変えていない）。
  ファイルの違いは入力で吸収した:
  - ENDF/B-VII.0 に C-12 と C-13 のファイルはなく、天然の C（`n-006_C_000.endf`）だけがある。ADR-0079 の C-12 と C-13 の両方がこの
    ファイルを指す
  - `tsl-HinH2O.endf` に 573.6 K はなく、H-1 は 550 K と 600 K で処理する。565 K の問題（2A、2Q、3B）は lattice がこの 2 つの
    群定数を温度について線形に内挿する（ADR-0080）。KENO-VI の 3B も 550 K と 600 K の 2 つの計算から手で内挿している（k を内挿するか、
    群定数を内挿するかが違う）
  - xs の警告は VIII.0 と同じ種類（MF4 の補間則の違うグリッド、運動学の閾値）で、止まらない
- ステージは `endfb70/dvc.yaml`（ライブラリ `xs`、格子 `pincell`、`assembly`）と `endfb70/p3/dvc.yaml`（3A、3B。`p3_inputs.py
  --library-dir endfb70` が書く）。本番の側の同じ比較は `dvc.yaml` の `keno-pincell`、`keno-assembly`（本番のライブラリで同じツール）。
  格子の入力は `p1/`、`p2/` のものをコピーして使う。比較のツールは `compare_keno_lattice.py`（格子）と `compare_p3.py`（3A、3B）。

## 結果

xlc − KENO-VI は (k_xlc − k_KENO-VI) × 1e5 pcm。ENDF/B-VIII.0 の側は、本番のライブラリを同じツールで解いたもの（コミットは「計算」）
（格子。`keno-*` のステージ）と、verification.md の 3A、3B の比較の JSON（`p3/compare-3?-openmc.json`）。

## 結論

結論は上の表の数値で支えられることだけを書く。

- 止まった核種はない。
- k: 15 の格子で、ENDF/B-VII.0 の xlc − KENO-VI は +80〜+245 pcm（平均 +137）、3A は +157 pcm、3B は +137 pcm。ENDF/B-VIII.0 では
  格子が −33〜+159 pcm（平均 +63）、3A が +62 pcm、3B が +165 pcm。VII.0 のほうが小さいのは 2F、2G、2J、3B だけで、1B〜1D、2A〜2D、2I、2Q と 3A では VII.0 のほうが +95〜+172 pcm 大きく、
  2E、2H、2K は +11〜+28 pcm 大きい。
- VIII.0 の xlc − OpenMC（同じ核データの手法の差。verification.md の「OpenMC との比較」と「Problem 3 の炉心の計算」）は格子で平均 +12 pcm
  （−93〜+72）、3A が +38 pcm、3B が +41 pcm。核データの版が揃えば xlc − KENO-VI もこの大きさになると見込んだが、VII.0 の
  xlc − KENO-VI は平均で約 +125 pcm 大きい。VIII.0 では xlc − KENO-VI（平均 +63）が xlc − OpenMC（+12）と OpenMC − KENO-VI（+52）の
  和（+63）に等しいので、この食い違いは VII.0 のライブラリでの xlc の動きにある。原因は確かめていない
  （候補は xlc の VII.0 のファイルの扱い、AMPX と NJOY の処理の差、KENO-VI のモデルの解釈。[#0131](../../docs/issues/0131-endfb70-keno-offset.md)）。
  したがって「VIII.0 での KENO-VI との差の残りは核データの版の差」とは、k については言えない。
- ピン出力: 吸収体のある集合体（2E〜2H、2J、2K）で、VII.0 のライブラリの xlc − KENO-VI の RMS は VIII.0 の 0.48〜0.61 倍に下がる
  （上の表。3B のピン出力も 0.086% と 0.149%）。2B〜2D、2A、2I、2Q と 3A は両方で同じ程度。軸方向の出力の差の RMS は 3A、3B とも
  VII.0 のほうがわずかに大きい（3A 0.0032 と 0.0028、3B 0.0023 と 0.0019）。VIII.0 で残っていた吸収体のまわりのピン出力の差が下がる理由は、核データの版（B-10、Si、Ag・In・Cd など）
  が候補だが、核種を 1 つずつ替えて分けておらず、k の差の原因が未解決（#0131）で xlc の VII.0 の扱いも候補のため、確かめていない。

## 計算

両方のライブラリは、χ に遅発中性子をそれぞれの分布で数える（[ADR-0186](../../docs/adr/0186-include-delayed-neutrons-in-chi.md)）。
xlc は 1f650c35（ブランチ chore/vera-delayed-chi-records の上で、分岐点も 1f650c35）、2026-10-23。Slurm の排他のジョブで `dvc repro` を実行した:
VII.0 のライブラリは 466（`xlc-vera-endfb70-library`、36 分）、VII.0 の格子と 3A、3B は 471（`xlc-vera-endfb70-keno`、15 分）、VIII.0 の
ライブラリは 465（`xlc-vera-library`、46 分）、VIII.0 の格子（本番の `keno-*` のステージ）は 470（`xlc-vera-keno-lattices`、6 分）。
VIII.0 の 3A、3B の JSON は verification.md の「Problem 3 の炉心の計算」の実行（ジョブ 475）のもの。ステージの入力と出力の md5 は
`endfb70/dvc.lock`、`endfb70/p3/dvc.lock`、`dvc.lock`、`p3/dvc.lock`。表の数値は `python3 examples/verification_tables.py examples/vera/verification-endfb70.md` が JSON から描く
（[ADR-0176](../../docs/adr/0176-generate-verification-tables.md)）。
