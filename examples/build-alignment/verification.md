# ビルドの整列の設定の測定

ADR-0157（ループの先頭を 64 バイトに揃えてビルドする）を決めた測定。整列の設定ごとに、xs、lattice、core の出力が
バイト単位で同じかと、時間を比べる。

## 計算

- スクリプトと入力: このディレクトリの `build.sh`、`measure-xs.sh`、`measure-lattice-core.sh`、`measure-2A.sh`、
  `pincell-1B.toml`、`assembly-2A.toml`（examples/vera/p1/pincell-1B.toml と examples/vera/p2/assembly-2A.toml に、少数群定数の
  全桁の出力 `few-group` を足したもの）
- 実行したコミット 103c12df、分岐点 eb667f66（main）、2026-10-14。r995 の Slurm の排他のジョブ 302（xs）、305（lattice と
  core）、307（2A の繰り返し）
- 測った実行ファイル: 3 つのコミットのソースを `build.sh` で release でビルドしたもの。b873a967（main）、ebe7c100 と d39c5db3
  （ブランチ perf/0088-line-shape-table のコミット。タグ `record/adr-0157-fast-placement` と `record/adr-0157-slow-placement`）。
  d39c5db3 は ebe7c100 に、xs の依存の `num_cpus`（Cargo.toml と Cargo.lock）と `num_cpus::get_physical()` の呼び出しを足したもの
  （ほかの差はテストとコメント）で、設定なしでは `ReichMooreXs::cross_sections` の
  命令列は同じで開始アドレスが変わる（#0105。ほかの関数は確かめていない）
- 設定（各ソースの `.cargo/config.toml` の `target-cpu=znver5` に `-C llvm-args=…` で足す）: v0 なし、v1
  `-align-all-functions=6`、v2 v1 と `-align-all-nofallthru-blocks=6`、v3 `-align-loops=64`

## 出力の一致

- xs（M0、examples/m0/xs.toml）: 3 つのコミット × 4 つの設定 × 2 回の 24 本のライブラリは、すべてバイト単位で一致した
  （md5 `1943d0c43e0a5023686b829cc4029967`）
- lattice と core（b873a967、4 つの設定 × 2 回）: M0 のピンセルの少数群定数と標準出力、M0 の炉心の標準出力、VERA 1B の
  少数群定数と標準出力、2A の少数群定数、ピン出力、標準出力は、すべてバイト単位で一致した。307 の 2A の 12 回も一致した

| v1   | 56.15〜58.06 | 56.48〜56.89 | 56.76〜56.88 | 3.57 MB                                     |

設定なし（v0）では d39c5db3 だけが 40% 遅い。v1、v2、v3 では 3 つのコミットの差が消え、v3 はどのコミットも 54.1〜54.9 秒。
このジョブでは、同じ実行ファイルの 2 回の差が最大 5 秒（b873a967 の v2、ebe7c100 の v0）あり、ばらつきは #0112。

同じ 12 の実行ファイルは、ジョブ 277（2026-10-13）でも測った。277 は手元のスクリプトとビルドで実行したが、`build.sh` で
作り直した 12 の `xs` は 277 のものとバイト単位で同じだった（md5 の先頭 8 桁: b873a967 は v0 から順に 0661b146、689d7ae8、

遅く（55.45 と 54.29、55.56 と 53.91、55.46 と 53.99 秒）、平均で 1.4〜1.7 秒遅い。302 でも v1（56.15〜58.06 秒）は
v3（54.10〜54.91 秒）より遅い。277 を再現するには、103c12df の `build.sh` で実行ファイルを作り（上の md5 になる）、
`measure-xs.sh` を実行する。

1.3% 遅いが、同じジョブの中のばらつきと区別できるかは確かめていない。
